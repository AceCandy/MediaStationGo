# 黄果 AI 独立站源接入设计

状态：用户已于 2026-10-06 批准完整接入实施。调查日期：2026-10-05～2026-10-06。

用户已确认目标是 MediaStationGo 主项目，前期仅设计；2026-10-06 在确认独立表、三个排行榜及下载/权限方案后明确授权开始实施。本文参照现有红果短剧的发现、资料同步、管理员下载、文件入库和 Web/Emby 播放流程；未标为用户已确认的模型/行为选择均是建议，不能当作实施授权。

## 1. 目标与边界

新增一个独立的「黄果 AI」资料体系，内部标识统一为 `huangguoai`。用户可以浏览分类、搜索作品、查看详情；管理员可以同步资料、下载可取得的完整分集。下载产物经验证、外部整理或直接扫描入库后，在现有 Web 播放器和 Emby 客户端播放，并保留独立收藏、进度和统计。

只接入 `huangguoai.com` 对应的站源及其经验证的镜像。`huangguo.video` 和旧 `cloudfront` API 均不接入、不作为下载失败后的替代来源。同名作品也不跨站合并。用户已确认排除「黄果吃瓜」：不采集 `/chigua/` 文章目录及 `/archives/` 详情，不增加文章表或文章展示入口。

参照红果的产品流程，不复制红果特有的 App 签名、Android 离线兜底、官方合集、人物身份及接口协议。首版不增加远程在线播放、动态源站 STRM、自动付费、站源账号注册、交互式验证浏览器或全站源插件平台。源站资料不足时显示未知，不推断人物、季号、完结或首播日期。

完整交付范围包含目录、资料、下载、文件绑定、Web、Emby、用户状态和运维；可以分步实施，但仅完成目录不能称为完整接入。

## 3. 产品行为

### 3.1 发现与详情

在发现页新增「黄果 AI」，路由为 `/discover?system=huangguoai`，保留原有默认体系。进入时只加载当前页和必要筛选项，切站不预加载其他体系。

分类支持 AI 短剧、AI 漫剧、AI 换脸、AI 魔改；「全部」按作品 ID 去重。同一作品可属于多个分类，分类关系独立保存，不强行写成一个互斥字段。题材标签与源分类分开。

卡片显示标题、本地海报、源分类、评分（存在时）、更新说明及资料补齐状态。详情显示简介、标签、已确认分集、源站时间说明和本地文件。源站未提供演职员身份时不生成“演员表”。

普通用户只能浏览和操作自己的收藏/播放状态；管理员可以手动刷新资料、查看诊断和下载。暂无本地文件时不显示可立即播放的按钮。已有可见本地文件时跳转现有媒体播放路径。

页面中的分类、标签、搜索、排序、页码由 URL 管理；切用户/播放配置/查询时取消旧请求，旧响应不能覆盖新状态。所有列表有分页与明确的重试操作。

### 3.2 搜索与排序

首先提供已采集目录的本地标题/ID 搜索。完整版本再接通已确认的官网 `keyword` 搜索，并让用户明确区分「本地目录」与「源站搜索」，不能把本地命中说成全站结果。

源站搜索结果批量登记摘要，随后异步补齐详情；搜索 HTTP 不下载视频、不逐条同步详情。上游未提供可验证分页时，仅返回实际解析数量，不伪造全站总数。

本地排序标为本地排序。分类 `sort=hot` 只能证明该接口的热度顺序，不能自动冒充官网综合排行榜。官网热播榜、推荐榜、潜力榜的页面和当前排名条目已确认可读取；建议作为独立榜单入口纳入发现页，保留官网顺序并关联本源作品。用户已确认纳入首版；榜单范围、刷新语义及完整关联尚需验证，未确认的榜单排序能力隐藏。

### 3.3 下载空间与任务中心

复用现有下载空间，新增来源选择；先保留现有红果视图，再增加黄果 AI 视图，避免立即重写为跨来源混合队列。作品级汇总、分集状态、重试、取消、进度、执行历史保持一致的操作方式。

任务中心新增黄果 AI 体系：目录发现、详情刷新、图片维护、榜单刷新（确认后开放）。下载执行历史仍归下载空间；自动下载补充默认关闭，完成手动下载闭环后才开放独立定时配置。

### 3.4 可见性建议

沿用 `can_view_discover`；黄果 AI 的目录、搜索、详情和图片再结合现有成人内容开关与当前用户/播放配置的 `IncludeNSFW` 判定。文件播放继续按具体媒体库权限判断。新黄果 AI 库明确加入 `adult.library_ids`，不依赖库名猜测，也不引入文件级 NSFW 字段。

这是基于站源当前分类和项目既有可见性机制提出的方案；实施前与下载/播放范围一并确认，不增设另一套账号或权限平台。

来源客户端只处理请求、解析、规范化与取流；Repository 只负责持久化；Service 负责调度、互斥、补齐、下载和取消；Handler 负责认证、参数检查与安全 DTO。

建议新增 `internal/huangguoai` 客户端和独立 Service/Repository。复用现有任务跟踪、外部网络策略、FFprobe/FFmpeg 校验、文件发布工具、前端展示组件及播放处理。只有明确被两边共同使用的小函数才抽取；不把红果全部重构为来源插件框架。

## 5. 身份、模型与存储

### 5.1 身份规则

内部 UUID 与源站 ID 分开，源站数字 ID 全程按字符串处理。作品唯一性由 `huangguoai + source_id` 确定；镜像切换不改变身份。不能用标题、域名或播放签名 URL 去重。

分集用作品内部 ID + 已确认正整数集号保持身份；路径中的 ep-N、页面 ep 字段和分集链接须互相校验。同一个作品在别的源出现，不改变本源身份。不完整映射不能删掉已保存的分集或已下载文件。

统一文件标签：`[huangguoai-<sourceID>]`，单个源作品默认以 `S01E001` 坐标绑定。标题中的“第二季”不能生成跨作品合集；得到权威跨季关系后再单独设计扩展。

用户已确认沿用红果的身份分层：电影展示 ID 为 `hga-work-<workUUID>`，剧集展示 ID 为 `hga-group-<sourceID>`，默认季为 `hga-season-<workUUID>`，单集为 `hga-episode-<episodeUUID>`。黄果 AI 尚无已核实的官方合集关系，因此剧集以自身源站作品 ID 作为根身份，每部作品独立展示，不按标题合并。ProviderIds 使用 `HuangGuoAI` 和源站 ID，避免与红果 `hg-*` 冲突。默认 Season 是作品的虚拟层级，不另建季表或合集表；第 13 节给出完整身份映射。

数据库迁移为追加表/索引和必要枚举分派，无旧源数据转换。清理源资料不得级联删除已完成文件或用户状态。关闭功能保留历史资料和已有文件可读。

## 6. 采集与网络设计

### 6.1 目录同步

每个分类独立分页；解析 `status=1`、`data.items` 和 `data.pagination`，检查页码与请求一致、数量合理、ID 合法，区分业务失败、验证页与有效空页。页面摘要、分类关系和下一页检查点在一个事务提交。

首次同步按接口实际页数扫描，不固定只取首页或前 20 页。安全页数/响应大小/运行时限明确设定，触限报告“未完成”，不报告全站完成。统计新增数来自真实数据库新增，不来自返回条数。

当前确认的 `sort=hot` 会重排：不得复制红果“碰到上次首条 ID 就停止”的增量规则。首版对热度排序做可恢复周期扫描；新作优先依赖经过验证的稳定新上架排序。即使后续确认稳定排序，也保留重叠页和周期重扫处理旧作品补集/分类变化。一个分类成功不清除另一分类的失败。

热度重排下页码恢复只能提供恢复点，不能保证同一时间快照或历史全覆盖；轮次结束对重叠/重复/明显总数变化进行校验，必要时补扫。界面显示最近完成轮次和已收集作品数量，不承诺全站总量。

### 6.2 详情刷新

发现任务不逐部请求详情。后台从持久化摘要选择待补齐项，固定轮次截止时间，首次补齐和未完结作品刷新分开。成功事务保存作品、确认分集、快照及待维护图片地址；失败保持上一份成功资料。

完结证据可靠后减少自动刷新；未知状态和未完结作品继续维护。人工指定作品刷新可以绕过冷却。403/超时/解析变化与真实 404 分开记录，不能把验证页当“作品已下架”。单次分集减少不触发删除；清理需独立确认流程。

### 6.3 镜像与凭据

主站优先，失败时仅尝试已验证的本源镜像。官方发布页的链接只作为候选发现线索，先验证站源、页面结构和固定作品身份，再加入候选；不自动信任任意外链或复制广告域名。

目录、页面、媒体和密钥请求按各自用途发送 Referer/Accept；会话按来源域隔离。Cookie、账号 Token 不跟随跨域重定向发送，媒体签名参数不能在规范化时丢失。TLS 校验、代理设置、DNS 与每次重定向后的公网地址检查沿用项目已有策略，不为兼容性降低全局网络限制。

首版以匿名可访问资料/完整分集为基础。若下载必须使用用户已有账号，可在确认协议后增加管理员会话配置，沿用数据库加密及掩码 DTO；不要求管理员填写固定 AES 密钥。请求期取到的密钥只在内存中使用，过期重新解析。

目录并发初始建议 2，详情与媒体并发分别受限；所有 HTTP 有超时、响应大小及有限重试，遇 429/验证页退避。参数在实现时按现有调度规范确认，不无限重试或无限扫描。

## 7. 下载与入库

### 7.1 取流必须单独实现

红果现有下载支持的是其来源协议和完整 MP4，不能把黄果的 HLS 地址直接交给红果 App 下载器。

黄果下载按作品 + 集号重新读取规范分集页，再解析当前可用取流信息。`videoInitialData.videoSrc/epPlaySrcs` 是候选线索；`videoApi/videoKey/videoIv` 只说明存在协议字段，当前样本中后三个为空，不能据此假定所有视频都用固定 AES 算法。

识别完整 MP4、VOD HLS master/media playlist、标准 AES-128 HLS 及源站另有的包装格式。未知加密、DRM、SAMPLE-AES 或无法确认格式明确报不支持，不能发布不可播放文件。页面内 preview 字段和试看地址与完整视频分开；限制内容返回明确状态，不把试看片段标为整集完成。

HLS 须处理相对路径、媒体序列、每段 IV、密钥切换、EXT-X-MAP、字节范围、discontinuity、主列表选流和 ENDLIST。首版只接受有限 VOD；直播/缺失完整终止证据的清单拒绝完成发布。分片/清单有数量和体积上限。

从候选中选择当前实际可用的最高兼容画质，展示选择结果；不承诺全站 1080p。所有 HTTP、密钥及分片都经来源客户端与项目网络检查。优先在本地构建受限清单后交 FFmpeg 合并，避免 FFmpeg 自行请求任意上游地址、绕开凭据隔离和网络校验。

### 7.2 队列和完整性

队列采用与红果相同的持久化租约、取消和无覆盖发布契约，但使用黄果自己的表和来源 resolver。拟定状态：queued → downloading → waiting_verify → verifying → publishing → completed；失败/取消可人工重试。

传输与校验分池调度。完整性包括清单和分片取齐、解密/合并、FFprobe 可读性与时长核对、可配置完整解码、SHA256、本地同步及无覆盖发布。仅文件存在、FFmpeg 退出成功或目录可访问都不足以标为完成。

HLS 恢复先以分集为单位重新解析会话并重新传输；只有可以确认相同媒体清单/分片身份和校验一致时才复用已落地分片，不做未经验证的跨会话拼接。恢复检查点不保存 Cookie、Token、签名 URL 或密钥。受限临时文件取消/失败后按租约归属清理，不能删其他执行者的文件。

源站错误可以有限重试同一源的镜像；本地磁盘/工具/权限错误不能触发换站。完成文件不自动重下，不覆盖同名且缺乏本任务完成凭据的文件。

### 7.3 输出与扫描

使用与红果同样的 downloading/completed 两阶段目录；建议作品目录为 `日期或未知年份/作品名 [huangguoai-ID]/`，文件为 `作品名 [huangguoai-ID] S01E001.mp4`。日期语义明确使用已确认来源时间或未知，不能将采集时间伪装为源站发布时间。

下载发布只表示文件完成，不表示已经入媒体库、云端备份完成或 Emby 可见。外部 CD2/Symedia 可处理 completed；最终本地/挂载文件或既有 STRM 经扫描进入黄果 AI 库。

扫描解析来源标签及 S01/集号，精确绑定已补齐资料；资料缺失进入待绑定队列，不按相似标题猜配。误放普通库或标签冲突报告问题，不能悄悄改成红果/TMDb 文件。新增文件和删除文件同步维护作品 library_ids/latest_media_added_at，不改变用户历史身份。

## 8. API 草案

统一前缀 `/api/catalogs/huangguoai`，下表为拟新增契约。公共 DTO 不含上游播放地址、密钥、凭据或原始 HTML。

| API | 行为 |
| --- | --- |
| `GET /works` | 本地摘要/正式资料合并后过滤、准确计数及分页；keyword/category/tag/order 参数白名单 |
| `GET /search` | 显式 `scope=local|upstream`；上游搜索确认后开放，批量登记摘要并异步补齐 |
| `GET /works/:sourceID` | 已持久化详情，未补齐明确返回状态，不编造分集 |
| `GET /works/:sourceID/episodes` | 已确认分集及分页；可下载状态带确认时间，未知不是成功 |
| `GET /works/:sourceID/media` | 按当前媒体库权限过滤的已有本地/STRM 文件 |
| `GET /libraries/:libraryID` | 指定黄果 AI 库的逻辑作品分页 |
| `GET /artwork/:id` | 本地图片，权限校验，缺失可重试且不长期缓存占位失败 |
| `GET /me`、`GET/PUT /works/:sourceID/favorite` | 当前用户独立收藏，读取不受资料任务生命周期影响 |
| `PUT /media/:mediaID/played` | 先检查具体可见文件，再写本源状态；不能写其他用户进度 |
| `POST /works/:sourceID/refresh` | 管理员手动资料刷新，不隐式下载视频 |
| `GET/PUT /status`、`POST /cancel`、`GET /pending` | 管理员来源启用、状态、取消和待绑定诊断 |
| `/downloads/config`、`POST /downloads/works/:sourceID` | 管理员配置和幂等作品入队；支持完整已确认分集/选集的明确请求 |
| `/downloads/works`、`/downloads/works/:sourceID/episodes` | 作品汇总及分集分页，保留已有任务状态/位置 |
| `/downloads/:id/cancel`、`/downloads/:id/retry` | 校验状态和执行权，已完成文件不自动删除 |

任务执行和日志走现有 `/api/tasks`；统计的 system 枚举增加 `huangguoai`，`all` 合并前保留来源身份。错误用现有响应风格并增加可判别业务原因：source_unavailable、verification_required、session_required、preview_only、unsupported_media、local_storage_failed；映射 HTTP 时区分本地权限不足和上游拒绝。

拟定权限矩阵如下，前端入口与后端直连请求使用同一判定；不因为管理员拥有操作权而跳过其用户/播放配置的内容可见性。

| 接口范围 | 权限和内容范围 |
| --- | --- |
| works 列表、搜索、详情、分集 | 登录 + `can_view_discover` + 当前用户/配置允许该内容体系 |
| 来源发现海报 | 登录 + `can_view_discover` + 内容可见性；源图片 ID 不能绕过判断 |
| libraries、works/media、已有文件图片、播放 | 登录 + 具体文件/媒体库可见性；不额外要求发现权限，已关闭采集仍可观看已有文件 |
| 收藏 | 登录 + 可见作品范围；来源发现收藏与媒体库收藏的授权路径明确区分，不允许仅凭猜测 ID 写入 |
| played、进度、播放事件 | 登录 + 已验证的具体可见文件/分集；只读写当前用户 |
| status 修改、cancel、pending、手动刷新 | 管理员 + 内容可见性；status 公开能力摘要不返回凭据或任意路径 |
| 下载配置、入队、列表、取消、重试和下载历史 | 管理员 + 内容可见性；后端再次验证来源、任务和输出范围 |
| 统计 | 沿用现有管理员统计授权，来源范围明确，隐藏内容不得通过统计详情泄漏 |

若同一个本地 artwork_id 被发现页与已有媒体库复用，允许“发现权限 + 内容可见性”或“拥有可见绑定文件”两条明确授权路径；不能只检查登录。错误/无权限时不下载上游图片，测试使用合成图片。

## 9. 文件投影、播放与兼容

公共 MediaView 新增黄果来源投影分支；媒体库列表、逻辑作品、搜索、最新入库、收藏、继续观看、NextUp、版本、详情和人物相关入口均审计来源分派。没有可见文件的来源摘要只能进入发现，不能进入 Emby 的可播放列表。

首版不推断跨作品官方合集。建议单个来源作品按第 13 节规则投影 Movie，或独立 Series + 默认 Season；类型按来源分类映射，未确定分类或跨类型分类冲突时不猜测类型。Emby 的 Type、ParentId、SeriesId、SeasonId、ProviderIds、UserData 和 MediaSources 必须一致。

Web/Emby 共用本源用户状态语义；作品收藏按 source_id，进度按 source_id/集号，事件按用户/会话/作品/集号。文件改名、搬迁、重复版本、移除后重新入库不丢进度，跨源同名不串状态。没有可见文件不允许通过历史链接绕过媒体库权限。

现有部分通用 Emby 路径会 JOIN `metadata_items`（例如 `internal/service/emby_visibility.go:14`），不能把黄果文件送入该分支后期待其自动出现。新增的来源投影必须从独立作品/绑定表读取身份并应用文件权限；列表、详情、播放目标和进度回写都要在完全没有 metadata_items 替身行的数据库样例中通过。公共 MediaSource/流处理可以复用，旧元数据归属解析不能代替来源分派。

计数、过滤、资格判定先于分页；只批量补齐当前页资料，禁止一张卡片触发一个完整详情请求。统计和全局最新作品使用已有作品级查询契约，并纳入大样本 SQL 计划检查。

启用开关关闭时停止新采集/下载/绑定；既有文件、资料及历史继续可读。旧红果 API、文件标签、任务和 Emby ID 不改名。涉及播放器可见 Emby 行为的变更同步维护 `web/src/pages/embyApiCatalog.ts`。

## 12. 风险、退回方式和待确认项

主要外部风险是完整视频/密钥链路、会话限制、镜像变更和目录重排。当前已证明的是目录和页面可读，不能保证每集可下载、所有画质可取得或历史全站覆盖。

回退优先关闭黄果 AI 功能并取消/等待工作者，保留独立表、用户状态和完成文件。旧程序版本未必认识新库类型/Media 来源：有黄果入库文件后不能只回退二进制并宣称兼容，应先验证旧版本行为，必要时恢复数据库备份或保留兼容版本。新表不在停用时自动 DROP，不把黄果文件转换成普通 TMDb 或红果记录。

目标项目和第 14 节核心产品/模型选择已获批准。技术待确认项：上游搜索与榜单、稳定排序、完整分集/试看判断、当前媒体与密钥协议、真实下载验收环境。技术未知项必须在阶段 0 消除或明确标记对应能力受阻，不能用未经验证的协议填补。

实施进度与检查记录见 `.trellis/tasks/10-06-huangguoai-integration/implement.md`。

## 13. 数据模型和类型的具体建议

### 13.1 是否新增表

建议新增来源自己的表，保留第 5 节的隔离边界。完整范围需要 14 张基础表：9 张来源资料/同步/绑定表，3 张用户状态表，2 张下载表。第 15 张榜单表只在官网榜单协议确认并纳入范围后新增。

不按四个分类分别建作品表，也不按电影/剧集分别建作品表；一个 `huangguoai_works` 保存本源作品。各分类和两种展示类型共享同一套作品、分集及绑定身份。

| 选择 | 取舍 |
| --- | --- |
| 新增 `huangguoai_*` 表，复用公共文件/任务/设置 | 推荐。符合现有独立 catalog 模式；类型、分集和权限变化不会污染红果资料 |
| 给全部红果表添加 provider 并改造为共享表 | 会改变红果所有唯一键、外键、查询、状态和迁移；本次不推荐 |
| 塞入 `metadata_items` 作为另一种刮削资料 | 与本项目独立来源、绑定和播放契约不一致；不作为候选方案 |

14 张是完整交付模型的建议数量，不要求一次迁移全部功能。对应阶段再登记所需表，不为未接入的人物、跨季合集、弹幕、播放代理增建表。公共 `media`、MediaProbe、libraries/roots、settings、task_executions、权限与播放配置继续复用，不复制新来源版本。

### 13.2 各种 ID 分别是什么

以源站作品 `7833` 为例，用户已确认沿用红果方式的 ID 契约如下；其余模型行为仍按第 14 节的决策状态处理。

| 对象/使用位置 | ID 或键 | 规则 |
| --- | --- | --- |
| 源站作品 | `source_id="7833"` | 正整数字符串，建议 varchar(32)，与数字精度无关；同源唯一 |
| 跨体系稳定来源键 | `huangguoai:7833` | 用于跨来源比较/统计去重；不能与红果的 `hongguo:7833` 混淆 |
| 正式作品行 | `works.id=UUID v4` | 沿用 PermanentBase；首次建行生成，以 source_id 冲突更新时保留 UUID |
| 正式分集行 | `episodes.id=UUID v4` | `(work_id,number)` 唯一；页面或取流地址更换不生成新分集 |
| 公共媒体文件 | `media.id=UUID v4` | 是现有可播放文件 ID；不同版本各有文件 ID，不等于作品 ID |
| 扫描提示 | `media.lookup_catalog_id="7833"` | 搭配 `catalog_source="huangguoai"`，保存源站 ID，不保存作品 UUID |
| 来源作品 API 参数 | `/works/7833` | 参数是 source_id；DTO 明确区分内部 `id`、`source_id` 与 `display_id`，前端禁止互传；展示 ID 解析按对象前缀分派 |
| 文件命名标签 | `[huangguoai-7833]` | 域名、类型和标题改变时仍能定位同一源作品 |
| Web/Emby 电影作品 | `hga-work-<workUUID>` | Movie 根身份，对应红果电影的内部作品 UUID 方式 |
| Web/Emby 剧集作品 | `hga-group-7833` | Series 根身份，以自身 source_id 代替尚未核实的官方合集 ID；不代表存在跨作品合集 |
| Emby 默认季 | `hga-season-<workUUID>` | 仅 Series 时存在，SeasonNumber=1，ParentId/SeriesId 指向 `hga-group-7833` |
| Emby 剧集分集 | `hga-episode-<episodeUUID>` | ParentId/SeasonId 指向默认季，SeriesId 指向 `hga-group-7833` |
| Emby ProviderIds | `HuangGuoAI: "7833"` | 源站标识，不写成 TMDb/红果 ID；分集可在确认后附其源分集键 |
| 收藏 | `(user_id,source_id)` | 与分类、Movie/Series、文件版本无关，不按季或当前可见成员展开保存 |
| 进度 | `(user_id,source_id,episode_number)` | Movie 使用 episode_number=1；转为 Series 后仍是第一集进度 |
| 下载唯一键 | `(source_id,episode_number)` | 类型变化不重入已完成任务；作品固定输出位置单独保存 |

镜像切换、改标题、重新同步、类型变化、文件重命名均保持 source_id 和已存在 UUID。Movie/Series 类型变化会切换作品展示 ID，不能承诺展示根 ID 不变；收藏、进度、下载不依赖该展示 ID。完整删除数据库再重新导入会产生新的内部 UUID，因此电影、季、单集展示 ID 可能变化；Series 根 ID 由 source_id 确定，可在相同源身份下重建。导入/备份必须按来源键映射，用户状态不能因清理资料而级联删除。

### 13.3 按分类确定类型，更新状态独立保存

用户已确认以下固定展示映射，取代此前按完结证据和集数自动判定类型的建议：

| 来源分类 | 分类代码 | 展示类型 |
| --- | --- | --- |
| AI 换脸 | `ai-huanlian` | Movie |
| AI 魔改 | `ai-mogai` | Movie |
| AI 短剧 | `ai-duanju` | Series |
| AI 漫剧 | `ai-manju` | Series |

AI 短剧/AI 漫剧即使明确完结且只有一集，也按剧集展示，使用默认第一季和第一集。AI 换脸/AI 魔改即使未完结、总集数未知，或目录摘要报告多集，也按电影展示；这些字段不触发自动转为剧集。展示类型不意味着源站明确标注电影/剧集，也不证明内容完整或可下载。

来源分类、展示类型和更新状态分别存储。一个 `huangguoai_works` 保存本源作品，两种类型不拆表；已确认分类推导 kind，分类查询和类型查询仍为独立筛选项。不再增加按集数判定的 `kind_state`、`kind_basis`，也不显示此前的“类型待确认”集数判定标签。

| 字段 | 含义 |
| --- | --- |
| `kind` | movie/series，由上表来源分类映射，供 Web/Emby 分派 |
| `type_category` | 用于确定展示类型的已核实来源分类；不随当前访问的筛选分类改变 |
| `source_reported_finished` | nullable boolean，源站原始 is_finished；缺字段不是 false，不决定类型 |
| `completed` | nullable boolean，结合有效集数/详情得出的源作品完结状态；未知和未完结不同，不表示下载任务完成或文件完整 |
| `source_episode_count` | 来源已更新集数；未给出则未知，不等于当前可取流数量 |
| `source_total_episodes` | 来源标示最终集数；接口 total_episodes=0 规范为未知，白名单快照保留原值 |
| `confirmed_episode_count` | 按有效正集号清单得到的数量；同时保留集号空位，不按数量重排 |

类别缺失的搜索摘要先登记待补齐，不凭集数推断类型。分类多对多仍是建议：同一作品若同时属于两个电影分类或两个剧集分类，映射结果一致；若实际发现同时属于电影类和剧集类，优先级尚待确认，不按抓取顺序或当前页面选择类型。待确认处理建议：已有正式资料保持上一份类型并记录分类冲突；新作品在冲突解决前不发布正式播放投影。

红果实际 `Work.IsMovie()` 是 Completed 且 TotalEpisodes=1 且 EpisodeCount<=1（`internal/hongguo/client.go:544`）。黄果 AI 仅沿用已确认的 ID 分层和展示结构，类型采用本节的用户指定分类映射，不复制红果的集数判定规则。

### 13.4 类型变化、默认季和文件绑定

建议即使是 Movie，也保留已经确认的 episode 1 行。文件始终绑定到 `(work_id,episode_id)`；Movie 只允许第 1 集，Series 使用原有正集号。这样两种形态用同一套下载/进度键，避免转类型时迁移第一集进度。

Series 默认季号固定为 1，Season 是只读虚拟投影；剧集根为 `hga-group-<sourceID>`，不为“默认第一季”生成官方合集记录。红果当前 Series 需满足已核验的 related_album_id/season_index 才进入媒体列表，但黄果尚无相同关系证据，不能复制它的 ReadyWork 条件导致所有剧集被隐藏。黄果作品资格由有效正式资料及当前用户可见绑定文件决定。

类型不会因补集、总集数修正、完结标记变化或短响应自动切换。电影类保留内部 episode 1 坐标；若详情确实出现第 2 集及以上，保存已确认的分集资料并报告异常，不删集、不自动升级 Series，也不把多个分集当成同一电影的不同文件版本。电影多分集如何下载/播放仍需另行确定，待确认处理建议：第 1 集沿用电影绑定契约，额外分集暂不进入下载/播放投影。

若后续确认源站作品分类变更而需要人工修正 kind，保留内部作品/第一集 UUID、收藏、进度和已完成下载，不重命名完成目录或重复下载。旧的 Web 来源链接依 source_id 解析到当前展示；展示根在 `hga-group-<sourceID>` 与 `hga-work-<workUUID>` 间切换时，同步更新父子投影和查询缓存。已不适用的 Emby 根/Season/Episode ID 返回明确不存在；Emby 客户端需刷新列表。公共媒体播放 ID 保持稳定，旧展示 ID 不承担收藏或进度存储键。

电影用已有 Movie 展示；Series 用作品→默认 S01→Episode 展示。Movies 的集号 1 只是内部状态/绑定坐标，不强制在用户界面显示“第 1 季第 1 集”。输出文件可统一保留 S01E001 坐标，类型变更不影响扫描。

## 15. 实施结果与使用方式（2026-10-06）

已实现独立 15 表、来源协议与可恢复资料任务、三榜单、本地/官网搜索、独立下载队列、校验与无覆盖发布、扫描绑定、Web/Emby 层级以及收藏/进度/续播/统计。类型和 ID 按第 13 节执行，不接入吃瓜文章。运行时仅使用主站，没有通过固定作品验证的镜像。

### 开始使用

1. 部署新版本前备份数据库；应用启动执行追加迁移，不转换红果或普通资料。部署环境需已有 FFmpeg/FFprobe，下载目录须可写，并支持同一根目录下硬链接无覆盖发布。
2. 保证全局成人内容开关、当前用户和播放配置允许访问。进入「任务中心」选择黄果 AI，手动运行作品发现，再刷新资料和排行榜。发现任务周期扫描四分类，不保证任意时点的网站快照。图片维护是独立任务。
3. 「发现 → 黄果 AI」浏览四分类、热播/推荐/潜力榜；搜索明确区分本地资料和官网搜索。未补齐作品先刷新资料；无本地文件不显示直接播放或文件收藏。
4. 「下载空间 → 黄果 AI → 下载设置」设置来源独立的下载根目录和传输/校验并发。根目录不能与红果下载目录或媒体库互相包含。详情选择下载，查看作品和分集状态，失败可重试。
5. 完整传输后进入独立校验，只有校验通过才发布到 `<下载根>/completed`；`downloading` 是暂存目录。电影只下载真实第 1 集，剧集使用确认集号，不填补目录摘要中的虚构集数。
6. 完成文件可外部整理或直接扫描。新建「黄果 AI」媒体库指向完成目录或整理后的专用目录，保留 `[huangguoai-源ID] S01Exxx` 标签。一个库可以同时展示电影与剧集；不要建成普通电影/电视剧库。已入库文件的内置整理只允许留在黄果 AI 库，电影内部仍保留 S01E001。
7. 扫描完成后 Web 与 Emby 可播放本地文件。Emby 使用 `HuangGuoAI` ProviderIds；剧集固定默认第一季，不按同名合并。收藏按作品源 ID，观看进度按源 ID/集号保存。

下载空间的来源开关停用新采集、下载和绑定，既有资料、文件和用户记录保留。重新启用后刷新资料或扫描可补绑定。下载定时自动补集未增加，使用管理员手动入队，不把发现任务等同于下载任务。

### 实际接口对应

第 8 节是设计阶段的概念 API。实现沿用现有公共媒体库 `/api/libraries/:id/series` 及现有播放入口，不新增来源专用库/播放器。黄果独立前缀 `/api/catalogs/huangguoai` 提供 `works`、`search`（官网）、`works/:sourceID/episodes|media|state|favorite|refresh`、`me`、`artwork/:id`、`media/:mediaID/played`、`status`、`cancel` 和 `downloads/*`。本地搜索用 `works?keyword=`；收藏读取用 `state`；任务和日志仍在公共任务中心。没有独立 `pending` 接口，未绑定文件保持 `source_pending` 诊断，资料补齐后重绑。
