# 修正红果发现计数与按完结状态刷新

## Goal

红果发现任务只把此前不存在的作品计为新增；首次补齐新作品，按周期仅刷新未完结作品，并将新增、更新和无变动清晰区分。

## Background

- 当前分类页和榜单按 `source_id` upsert 摘要，但发现任务按每页/榜单返回条目数累加，跨分类、榜单和重复扫描都可能重复计数（`internal/service/hongguo.go:204-213, 398-402`；`internal/repository/hongguo_discovery.go:14-72`）。
- 待补齐项依据发现记录存在、正式作品不存在且不在失败冷却队列筛选（`internal/repository/hongguo_discovery.go:75-82`）。
- 资料刷新批次还查询已入库超过 24 小时的作品，每轮最多处理 100 项，目前未过滤完结状态（`internal/service/hongguo.go:457-486`；`internal/repository/hongguo_repository.go:322-332`）。
- 详情每次保存都更新 `refreshed_at`、快照时间并重建关联，不能依据数据库更新时间判断业务是否有变化（`internal/repository/hongguo_repository.go:47-112`）。
- 剧集已有 `completed` 布尔字段，由详情的可信“全 N 集”信息判断；为 false 时也可能只是缺乏完结证据（`internal/hongguo/client.go:465-480`；`internal/model/hongguo.go:32-55`）。展示/修改完结状态不属本任务。

## Requirements

- 分类扫描仍保存摘要和分页检查点；仅数据库中首次出现的红果 `source_id` 计为本轮新增，同一作品在不同分类或榜单出现不得重复计数。
- 榜单仍完整抓取并原子替换名次；已有作品的名次和摘要更新不计新增，榜单首次发现的作品计新增并进入既有详情补齐流程。
- 新发现作品首次补齐详情、失败冷却及到期重试、搜索注册后补齐和明确指定 ID 的手动刷新保持原状。
- 发现和资料刷新是两个独立逻辑：分类、榜单照常扫描以发现新 ID；资料刷新先补齐尚未入库的发现项，再按现有时间间隔和批次上限刷新已入库但未完结的作品，直至某次刷新确认完结；已完结作品不再进入自动详情刷新（包括历史失败队列的自动重试），管理员明确指定 ID 的手动刷新保留。
- 任务计数和文案应区分发现任务的真实新增数与资料刷新任务的新作品首次补齐、旧作品资料更新、刷新后无变化；仅业务详情字段变化计为更新，时间戳变化不算；不把已有榜单项当成新增项。

## Acceptance Criteria

- [x] 同一分类或榜单重复执行时，第二次发现任务新增数为 0，榜单名次仍按本次完整抓取结果替换。
- [x] 分类、榜单互有重叠时，每个首次出现的 `source_id` 只计一次；已有正式作品不会被误算为新作品。
- [x] 新摘要仍能被自动/定时/手动批次补齐；失败项仍按冷却时间重试。
- [x] 分类与榜单仍正常扫描、发现真正新 ID；已有完结作品不会被自动请求详情。新 ID 首次补齐，已有未完结作品满 24 小时后自动刷新，确认完结后下一轮不再自动刷新。
- [x] 新 item 首次补齐和已有 item 刷新成功时，任务日志与指标能区分新增、内容变化、无变动；时间戳变化本身不得误报内容更新。
- [x] 旧作品的数据、榜单、检查点、用户状态保持不变；相关回归测试覆盖计数、补齐及不再定期重抓。

## Out of Scope

- 不修改剧集 `completed` 判定及页面展示，不迁移或清理既有红果数据，不取消管理员明确指定 ID 的手动刷新。
