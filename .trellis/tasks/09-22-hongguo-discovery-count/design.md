# 技术设计

- 保持 `hongguo_discoveries.source_id` 唯一约束和现有摘要 upsert / 分类检查点 / 榜单事务边界。持久化方法返回真正首次进入目录且此前不在正式作品表中的 source IDs；用数据库实际插入结果辨别并发首次发现，避免以每页抓取长度充当新增。分类和榜单仍分别记录抓取/更新的事实，但只有新增 ID 影响“新增”指标。
- `runLocked` 的发现回调接收新增 IDs，累加真实新增数；重复扫描和榜单替换若无新增，不展示逐条“已记录”旧 ID。保留持久化成功后触发资料补齐唤醒，唤醒自身会判断队列是否为空。
- `refreshBatch` 保留待补齐分页、到期失败项与旧作品定期刷新，但已有作品候选和历史失败自动重试均排除 `completed=true`；指定 ID 的管理员手动刷新入口不变。继续保留 `refresh` 游标与默认 24 小时节奏。
- 详情刷新结果需根据已保存的业务内容与本次解析结果判定新作品首次补齐、已有作品内容变化、无变动；比较已有的白名单详情快照/业务字段，涵盖集数、状态、简介、评分、人物、图片等实际保存内容；不得把 `refreshed_at`、`updated_at` 或快照 `fetched_at` 变化算作内容更新。
- 明确区分“未曾发现”与“已有正式作品但尚无发现摘要”；后者不是新增，不能因为补写摘要就误计。更新契约文档中关于 24 小时旧作品刷新和发现进度的过时描述。
- 已有服务测试基础设施使用 PostgreSQL 测试库；覆盖重复扫描、跨分类/榜单、榜单替换、首次补齐、仅未完结旧作品参与定期刷新、完结作品退出自动队列及手动指定 ID 行为。

## 回滚

代码回滚可恢复旧候选筛选和日志口径；不进行数据迁移，不删除旧刷新游标或已有作品。
