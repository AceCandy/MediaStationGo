# 媒体详情展示型下拉框技术设计

## 1. 设计目标

在不改播放器和流接口的前提下，把详情页原有纵向轨道列表替换为四个原生下拉框，并将收藏按钮移到标题旁。基础详情始终以 URL 中的媒体为准；版本下拉只决定轨道区域展示哪个媒体版本。

## 2. 边界与状态归属

详情页保留两类互不混淆的状态：

- `media`：URL 中的基础媒体，继续负责标题、海报、简介、收藏、播放、投屏、刮削、探测和管理操作。
- `displayMedia`：下拉区域当前查看的版本，只负责视频、音频和字幕选项。

四个下拉框均不产生播放器参数。选择版本时不得替换 `media`，避免现有 `/play/:id`、外部播放器和投屏链接被展示状态隐式改变。

## 3. 后端契约

新增只读接口：

```text
GET /api/media/:id/versions
Response: MediaView[]
```

服务层按以下顺序处理：

1. 按 `id` 查询当前 `MediaView`；不存在或当前请求不可见时返回空结果，由处理器映射为 `404`。
2. 复用 `MediaViewRepository.FindByMetadataID`，并传入现有 NSFW、允许媒体库和隐藏媒体库过滤条件。

接口不分页。同一共享作品通常只有少量版本，且仓储查询使用已有 `metadata_id` 索引。它不复用 `ListMediaVisibleGrouped`，避免全库读取、分页截断和标题启发式误分组。

版本响应只承担版本选项。选中版本需要完整轨道时，前端继续调用现有 `GET /api/media/:id`；没有轨道时再调用现有 `POST /api/media/:id/probe/ensure`。

## 4. 前端数据流

```text
打开 /media/:id
  -> GET /media/:id
     -> 立即显示基础详情
     -> 缺少 tracks 时按现有流程异步 ensure probe
  -> GET /media/:id/versions
     -> 填充版本下拉，失败时退化为当前媒体

选择版本
  -> 只更新 selectedVersionID
  -> GET 该版本详情
  -> 缺少 tracks 时异步 ensure probe
  -> 更新 displayMedia
  -> 不修改 URL 基础 media，不传递任何播放参数
```

版本切换使用 React effect 的取消标记，只允许当前选择对应的请求更新 `displayMedia`、探测状态和错误状态。切回 URL 媒体时直接复用已经加载的 `media`，不重复请求。

## 5. 展示设计

- `MediaDetailTracks` 保留组件入口，内部整体替换为四个 `<select className="input-base">`。
- 版本选项优先显示分辨率、视频编码和容器，信息不足时回退到文件名或“当前版本”。
- 视频、音频和字幕选项复用现有 `display_title`、语言、编码、声道、分辨率等轨道字段生成简洁文本。
- 没有对应轨道时保留一个“暂无视频/音频/字幕轨道”的禁用选项。
- 探测和加载提示只位于选择器区域，并通过 `aria-live` 告知状态。
- 桌面使用四列网格，窄屏降为两列，再按现有容器宽度自然收缩；不新增 CSS 文件或第三方组件。
- 收藏按钮复用现有 Heart 图标、文案和颜色，移动到标题同行，并补充按钮类型和按下状态语义。

## 6. 兼容、回滚与风险

- API 为新增只读路由，不改变现有详情、播放和流响应。
- 未关联共享元数据的扫描中媒体本来不进入 `MediaView`；接口维持现有详情不可见行为，不为本功能扩大读模型范围。
- 版本接口失败时前端仍可显示当前媒体及其轨道，不阻塞详情页。
- 回滚时可独立移除版本路由/API 调用，并恢复原 `MediaDetailTracks` 渲染；现有探测改动不需要回滚。
- 本次不为播放器预埋无效的选择参数或状态接口；播放器重做时再定义正式播放选择契约。
