# 实施计划

## 1. 持久化任务执行记录

- 新增 `TaskExecution` 模型、迁移注册和 repository 查询/更新方法。
- 将 `TaskTrackerService` 改为数据库摘要权威源，并增加 trigger 与 interrupted 状态。
- 启动时恢复遗留 running 记录为 interrupted。
- 验证：模型迁移测试、TaskTracker 单元测试、PostgreSQL 分页与恢复测试。

## 2. 独立任务日志

- 实现按本地日期和任务 ID 生成路径的追加 writer。
- 将现有 Details 和关键阶段输出写入日志，摘要继续写表。
- 增加按任务 ID 顺序读取每日文件的详情接口与尾部大小限制。
- 验证：跨日、并发追加、缺失文件、截断、非法任务 ID 和跨目录访问测试。

## 3. 统一刮削 worker

- 抽取单个电影/电视剧媒体作品的候选选择、claim、处理和状态更新。
- 将显式媒体重刮削改为重置 scrape status 并唤醒 worker。
- 将 Catalog series 改为单次处理完整电视剧，保留内部 checkpoint。
- 让已完成 Catalog job 可在显式重触发时重置 checkpoint 并重新排队。
- 合并 worker 生命周期：每次先取媒体作品，无媒体待办才取 Catalog job。
- 验证：串行性、媒体优先、不抢占作品、重复触发去重、失败重试和重启恢复测试。

## 4. 补齐任务来源

- 给现有手动、定时、事件触发任务传入 trigger。
- 给计划扫描和回收站清理增加执行记录；确保计划整理不重复记录。
- 扫描入库触发刮削时只重置/唤醒，不直接启动刮削 goroutine。
- 验证：各入口分别产生一条且仅一条正确来源的执行记录。

## 5. 任务中心前端

- 更新 tasks API 类型与分页/日志详情请求。
- 将运行中和最近完成区域合并为一张统一列表，增加来源、状态与详情操作。
- 日志详情使用按需打开的对话框或侧面板，处理加载、空日志、截断和错误状态。
- 周期任务改为工具栏入口打开管理面板，保留立即运行能力。
- 验证：前端 lint/build，以及 390x844、768x1024、1440x900 和相关断点的无溢出检查。

## 6. 集成复核

- 运行相关 Go 单元测试与 PostgreSQL 集成测试；不默认执行全量编译，执行前按项目规则向用户说明并取得批准。
- 运行 Web lint/build、`git diff --check`。
- 独立复核数据流：触发 -> 业务状态 -> worker claim -> TaskExecution -> 每日日志 -> API -> UI。
- 检查未产生临时日志、测试数据库凭据或本地调试文件。

## 回滚点

- 步骤 1-2 可独立回滚到内存 TaskTracker，保留数据库表与日志不删除。
- 步骤 3 可恢复原 Catalog worker 与扫描后 goroutine，但不得同时启动两套 worker。
- 步骤 5 可临时读取兼容的旧响应字段回滚 UI。
