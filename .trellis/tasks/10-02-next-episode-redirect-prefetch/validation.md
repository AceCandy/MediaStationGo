# 验证记录

## 实现

成功的 GET/POST PlaybackInfo 请求启动后台预取。使用已验证的 MediaSourceId；未指定时复用现有可播放媒体选择。只查询同季集号加一的可见版本，每个版本先等待有效的完整轨道文档落库，再串行解析远程 STRM 或本地路径映射，复用现有直链验证、403 重试、同 UA 缓存及并发合并。空 UA 不预取；服务生命周期 context 取消时终止，每轮上限一分钟。

接口目录与直链缓存规范已同步。没有增加配置、依赖、数据库结构或修改轨道回填。

## 检查结果

- 三来源（普通、NFO、红果）预取测试实际执行（非目标媒体也预置有效文档，防止就绪门槛掩盖范围泄漏）：非阻塞、同 UA 播放复用、远程 STRM、本地路径映射、隐藏库/后续集/跨季范围、空 UA/已取消 context。
- 生命周期取消与未配置前缀测试通过：取消释放 HTTP 与 in-flight，不缓存失败；未配置前缀不请求上游。
- 先媒体信息后取链：无效文档不取链，已就绪版本不被未就绪版本阻塞；HTTP GET/POST 在下一集文档缺失时不取链，文档落库后才取链。实际阻塞轨道回填 runner 的测试确认回填完成并落库前不会发出取链请求，没有新增重复探测。
- HTTP GET/POST 集成测试通过：响应不等上游、HTTP 请求结束不取消后台、无效媒体源/非法 JSON/缺失媒体不预取、视频流复用相同 UA 的预取。
- `go test -race` 定向 service 回归通过，覆盖下一集查询/轨道回填、直链验证/403 恢复与耗尽、并发合并、取消、500 本地回退、路径映射及外部跳转凭据边界。
- `go test -race` 定向 handler 回归通过，覆盖 PlaybackInfo/selection、视频流媒体 ID、大小写与前缀路由、请求取消 499。新 HTTP 测试夹具最初缺少 Media 服务，补齐后通过，并拆为 GET/POST 独立用例。追加媒体信息就绪门槛时，测试夹具也补齐了 MediaProbe 注入（实际服务 builder 已有注入）。
- 所有上述数据库回归使用专用测试数据库的随机隔离 schema，明确检查 `skipped=0`。补跑上一轮曾因未设置测试 DSN 而跳过的服务/handler 数据库回归。
- `web: npm run lint`、`npm run build`、`scripts/check-nextup.mjs` 与 `git diff --check` 通过。浏览器检查包括接口目录交互、三个屏幕尺寸、主题可访问性及非管理员访问。
- 临时 Web 预览服务已关闭，浏览器会话由脚本关闭。

## 独立复核

实现后重新核对了实际 ServeMedia 源选择、PlaybackInfo 成功/失败分支、请求 UA、Container.Context/Close 取消链、NextEpisodeMediaIDs 和 FindByIDs 的权限过滤。追加复核了 `versions[:0]` 原地压缩待就绪版本（只写当前或已访问下标）、有效文档校验、服务实际注入 MediaProbe、取消检查与每秒读取的总超时。没有发现需要扩大范围的缺陷。独立审查代理服务返回 503，复核由主线程完成。

## 未验证与限制

没有部署或重启业务服务，没有 YAMBy 真机连播验收或整仓全量测试。缓存仍沿用一小时 TTL，PlaybackInfo 与视频流 UA 不同会分别取链；源站可能在缓存 TTL 内使已验证直链提前失效。每轮只预取下一集，不跨季、不跳过缺集。轨道文档每秒检查一次；等待与解析共用一分钟上限，超时未就绪的版本跳过本轮预取。用户已批准提交归档；未部署或推送。
