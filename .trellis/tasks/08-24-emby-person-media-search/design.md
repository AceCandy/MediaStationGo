# Emby 人物与媒体并列搜索：技术设计

## 边界

- 只修改 Emby `/Items` 的非空 `SearchTerm` 路径。
- `Items` 继续拥有请求分流；`searchTopLevelItems` 负责搜索类型解析、候选召回、合并排序、分页与 payload 组装。
- 人物仍由 `PersonRepository` 管理，媒体仍由 `MediaViewRepository` 管理；不新增索引、表或依赖。

## 数据流

1. 保留现有请求归一化，包括单字符加 `%` 的播放器兼容处理。
2. 从 `IncludeItemTypes` 独立解析人物开关与媒体 kinds：
   - `Person` 启用 PostgreSQL 人物召回；
   - `Movie` / `Series` 启用现有媒体召回；
   - 未支持类型忽略；没有任何已支持搜索类型时返回空结果；
   - 未指定类型时保持现有默认，仅搜索 Movie 与 Series，不隐式加入 Person。
3. 媒体候选继续经 `SearchMetadataIDs` 使用 OpenSearch 优先、PostgreSQL 回退；为合并排序以 `offset=0, limit=100` 取得候选。
4. 人物候选复用 `PersonRepository.List(search, nil, 0, 100)`，不查询 `MetadataCredit`，因此不会展开参演作品。
5. 把媒体与人物投影为最小统一候选：稳定的类型键、对象 ID、标题/姓名、原名、简介、类型、年份。人物年份和自然数字值为 `0`。
6. 先按“类型键 + ID”去重，再复用现有匹配分组与比较规则对合并候选重新排序；该组合键也避免不同表相同 ID 冲突。
7. 排序后截断到 100 条，再按原始 `StartIndex` / `Limit` 内存分页。
8. 媒体按现有 Movie/Series payload 路径组装；人物复用 `personPayload`；最终按分页后的统一候选顺序输出。

## 排序契约

- Tier 0：标题/姓名或原名完全匹配；年份倒序，最后按稳定类型键和 ID 排序。
- Tier 1：标题/姓名或原名完整包含全部搜索组。
- Tier 2：其它字段匹配。
- Tier 1/2 沿用现有字段覆盖率、首次位置、匹配跨度、自然数字倒序、年份倒序及稳定 ID 顺序。
- 人物没有年份、类型编号和 genres，缺失值按零值参与比较。

## 兼容性

- 纯 `Person` 路径继续使用现有 `Persons`，避免改变其过滤、分页和 payload。
- 无 `SearchTerm`、带 `IDs`、父级浏览、收藏/续播过滤等非合并搜索路径保持现有优先级和行为。
- 混合搜索仍遵守现有媒体可见库、NSFW、父级库、收藏和续播约束；人物没有对应媒体可见性关系，不套用媒体库过滤。
- 玩家可见行为变更后同步 `web/src/pages/embyApiCatalog.ts`。

## 取舍

- 不为人物接入 OpenSearch；现有 PostgreSQL 子串召回已满足当前范围。
- 不建立新的通用搜索框架；仅把现有排序输入扩展为能标识人物和媒体的最小投影。
- 每个来源最多召回 100 条，合并后再截断 100 条。该上限与现有搜索契约一致，避免无界内存排序。

## 风险与回滚

- 风险：同名人物和媒体需要稳定且可解释的最终顺序；用类型键加 ID 保证确定性。
- 风险：混合结果的 `TotalRecordCount` 是最多 100 条的合并候选数，不是数据库全部命中数；与现有候选上限一致。
- 回滚：修改不含数据库迁移；回退服务搜索分流、统一候选排序适配和目录说明即可。
