# 代理池不可用代理检测与清理

## Goal

让管理员在代理池管理页主动检测无法建立可用代理连接的节点，并安全地从代理池中批量删除确定不可用的节点，避免豆瓣任务遍历大量死代理。

## Background

- 当前代理池以加密 URL 和顺序持久化，公开接口只返回脱敏地址、ID 和是否含认证信息。
- 当前管理页只有完整列表加载与保存能力，没有健康检测、状态字段或清理入口。
- 当前运行环境已有约 3,000 个代理；逐个同步检测会把阻塞从业务请求转移到检测请求，检测必须有并发和超时边界。
- 单独出现豆瓣 HTTP 400、限流、Cookie 或上游服务异常不足以证明代理失效；只有直连基准健康且代理返回当前路由已明确判定失败的精确结果时，才可进入不可用分类。

## Requirements

- 代理池管理页提供独立的“检测不可用代理”入口，不要求先保存文本框里尚未提交的编辑内容。
- 检测使用数据库中已保存的完整加密代理配置，响应和日志不得暴露认证信息、完整代理 URL 或密文。
- 仅把确定属于代理连接能力的问题判定为不可用，包括连接失败、连接超时、代理认证失败，以及在健康直连基准下出现的精确 HTTP 400、`unexpected EOF` 或无效成功响应。
- 豆瓣限流、Cookie 异常、无法归因的业务响应错误或检测目标自身异常不得导致整池误删。
- 检测必须限制并发数和单代理超时，并向管理员展示总数、可用数、确定不可用数和无法安全判定数。
- 批量删除必须复用现有代理池原子替换语义；删除成功后保持剩余代理的原顺序，并刷新运行时代理快照和页面文本框。
- 删除属于不可逆管理操作，必须采用项目现有危险操作确认交互。
- 检测或删除失败时保留原代理池，不返回或记录敏感代理信息。

## Acceptance Criteria

- [ ] 管理员可在代理池面板发起已保存代理的检测，并在检测期间看到忙碌状态且不能重复提交。
- [ ] 3,000 个代理的检测以受控并发运行；每个代理都有明确超时，单个慢代理不会无限拖住检测。
- [ ] 检测结果显示检测总数、可用数、确定不可用数和无法安全判定数，然后弹出一次性清理确认。
- [ ] 上游整体异常时不会把全部代理判定为不可用或执行批量删除。
- [ ] 管理员确认后，确定不可用代理被物理删除；取消确认不修改数据库或运行时代理池。
- [ ] 删除后剩余代理顺序、含认证代理的加密凭据以及脱敏 API 契约保持不变。
- [ ] 后端聚焦测试覆盖并发检测分类、超时、全局上游异常保护、原子删除和敏感信息不泄漏。
- [ ] 前端测试或等价检查覆盖按钮忙碌态、结果确认、取消不删除和成功后刷新。

## Out of Scope

- 定时或后台周期健康检查。
- 保存长期健康分数、失败次数、延迟历史或冷却状态。
- 检测尚未保存到数据库的文本框内容。
- 将代理健康检查扩展到豆瓣以外的 Provider。

## Notes

- 现有确认组件 `confirmAction` 可复用，不新增弹窗框架。
- 现有 `ProxyPoolService.Replace` 已具备事务性完整替换和运行时快照刷新能力。
- 用户已确认不做逐项结果列表：检测完成后展示汇总，确认后一次清理全部确定不可用代理。
