# 统一观看历史与播放统计

## Goal

统一 Web 与 Emby/Jellyfin 播放器的观看历史、继续观看和完成状态，防止越权、进度丢失与并发写入异常；同时持久化独立播放事件，并在 Web“观看空间”提供管理员播放统计页面。

## Background

- Web 与播放器兼容 API 当前共用 `playback_histories`，按账户和作品元数据保存最新进度。
- 当前完成判定、最终进度提交和请求校验不一致，且播放器用户参数未与鉴权账户统一校验。
- 现有历史状态只能表达“最后播放到哪里”，不能可靠表达播放次数。
- Play Profile 属于同一账户的内容过滤器；历史无需按 Profile 隔离。需要隔离时使用独立账户。
- Emby PlaybackInfo 已返回 `PlaySessionId`，标准进度请求模型也包含该字段，但当前进度 handler 未读取；Web 播放器当前没有会话 ID。
- `SessionTrackerService` 只在内存中维护实时设备状态，进程重启会清空，不能承担持久播放统计去重。

## Requirements

- R1. 普通账户只能读取和操作自己的观看历史、收藏及播放器 UserData；请求显式指定其他账户时返回 403。管理员只有在请求显式指定目标账户时才可跨账户读取和操作这些数据；未指定目标账户的普通自助接口始终操作管理员自己的数据。本次只提供跨账户 API 能力，不新增管理员代操作 UI。
- R2. 观看历史是所有账户默认具备的基础能力，不由 `can_view_history` 控制。为兼容旧客户端，后端暂时保留该字段并始终返回、保存为 `true`；前端权限管理界面移除该开关，本次不删除数据库列。
- R3. 所有入口共用同一完成判定：总时长小于 10 分钟时，播放位置达到 `duration - 30 秒`；总时长大于或等于 10 分钟时，播放位置达到 `duration * 90%`。
- R4. Web 播放器的周期上报继续节流，但暂停、播放结束和页面离开时必须提交最终进度；仍在页面生命周期内的失败提交最少重试一次，离页提交使用浏览器原生 keepalive 能力。
- R5. `/playback/:id/progress` 删除无效的 `completed` 请求字段，由服务端统一计算完成状态；旧客户端继续发送该字段时兼容忽略，不能覆盖服务端结果。
- R6. 所有进度入口校验位置与时长边界：拒绝负位置、非正时长和 `position > duration`；响应百分比限制在 0% 到 100%。
- R7. 历史写入使用 PostgreSQL `INSERT ... ON CONFLICT DO UPDATE`，利用现有账户与作品元数据唯一约束，避免首次并发写入冲突。
- R8. 原生进度写入必须验证当前账户对媒体的可见性；不可见媒体不得创建或更新历史。
- R9. 播放位置不足 20 秒时忽略自动观看进度和播放统计。手动标记已看绕过 20 秒门槛并直接写入完成状态；手动标记未看删除该账户与作品的观看历史，不保留恢复位置。两种手动操作均不产生播放统计事件，已存在的真实播放事件不受影响。
- R10. Web 首页与播放器使用同一套继续观看服务规则：未完成、位置至少 20 秒、按最后观看时间倒序，并应用账户媒体可见性。
- R11. Web 首页和观看历史增加按账户隔离的请求去重与短时缓存；播放上报、历史删除和账户切换必须使相关缓存失效。
- R12. 播放器 Resume 批量加载历史对应的媒体、版本与 UserData，避免逐条查询。
- R13. 新增独立播放事件记录，以 `metadata_id` 为内容维度；一个独立播放会话首次达到 20 秒时记录一次，同一会话内暂停、恢复、拖动和重复上报不重复计数，关闭后重新打开媒体产生新会话并可再次计数。Web 使用浏览器原生 UUID 生成会话 ID，Emby 使用 `PlaySessionId`。
- R14. 统计支持按日、周、月聚合播放次数，并按时间范围、电影/电视剧等媒体类型、单个或多个媒体库、指定账户筛选。播放统计仅管理员可查询。
- R15. Web 新增管理员专属播放统计页 `/playback-stats`，页面放在“观看空间”导航中、“我的”和“播放器日志”之间；普通用户既看不到入口，也不能直接访问页面。页面使用现有控件与 CSS 展示筛选条件、汇总和时间序列，不新增图表依赖。
- R16. 观看历史仍按账户隔离，不增加 `play_profile_id` 维度。
- R17. Web 首页“最近添加”按逻辑作品查询和分页：电影使用 movie metadata，剧集分集归到 series metadata；按作品关联媒体的最新入库时间倒序后只返回当前页，不得先读取大批媒体文件再在内存归组。
- R18. Web 首页不请求未展示的媒体库数据；最近添加和继续观看保持独立并行加载，不新增首页聚合接口。
- R19. 收藏列表以 `favorites.metadata_id` 为作品身份，批量读取作品展示信息，不按收藏逐条解析 `media_id` 或查询播放版本。
- R20. 作品卡片和作品详情使用 `metadata_id`。详情展示可见播放版本，并优先选中该账户上次实际播放且仍可见的 `media_id`；只有点击播放时才把明确版本 `media_id` 传给播放器。
- R21. Emby/Jellyfin 的 Latest、Items、Resume、单项详情和 PlaybackInfo 遵守相同边界：作品列表先按 metadata 分组分页，批量加载页内关系；列表不得过早绑定具体播放版本或产生随结果数增长的逐条查询。

## Acceptance Criteria

- [ ] 普通账户无法通过路径、查询参数或请求体读取、修改其他账户的历史、收藏和播放器 UserData；管理员仅在显式指定目标账户时跨账户读写。
- [ ] 历史、收藏、UserData 的每个显式 `userId` 路由都覆盖“本人允许、普通账户跨账户 403、管理员显式目标允许”的权限矩阵。
- [ ] `can_view_history=false` 的旧数据不会阻止历史能力，兼容 API 始终投影为 `true`，前端不再显示该权限开关。
- [ ] Web 与播放器兼容 API 对同一进度产生相同的 `completed` 结果，并覆盖 10 分钟边界测试。
- [ ] 旧客户端发送 `completed` 时该值被忽略，结果仍由服务端规则计算。
- [ ] 小于 20 秒的自动播放不会写入历史、进入继续观看或产生播放统计事件；恰好 20,000ms 时开始写历史，并在会话 ID 有效时产生事件。
- [ ] 手动标记已看或未看可以直接改变完成状态，且不会新增播放统计事件。
- [ ] 手动标记未看后该作品没有历史和可恢复位置，原有真实播放统计事件仍保留。
- [ ] Web 在周期上报、暂停、结束和离页场景下保存最新有效进度，重复事件不会产生无界请求。
- [ ] 离页时实际发出携带现有认证信息的小体积 keepalive 请求；离页失败不启动后台无限重试。
- [ ] 进度接口拒绝非法位置/时长，响应中的播放百分比始终位于 0% 到 100%。
- [ ] 并发首次上报同一账户、同一作品时只保留一条有效历史且不因唯一约束返回错误。
- [ ] 不可见媒体无法通过原生进度 API 写入历史。
- [ ] 首页与播放器 Resume 对同一账户返回一致的继续观看集合和顺序。
- [ ] 页面短时间往返不会重复请求相同账户的历史；播放变更、历史删除或账户切换后不会复用过期缓存。
- [ ] Resume 使用批量媒体解析，并有查询行为或结果测试覆盖。
- [ ] 同一播放会话无论上报多少次进度都只产生一条播放事件；新播放会话达到 20 秒后产生新的事件。
- [ ] 有效会话的历史与事件写入保持原子；模拟事件写入失败时不留下只有历史、没有事件的部分状态。
- [ ] 没有会话 ID 的兼容客户端仍可保存达到门槛的历史，但不产生无法去重的播放事件；不可见媒体两者都不写。
- [ ] 管理员统计 API 可按粒度、时间范围、媒体类型、一个或多个媒体库和指定账户筛选；普通账户访问返回 403。
- [ ] 统计 API 拒绝非法粒度、日期和 `from > to`，日/周/月边界按服务端本地时区计算，媒体库参数的重复值不会重复计数。
- [ ] 管理员在“观看空间”看到 `/playback-stats`，位置在“我的”和“播放器日志”之间；普通账户无入口且直接访问被拒绝。
- [ ] 读取既有异常历史时，返回的播放百分比仍被限制在 0% 到 100%；Resume 同样排除不可见媒体。
- [ ] 历史和统计均按账户而非 Play Profile 隔离。
- [ ] 最近添加在数据库中按逻辑作品归组、按关联媒体最新入库时间排序并在归组后限制数量；不得读取 50,000 条媒体后内存归组。
- [ ] 首页不再请求媒体库列表，最近添加和继续观看互不等待。
- [ ] 收藏列表只依赖 `metadata_id` 批量组装作品卡片，结果规模增加时查询次数不线性增长。
- [ ] 作品卡片进入 metadata 详情；详情批量返回可见版本，上次播放版本仍可见时默认选中，否则使用现有版本优选规则；播放路由只接收最终选定的 media ID。
- [ ] Emby/Jellyfin 的作品列表、Latest 和 Resume 均先按 metadata 分页并批量加载当前页数据，单项详情和 PlaybackInfo 只在播放边界解析版本。

## Out of Scope

- 按 Play Profile 隔离观看历史。
- 普通账户查看个人播放统计。
- 管理员在 Web 中代其他账户编辑历史、收藏或 UserData。
- 为首页性能引入新的前端数据请求依赖，或为统计页引入图表依赖。
- 新增首页聚合接口、缓存框架或为列表预先计算默认播放版本。
- 用播放事件替代作品级最新进度；两类数据分别承担状态与统计职责。
- 删除数据库中的 `can_view_history` 列。
