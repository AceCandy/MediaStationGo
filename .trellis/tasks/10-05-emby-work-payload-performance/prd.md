# 收藏与全局 Latest 查询性能

## 目标与背景
- 收藏请求总耗时 4072 ms，其中红果页内节点补全约 4029.7 ms；13 个合集、85 个成员、9518 个文件重复读取合集资料。
- 用户明确要求同时优化全局 Latest。真实数据中完整全局 Latest 原路径曾在 60 秒内未完成；候选生成还存在全量三层聚合和选择率低估。

## 要求与验收
- 共享全局 payload 入口复用库内作品投影，保留原完整公共 payload、Fields、身份、封面、合集全局代表与时间、权限和有效状态。
- 默认电影/分集 Latest 的候选避免生成无用作品/季节点及第二次聚合；多版本保持可见文件 MAX 日期，状态仍按候选批检查。
- 普通候选的父/祖父读取保持原 origin 分组、重复行和 NULL 语义。
- 保持返回类型、排序、并列截断、分页、总数及无 NFO 时的旧混合 Latest 行为。
- PostgreSQL 原投影对照、完整公共 payload 对照和实际计划测试通过；真实数据库仅只读验证。

## 范围边界
不修改公开 API、默认 Movie/Episode 返回类型、数据、权限、状态契约、数据库结构、缓存或前端；不重启用户运行的服务。
