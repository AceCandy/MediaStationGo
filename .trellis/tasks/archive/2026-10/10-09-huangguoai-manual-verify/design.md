# Design

Add pending_review and warning/confirmed_by/confirmed_at to HuangGuo download rows. Compute the candidate digest after failed validation; status, rather than digest alone, controls admission. Independent claim excludes pending_review. Explicit accept locks the row, validates the retained size/digest, records actor/time and queues its existing digest for fenced publishing. Preview uses os.Root, a validated private stage, a regular-file check and ServeContent; routes retain admin and adult/profile checks. Retry of a review candidate clears the checkpoint and deletes only its private stage under the row lock before clearing the checkpoint; cleanup failures retain the path for retry. If the subsequent database commit fails, the stale review row may reference a missing candidate and must be retried/cancelled; it cannot publish; cancellation does the same. Work cancellation also routes review candidates through the single-row cleanup path. UI uses native inline video with an explicit acceptance warning dialog. No automatic scanner ingestion: acceptance publishes to the existing output directory for subsequent organization.

Additive model migration via existing AutoMigrate; old rows retain empty audit fields. Rollback requires resolving pending_review rows before using an older binary; do not drop retained files or columns automatically.
