# 播放器日志流水号与慢请求诊断

## 目标
- 说明 SenPlayer 01:07:19/01:07:29 两次请求耗时来源。
- 日志拥有数据库分配的跨月稳定递增流水号，列表、手机卡片、详情显示，详情可复制。
- 历史分区日志补号；重复迁移保持编号；原 UUID 主键、排序、分页与筛选保持。

## 边界与方案
- 修改日志模型、专用分区迁移、服务 DTO、Web 类型与页面；补充迁移和读写验证及规范。
- 原生 PostgreSQL sequence + ADD COLUMN 的 nextval 默认值原子补号，不使用 MAX+1 或分页行号。序列允许空号，不保证请求时间排序；历史补号顺序不代表请求时间。
- 管理 API serial_no 为十进制字符串，前端不转换成 Number。
- 本次不新增按号筛选，不部署、不重启、不在生产执行迁移。

## 验收
- 新库和历史月分区获得正整数、不重复编号；重复迁移后编号不变；后续新请求继续取号。
- GORM 写入和管理 API 读取贯通，超出 JS 安全整数仍无损。
- Web lint/build、响应式显示和复制成功/失败验证通过。
- 独立复核及 diff 检查，无凭据或调试产物入仓。
