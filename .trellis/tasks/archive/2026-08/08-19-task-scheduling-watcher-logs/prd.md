# 任务中心调度设置与文件监听日志

## Goal

让管理员在任务中心同时看清后台任务做了什么、是否启用定时执行、按什么周期执行，并能查看文件变更监听产生的增量入库日志。

## Background

- 任务中心的“媒体库扫描”绑定 Scheduler job `library_scan`，固定每 24 小时评估一次；定时执行受 `scan.periodic_enabled` 控制，默认关闭，手动执行不受开关影响。
- “媒体整理”绑定 Scheduler job `organize_source`；定时执行受 `organize.auto` 控制，周期来自 `organize.interval_seconds`，默认 300 秒且最小 60 秒，手动执行不受开关影响。
- 当前任务中心只展示 Scheduler 的周期和下次执行时间，不展示启用状态，也不能修改开关或周期。
- `organize.interval_seconds` 只在 Scheduler 启动时读取；运行中修改设置不会刷新已注册 job 的实际周期。
- 人物补齐、人物翻译和账号清理使用独立 ticker/worker，不属于当前 Scheduler job 注册表。
- `WatcherService` 常驻监听本地媒体库文件事件；5 秒去抖后逐路径增量入库或删除，但目前只写应用日志，没有 `TaskExecution` 和任务中心日志。
- 既有任务中心契约保留稳定任务定义、逐次执行摘要和按任务定义分日日志；历史数据不迁移。

## Requirements

- 任务中心对纳入配置范围的定时任务展示真实启用状态和实际周期，并允许管理员直接修改。
- 纳入配置范围的周期工作包括媒体库扫描、媒体整理、人物信息补齐、人物翻译和账号清理巡检。
- 设置保存必须影响运行中的后续调度，不要求重启服务；手动执行继续绕过定时开关。
- 人物补齐和人物翻译的事件唤醒不受定时开关影响；账号清理沿用现有安全开关，关闭时仍禁止手动清理。
- 后端拥有调度配置键、默认值、范围校验和运行时更新语义，前端不重复实现业务默认值。
- 新增稳定任务定义“媒体库变更监听”，触发方式为文件事件，不提供手动执行。
- Watcher 只在存在需要入库、更新、删除或报告失败的稳定路径时创建执行记录；纯目录注册和无关文件不得制造任务历史。
- 同一轮 5 秒去抖得到的稳定路径合并为一次短执行，日志逐项记录新增、更新、删除、跳过和失败，并保存汇总指标。
- Watcher 执行与“媒体库扫描”使用不同的任务定义和可区分的执行过滤条件，历史与日志不得串行。
- 保持现有媒体扫描、媒体整理、刮削唤醒和文件监听业务行为不变。

## Acceptance Criteria

- [x] 任务中心能展示并修改媒体库扫描的启用状态和周期；保存后无需重启即可改变下一次调度时间。
- [x] 任务中心能展示并修改媒体整理的启用状态和周期；保存后无需重启即可改变下一次调度时间。
- [x] 任务中心能展示并修改人物信息补齐、人物翻译和账号清理巡检的定时启用状态与周期。
- [x] 关闭任一定时任务后不再自动执行；现有手动入口仍可使用，但账号清理继续受原有安全开关限制。
- [x] 关闭人物补齐或人物翻译的定时触发后，既有事件唤醒仍能执行；账号清理继续遵守原有安全开关。
- [x] 非法、过小或不支持的周期由后端拒绝并返回明确错误，前端展示该错误。
- [x] 任务中心固定展示“媒体库变更监听”，没有事件历史时显示空日志状态，且没有手动执行按钮。
- [x] 一批文件变化只生成一次 Watcher 执行；日志可区分新增、更新、删除、跳过和失败路径。
- [x] Watcher 批次即使部分路径失败也继续处理其余路径，最终状态和指标准确反映部分失败。
- [x] 媒体库扫描历史不包含 Watcher 执行，Watcher 历史不包含整库扫描执行。
- [x] 后端相关定向测试、前端 lint/build、`git diff --check` 和独立复核通过。

## Out of Scope

- 不新增 Cron 表达式、时区选择或任意任务编排。
- 不改变手动任务的业务范围、扫描算法或文件监听机制。
- 不迁移或重写已有任务执行记录和日志文件。
- 不把常驻 Watcher 生命周期本身保存为永不结束的执行；只记录可审计的事件处理批次。
