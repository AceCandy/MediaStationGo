# 统一任务中心日志样式：技术设计

## 1. 边界

本任务只改变任务日志的文本格式与页面渲染，不改变任务执行状态、调度、持久化摘要、日志文件路径或读取 API。

数据流保持：

`任务生产者 -> TaskTrackerService -> 按日追加日志文件 -> 任务日志 API -> TasksPage 倒序渲染`

## 2. 后端日志契约

### 2.1 生命周期集中格式化

在 `TaskTrackerService` 的现有集中入口处理生命周期，避免七类任务分别拼接：

- `startTriggered`：无文本级别，消息前置 `🔻`。
- `update`：无文本级别；非空进度消息前置 `🔄`。
- `finish`：无文本级别，终态消息前置 `🔺`。
- `finishErr`：无文本级别，错误前置 `❌`，继续使用已脱敏错误。
- `appendDetails`：始终无文本级别；已有语义标记原样保留，无标记详情以 `ℹ️` 兜底。

倒序页面因此自然显示：顶部 `🔺 结束`，中间详情，底部 `🔻 开始`。

不改变 `taskLogStore.append` 的通用格式能力；任务中心统一传空 level。磁盘历史文件不重写。

### 2.2 详情生产者语义映射

只修改仍输出裸文本或语义不完整的现有格式化函数：

- 媒体扫描：沿用 `➕/🔄/🗑️`；库级摘要加 `ℹ️`，扫描失败加 `❌`。
- 媒体整理：错误 `❌`、跳过 `⏭️`、重新分类 `🔄`、清理 `🗑️`。
- 媒体/发现目录刮削：匹配或完成 `✅`、未匹配 `⚠️`、失败 `❌`、其他状态 `ℹ️`。
- 人物补齐：成功 `✅`、失败 `❌`、无效输入跳过 `⏭️`、标识失效并重置 `🔄`。
- 人物翻译：成功 `✅`、失败 `❌`、无有效译文 `⚠️`。
- 媒体轨道回填：保留此前确定的成功/失败格式。

不增加新的详情类型、配置项或依赖。

## 3. 前端兼容渲染

`TasksPage` 的日志行渲染器负责显示兼容，不改 API：

1. 解析并隐藏历史行中的 `[INFO]`、`[DETAIL]`、`[ERROR]`。
2. 识别 `🔺/🔻/➕/🗑️/🔄/✅/❌/⏭️/⚠️/ℹ️` 的首个状态标记。
3. 用 CSS 徽标替换状态字符，保留原时间戳与正文；颜色由主题类控制，不依赖 Emoji 字体。
4. 历史 `[ERROR]` 裸文本补 `❌`；历史 `[DETAIL]`、`[INFO]` 裸文本补 `ℹ️`。
5. 保持现有倒序、换行、日期选择、截断提示和手动刷新逻辑。

颜色映射：开始/结束为紫色，信息为青蓝，新增/成功为绿色，删除/失败为红色，更新为蓝色，跳过为中性灰，警告为橙色。

## 4. 兼容性与安全

- 新旧日志可在同一文件中混合显示。
- 不迁移历史文件，回滚只需回退代码；旧文件仍可由原读取逻辑展示。
- 日志写入失败仍只记录应用错误，不阻断业务任务。
- 已有 URL/路径脱敏边界保持不变；样式层不解析或扩展敏感正文。

## 5. 取舍

- 选择中央生命周期格式化，而不是修改所有 start/finish 调用，减少重复和遗漏。
- 详情语义只能由业务生产者准确判断，因此仅在现有详情格式化函数中补标记；中央层只提供 `ℹ️` 兜底。
- 不引入结构化日志事件或前端测试框架；当前文本文件契约和现有工具足以完成目标。

## 6. 回滚

后端、前端和规范改动均为文本格式层修改，无数据迁移。回滚代码即可恢复旧写入/展示；任务执行记录和历史日志文件不需要处理。
