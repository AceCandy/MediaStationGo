# 统一任务中心日志样式

## Goal

统一任务中心所有任务的日志结构和视觉语义，去除不直观的文本级别标签，使倒序日志仍能清楚展示任务边界，并让每条详情通过稳定的彩色状态标记快速识别。

## Background

- 任务日志文件当前由 `TaskTrackerService` 集中写入：启动、更新和结束消息使用 `info`，详情默认使用 `detail`，最终错误使用 `error`（`internal/service/task_tracker.go:158-180,286-345,385-403`）。
- 日志页面按行倒序展示，因此一个任务块在视觉上应由顶部结束标记和底部开始标记包裹（`web/src/pages/TasksPage.tsx:35-39,136-182`）。
- 当前生产者格式不一致：媒体库扫描已有 `➕`、`🔄`、`🗑️`，媒体轨道回填已有成功/失败标记，整理、刮削、人物补齐和人物翻译仍存在无标记详情。
- 现有工作树包含本轮此前完成但尚未提交的媒体轨道回填日志、远程探测等待、日志刷新按钮和彩色状态徽标修改；本任务应保留并纳入统一方案，不回退这些改动。

## Requirements

- R1. 任务中心展示的所有新日志不再显示 `[INFO]`、`[DETAIL]` 或 `[ERROR]`；最终错误统一使用红色 `❌`。
- R2. 任务开始行使用 `🔻`，任务结束行使用 `🔺`。由于页面倒序，结束行显示在任务块顶部、开始行显示在底部。
- R3. 所有详情行必须有一个明确语义标记，基础映射为：
  - `➕` 新增
  - `🗑️` 删除或清理
  - `🔄` 更新、重新分类或进度
  - `✅` 成功
  - `❌` 失败
  - `⏭️` 跳过
  - `⚠️` 警告或未匹配
  - `ℹ️` 无法归入以上语义的普通摘要
- R4. 前端不得依赖操作系统的彩色 Emoji 字体；状态标记由任务日志渲染器绘制固定颜色的可访问徽标。
- R5. 统一覆盖任务定义：媒体整理、媒体库扫描、媒体轨道回填、媒体入库刮削、发现目录刮削、人物信息补齐、人物翻译。
- R6. 历史日志中的 `[INFO]`、`[DETAIL]`、`[ERROR]` 和已存在的状态 Emoji 必须在当前日志页面兼容显示，不要求改写已有日志文件。
- R7. 保留当前日志的时间戳、按日文件、尾部截断、倒序显示、日期选择和手动刷新行为。
- R8. 失败详情继续执行 URL/路径脱敏，不因样式统一扩大敏感信息输出。
- R9. 采用中央日志生命周期格式化和少量现有详情生产者映射，避免每个任务重复实现开始/结束标签。

## Out of Scope

- 不改任务执行、调度、重试或业务状态语义。
- 不迁移或重写磁盘上的历史日志文件。
- 不新增日志筛选、搜索、自动轮询或下载功能。
- 不引入新的前端依赖或日志结构化存储格式。

## Acceptance Criteria

- [ ] AC1. 新执行的任一任务日志不包含 `[INFO]`、`[DETAIL]` 或 `[ERROR]`。
- [ ] AC2. 倒序显示中，同一任务执行的结束行位于开始行上方，并分别显示彩色 `🔺`、`🔻` 徽标。
- [ ] AC3. 新增、删除、更新、成功、失败、跳过、警告和普通摘要详情分别使用 R3 中的标记和固定颜色。
- [ ] AC4. 七类任务定义产生的每一条详情都有标记；无裸文本详情。
- [ ] AC5. 历史日志中的文本级别标签在页面上不再裸露，已有 Emoji 能按同一颜色规则显示。
- [ ] AC6. 日志仍按日期读取、按行倒序、保持空行和尾换行；刷新按钮重新加载当前日期且旧请求不能覆盖新请求。
- [ ] AC7. 日志文件仍只追加，任务业务执行不因日志写入失败而失败。
- [ ] AC8. 后端针对生命周期/详情格式的测试、前端 lint、前端生产构建和 `git diff --check` 通过。

## Notes

- 本任务跨后端日志契约、多个任务详情生产者和前端渲染，按复杂任务处理。
