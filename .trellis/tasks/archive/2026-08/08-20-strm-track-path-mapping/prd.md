# STRM 远程轨道路径映射

## Goal

当 STRM 内容是远程 HTTP(S) 链接时，允许在媒体轨道提取阶段将该链接映射为后端可访问的本地媒体路径，从而对本地文件进行轨道探测/提取，不改变现有播放请求的 302 映射行为。

## Background

- 现有 `playback.path_mappings` 用于播放请求的本地路径→HTTP(S) 地址转换，每行格式为 `本地路径前缀 => 远程 URL 前缀`，最长本地前缀优先；命中后播放接口返回 302。
- 用户希望增加“提取轨道路径映射”，将 STRM 中的远程链接反向转换为本地路径，供轨道提取使用。
- `MediaProbeService.ProbeMedia` 是媒体轨道探测和结果写入的统一入口；`resolveSource` 当前会将 HTTP(S) STRM 目标交给远程 `ffprobe`。
- 内嵌于媒体容器的视频、音频和字幕流由媒体轨道探测产生；外挂字幕由独立的目录扫描逻辑产生。

## Requirements

- 新增独立的轨道提取路径映射配置，不复用或改变现有 302 播放映射的方向和语义。
- 新配置每行使用 `远程 HTTP(S) URL 前缀 => 本地路径前缀`，多条规则命中时最长远程 URL 前缀优先。
- 仅当媒体容器标记为 STRM 或媒体路径扩展名为 `.strm`，且其目标是可映射的远程 HTTP(S) 链接时使用本地路径。
- 映射仅用于 FFprobe 提取媒体容器内嵌的视频、音频和字幕信息。
- 未匹配映射时保持现有轨道提取行为。
- 规则命中但映射后的本地文件不存在或不可访问时，回退到现有远程 FFprobe。
- 映射后的本地文件必须继续使用现有本地媒体探测与源身份一致性校验，避免探测期间源变化时写入过期结果。

## Out of Scope

- 外挂字幕的目录扫描、发现和提供行为。
- 播放路由、302 映射或播放直链预解析行为。
- 非 STRM 媒体的本地路径转换。

## Acceptance Criteria

- [x] 匹配配置的 STRM 远程链接在轨道提取时被转换为预期的本地路径。
- [x] 未匹配、非 STRM 或非 HTTP(S) 输入的现有行为不变。
- [x] 现有“本地播放路径 302 映射”的配置和播放行为不受影响。
- [x] 映射逻辑的定向测试覆盖最长前缀命中、未命中保持远程探测，以及映射本地文件不可用时回退到远程探测。
