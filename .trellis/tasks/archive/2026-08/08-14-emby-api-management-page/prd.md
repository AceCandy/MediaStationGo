# 新增 Emby 接口管理页

## Goal

为管理员提供独立的“Emby 接口”菜单页，集中说明 MediaStationGo 当前对外兼容的 Emby 接口，重点覆盖播放器完成发现、认证、浏览、选流、播放、进度回传和会话维护所需的调用链。管理员无需阅读后端源码即可确认接口路径、鉴权方式、入参和返回结构。

## Requirements

- “观看空间”内必须在“我的”之后提供“播放器接口”子项，仅管理员可见。
- 不增加独立的“Emby 空间”；播放器接口仍使用管理员路由和权限保护。
- 页面内容必须以当前项目实际注册的 Emby 路由和处理器行为为依据，不把标准 Emby API 中尚未实现的能力描述为可用。
- 接口目录必须覆盖以下类别：服务发现与认证、用户、媒体库与媒体项、图片、播放信息、视频流与字幕、STRM/302 播放、播放进度、收藏与已播放状态、会话。
- 每个接口必须展示用途、HTTP 方法、路径、鉴权要求、支持状态、Path/Query/Header/Body 入参以及响应状态、字段说明和 JSON 示例；非 JSON 响应需要标明内容类型和行为。
- 对项目同时支持的 `/emby` 前缀、无前缀、大小写兼容路径和特殊别名，以统一说明或别名展示，避免将同一行为重复为多个接口条目。
- 对仅返回空结构或固定响应的兼容占位接口，必须与具备完整业务行为的接口明确区分。
- 支持按关键字搜索、按分类筛选、展开/折叠接口详情，并能复制接口路径和请求/响应示例。
- 页面需适配桌面、平板和移动端，内容不可横向挤压或互相遮挡；代码示例允许在自身区域内横向滚动。
- 页面必须复用现有管理端视觉语言、主题变量、布局和图标体系。

## Constraints

- 第一版是只读静态接口目录，不向接口发起请求，也不保存 Token、服务器地址或调试历史。
- 本次不修改 Emby 后端路由、协议行为或数据库结构。
- 接口示例不得包含真实 Token、用户信息、媒体路径或其他本地隐私数据。
- 页面数据应与展示组件分离，便于以后随实际兼容范围更新。

## Acceptance Criteria

- [x] 管理员侧边栏“观看空间”的“我的”之后存在“播放器接口”，可进入 `/admin/emby/interfaces`；非管理员在桌面侧栏和移动端底栏均不可见且不能直接访问。
- [x] 旧 `/admin/integrations/emby` 地址重定向到 `/admin/emby/interfaces`，已有链接不会失效。
- [x] 页面完整展示播放器核心接入链路所需类别，且每个接口均包含方法、路径、鉴权、支持状态、入参和出参信息。
- [x] `/emby` 与无前缀路由、大小写兼容规则和 `/emby/api/stream/:id` 等例外被准确说明。
- [x] “已实现”与“兼容占位”状态在列表中可直接识别，不会把空响应兼容端点误认为完整能力。
- [x] 搜索可匹配接口名称、路径和说明，分类筛选可收窄列表，清空条件后恢复全部接口。
- [x] 接口详情可独立展开/折叠，路径和代码示例可复制；复制失败不会破坏页面浏览。
- [x] 390x844、768x1024、1440x900 三种视口下无不可接受的重叠、截断或页面级横向滚动。
- [x] Web lint、TypeScript/Vite 构建和 `git diff --check` 通过。

## Out of Scope

- 在线 API 调试器、请求发送、Token 输入和请求历史。
- 从运行中的后端动态生成 OpenAPI/Swagger 文档。
- Emby 数据库导入、媒体库迁移或补齐新的 Emby 协议端点。
- 面向普通用户开放该菜单页。

## Risks

- 当前部分 Emby 路由为兼容客户端探测而返回空结构，若文案未区分支持层级，会造成能力误判。
- 后端路由继续演进后，静态目录可能滞后；本次通过集中式数据文件降低后续校对成本，但不会自动同步。
