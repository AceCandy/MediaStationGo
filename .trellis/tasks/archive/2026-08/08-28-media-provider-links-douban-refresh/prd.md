# 详情页外部来源链接与豆瓣缺失补齐

## Goal

让媒体详情页直接展示作品已有的豆瓣/TMDb 标识并可跳转到对应站点，同时让“豆瓣电影信息补齐”能够重新处理已有快照但仍缺少关键数据的电影，避免一次空快照永久阻止后续补齐。

## Background

- 详情页当前没有面向用户展示豆瓣/TMDb ID 及外部跳转入口。
- 作品的 provider ID 由 canonical metadata identifier 持有；媒体扫描提示不是权威作品标识。
- 本地存在对应 provider 详情快照时，需要在 ID 旁显示 `✅`。
- 当前豆瓣历史补齐只选择没有豆瓣快照的电影；一旦保存了缺少图片或简介的快照，后续任务不会再请求。
- `MediaView` 已从 canonical metadata identifier 投影 `tmdb_id` 和 `douban_id`；详情页不得改用 `Media.lookup_*` 扫描提示。
- `metadata_provider_snapshots.fetched_at` 记录成功保存快照的时间，可直接作为 24 小时冷却依据。
- 当前详情响应没有 provider 快照存在标记，需要由服务端补充；前端不得通过 ID 是否存在推测快照状态。

## Requirements

- R1：详情页在作品存在豆瓣 ID 或 TMDb ID 时展示对应 ID；不存在的 provider 不显示空入口。
- R2：点击豆瓣 ID 跳转到对应豆瓣电影页面，点击 TMDb ID 按作品类型跳转到对应 TMDb Movie/TV 页面。
- R3：若本地已保存该 provider 的详情快照，在对应 ID 旁显示 `✅`；标识仅表示快照存在，不表示字段完整。
- R4：豆瓣电影信息补齐继续只处理具有唯一豆瓣电影标识的 Movie，不扩展到 Series/Season/Episode，也不按标题猜测。
- R5：没有豆瓣快照的候选按现有行为获取；已有快照但缺少有效 poster、简介为空或标题不含汉字的候选允许重新请求豆瓣详情。年份、评分、上映日期、原名、语言、地区和类型等其他空字段仅随请求顺带补齐，不单独触发请求。
- R6：同一作品成功请求豆瓣详情后 24 小时内不得重复请求；失败请求不得伪装成成功冷却。
- R7：补齐只填充缺失字段，保留现有非空 canonical 字段和当前图片选择；豆瓣图片仍按候选图规则保存并仅在没有选择时提升。
- R8：任务保持批次、游标、串行节流和单项失败隔离，不新增依赖或独立任务。

## Acceptance Criteria

- [ ] AC1：详情页仅显示实际存在的豆瓣/TMDb ID，链接目标与 Movie/TV 类型正确。
- [ ] AC2：对应 provider 快照存在时显示 `✅`，不存在时不显示；判断来自服务端权威数据。
- [ ] AC3：已有豆瓣快照但缺海报、缺简介或缺中文标题且超过 24 小时的 Movie 会重新进入豆瓣补齐任务。
- [ ] AC4：24 小时内成功检查过的 Movie 不发起重复豆瓣请求。
- [ ] AC5：完整电影、非 Movie、豆瓣标识缺失或不唯一的条目不产生请求。
- [ ] AC6：重新补齐不会覆盖非空 canonical 字段或现有图片选择；可保存并提升缺失的豆瓣海报候选。
- [ ] AC7：任务指标能区分实际字段/图片变化、无变化和失败，不把零变化笼统显示为已补齐。

## Technical Notes

- 豆瓣现有填充边界可补 `title`、`original_name`、`overview`、`release_date`、`languages`、`countries`、`genres`、`rating`、`year`，以及 poster 候选；所有写入均保持 fill-only。
- 已有快照但需要重查时必须调用 provider 获取新详情并替换快照，不能继续复用旧快照，否则缺失内容永远不会变化。
- 成功返回并保存新快照后开始 24 小时冷却；请求、解析或持久化失败不推进冷却。

## Out of Scope

- 为没有权威 provider ID 的作品按标题搜索或自动绑定 ID。
- 修改豆瓣/TMDb 网站内容或绕过其访问限制。
- 将 `✅` 解释为图片、简介等内容已经完整。
