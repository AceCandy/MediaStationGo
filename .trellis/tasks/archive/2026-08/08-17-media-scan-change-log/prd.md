# 记录媒体扫描变更文件

## Goal

让媒体库扫描任务除了数量汇总外，直接显示本次新增、更新、删除的文件路径，并说明更新判定原因，便于定位 `.strm` 文件被误判更新的问题。

## Background

- 当前 `ScanResult` 只保存数量和错误，任务详情无法显示发生变化的文件。
- 手动扫描和“扫描已启用媒体库”任务分别组装任务详情，都需要展示相同格式的变更明细。
- 用户确认媒体库全部由 `.strm` 文件组成，当前任务只增加可诊断信息，不继续假设误更新根因。

## Requirements

- 保留现有媒体库扫描数量汇总和错误信息。
- 在任务详情中列出本次所有新增、更新、删除文件，不截断、不包含跳过文件。
- 变更明细使用固定图标和中文动作，最终任务日志不显示 `[DETAIL]` 标签：
  - `➕ 新增 <path>`
  - `🔄 更新 <path>（<reason>）`
  - `🗑️ 删除 <path>`
- 更新原因至少区分文件大小、纳秒级 mtime、首次补录文件指纹、本地元数据和派生元数据变化；多个条件同时变化时不得隐藏文件指纹变化。
- 手动单库扫描和计划任务“扫描已启用媒体库”使用相同的变更格式。

## Out of Scope

- 本任务不修改文件指纹判断规则。
- 本任务不修复尚未由具体文件和更新原因证实的误更新根因。
- 本任务不记录未变化或跳过的文件路径。

## Acceptance Criteria

- [x] 扫描新增文件后，任务详情包含 `➕ 新增` 和完整文件路径。
- [x] 扫描已有文件发生变化后，任务详情包含 `🔄 更新`、完整文件路径及准确原因。
- [x] 扫描发现文件消失并硬删除媒体记录后，任务详情包含 `🗑️ 删除` 和原文件路径。
- [x] 连续扫描未变化的文件不会产生变更明细。
- [x] 手动单库扫描与“扫描已启用媒体库”任务都展示变更明细，原数量汇总和错误详情保持兼容。
