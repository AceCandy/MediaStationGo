# 任务中心按任务定义统一展示

## Goal

将任务中心从“每次执行记录列表”改为“任务定义与运行状态列表”，使管理员在一个页面中看清所有后台任务、当前状态、调度方式、最近执行情况，并直接执行支持手动触发的任务或查看相关日志。

## Requirements

- 每种后台任务在主列表中固定展示一行，不因历史执行次数重复。
- 每行展示任务名称、触发方式或周期、当前状态、最近执行结果、最近执行时间；定时任务还展示下次执行时间。
- 每行明确展示该任务是否支持手动执行；支持时提供行内执行操作，不支持时不提供无效操作。
- 人物信息补齐及现有周期任务并入统一列表，不再使用页面右上角的孤立入口。
- 日志操作从任务行进入该任务的相关日志或执行历史；历史执行记录不再直接铺在任务中心主列表。
- 保留现有 `task_executions` 执行摘要与按执行 ID 存储的日志，不迁移、不删除历史数据。
- 核对当前已接入的后台任务种类和触发能力，避免改版后遗漏既有任务。
- 保持现有管理员权限边界和已有后台执行语义不变。
- 任务定义至少覆盖：整理流水线、媒体库扫描、媒体轨道回填、媒体入库刮削、发现目录刮削、人物信息补齐、人物翻译、回收站清理。
- 同一执行 `kind` 下的不同业务任务必须分行展示：人物信息补齐与人物翻译分开；媒体入库刮削与发现目录刮削分开。
- 只有已有无范围全局触发入口的任务提供“立即执行”；需要媒体库、路径或具体对象范围的任务仅展示其触发来源，不在任务中心新增含义不明确的全局操作。
- 任务日志视图按任务定义列出相关执行历史，并可读取选中执行的现有日志文件。

## Acceptance Criteria

- [x] 同一种任务连续执行多次后，任务中心主列表仍只显示一行。
- [x] 任务行可区分当前运行状态与最近一次执行结果，不再把 `completed` 阶段直接当作当前任务状态。
- [x] 定时任务可看到周期、最近执行时间和下次执行时间，并可在支持时立即执行。
- [x] 人物补齐可从对应任务行手动触发，页面右上角不再显示“补齐人物”和“周期任务”按钮。
- [x] 日志入口能够查看对应任务的相关执行日志；没有执行记录时提供明确空状态。
- [x] 所有现有任务定义在页面中可见，即使某项任务尚无历史执行记录。
- [x] 桌面和移动宽度下无内容重叠，操作按钮具有可访问名称和禁用状态。
- [x] 相关后端测试、前端 lint/build 与独立代码复核通过。

## Out of Scope

- 不修改各业务任务的处理算法、优先级或补齐条件。
- 不清理或归并历史执行记录和日志文件。
- 不新增任务启停、Cron 编辑或调度配置能力；只展示并复用现有能力。
- 不把文件 watcher、通知、搜索预热等常驻服务伪装成一次性后台任务。

## Confirmed Facts

- 当前 `GET /api/tasks` 与 `TaskExecutionRepository.List` 返回逐次执行记录，前端逐条渲染，因此同一任务会反复出现。
- 调度器固定注册 `library_scan`、`organize_source`、`recycle_purge`，均已有立即执行入口。
- 人物信息补齐已有全局手动触发入口；人物翻译仅由 worker 按待翻译业务状态触发。
- 轨道回填和部分扫描/整理入口需要媒体库、路径或具体对象上下文，不能从无范围的任务中心直接重放。
- 现有日志以执行 UUID 为索引按日存储，任务定义层必须先展示相关执行历史，再读取具体执行日志。
