# 统一定时任务手动触发并简化人物补齐

## Goal

让任务中心中面向用户的定时任务具备一致的立即手动执行能力，并将人物信息补齐简化为仅支持定时和手动触发，避免把服务启动唤醒误呈现为业务事件。

## Background

- `internal/service/task_definitions.go` 中媒体整理、媒体库扫描和人物信息补齐已经支持手动执行；人物翻译和账号清理巡检当前只有定时触发。
- 人物信息补齐的 `queuePeopleBackfill` 仅由服务启动和手动入口调用，没有来自刮削、扫描等业务流程的事件调用链；当前“事件”实际是服务启动后的一次初始唤醒。
- 调度器的 `RunNowAsync` 已提供独立于定时开关的立即执行能力，并通过 context 标识手动运行；媒体整理和媒体库扫描已经使用该机制记录正确的触发来源。

## Requirements

- R1：任务中心中的媒体整理、媒体库扫描、人物信息补齐、人物翻译和账号清理巡检均须显示手动执行操作；关闭定时计划不得禁用手动执行。
- R2：手动执行复用对应调度任务的业务逻辑，不维护第二套执行流程，并在任务记录中标记为 `manual`；周期到点执行仍标记为 `scheduled`。
- R3：人物翻译增加手动执行能力，继续沿用当前启用条件、单次最多处理 1000 组和并发互斥约束。
- R4：人物信息补齐移除服务启动时的事件唤醒和 `event` 触发方式，仅保留调度器定时执行与手动立即执行。
- R5：任务中心、现有全局人物补齐接口及媒体库页面使用的兼容接口仍可手动触发人物信息补齐。
- R6：人物信息补齐手动空跑继续留下完成记录；人物翻译继续沿用现有启用条件与空跑静默行为，不因增加手动入口改变候选和记录规则。
- R7：从任务中心手动执行账号清理巡检前，必须使用现有确认对话框明确提示会立即按当前保号规则检查并清理账号；取消确认不得发送执行请求。

## Acceptance Criteria

- [x] AC1：人物信息补齐的任务定义显示“定时 / 手动”，不再显示或产生 `event` 触发记录。
- [x] AC2：服务启动不再自动执行人物信息补齐；启用的周期计划到点后仍能执行。
- [x] AC3：从任务中心手动执行人物信息补齐、人物翻译和账号清理巡检时，接口返回已接受；实际创建的任务记录触发来源为 `manual`。
- [x] AC4：人物信息补齐的现有兼容接口仍能触发同一条手动执行链路。
- [x] AC5：定时计划关闭时，任务中心的手动执行仍可用，且不会改变计划开关或下次执行时间配置。
- [x] AC6：同一调度任务正在运行时再次手动触发，继续返回现有冲突响应，不产生并发重复执行。
- [x] AC7：相关服务和处理器测试覆盖定时/手动来源、人物补齐无启动事件、任务定义动作以及兼容入口。
- [x] AC8：账号清理巡检点击立即执行时先显示危险确认；取消后不调用 API，确认后只调用一次。

## Out of Scope

- 不为文件事件或业务事件型任务新增手动执行能力。
- 不改变人物补齐候选规则、人物翻译批次/上限、账号清理规则或任何定时周期配置。
- 不为任务中心以外的直接 API 调用新增确认令牌；账号清理确认是防止界面误触的前端保护。
- 不新增调度框架、任务类型或前端专用执行流程。

## Constraints

- 保留现有未提交的 `web/src/index.css` 与 `web/src/pages/PlaybackStatsPage.tsx`，本任务不修改它们。
- 优先复用现有调度器立即执行入口和手动运行 context，保持改动可回滚且不增加抽象。
