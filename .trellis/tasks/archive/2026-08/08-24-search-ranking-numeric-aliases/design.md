# 搜索候选与统一排序设计

## 决策与边界

非空 Web/Emby 搜索最多处理 100 个 Metadata 候选。OpenSearch 与 PostgreSQL
只负责根据相同关键词语义召回候选，不按调用方页码截取；repository 在数据库中
读取候选的最新标题、原名、类型、简介和年份，使用同一个 Go 排序器排序，再按
调用方的 `offset/limit` 切页。

这是明确的产品上限：返回总数最多为 100，第 101 条以后不展示，也不保证它比
前 100 条更不相关。无关键词浏览不受影响，继续使用现有数据库排序和分页。

## 查询与数字等价

沿用 `MediaSearchTerms` 的清理和拆词规则。每个关键词生成一个候选组：原词始终
保留；当整个关键词是无前导零的十进制 `0` 至 `100`，追加标准中文数字；当它是
标准中文数字 `零` 至 `一百`，追加十进制数字。标准中文输出和输入只有一套：
`零`、`一`至`九`、`十`、`十一`至`十九`、`二十`等整十、`二十一`等非整十，
以及`一百`；`一十`、`一百零`等不视为标准写法。

不同关键词组之间必须 AND；同一组的原词和数字等价词 OR。例如 `死神 44` 要求
同时命中“死神”和 `44|四十四`。候选匹配和共享排序采用最小公共 token 规则：
连续拉丁字母或数字为一个 token，每个汉字为一个 token。一种写法的全部 token
必须在同一个允许字段命中；不同关键词组可以分布在不同字段。因此“死神”要求
“死”与“神”在同一字段全部命中，但可以进入不连续的“其它匹配”。不支持范围
外数字、前导零、`〇`、`两`、财务大写、罗马数字或年份读法。标准数字及其等价
写法作为一个不可拆分的逻辑 token，`44` 不得仅因汉字 token 重叠命中“四十”。

OpenSearch 外层 `bool.must` 每项对应一个关键词组；组内 `bool.should` 每项对应
原写法或数字等价写法，并要求至少一种写法命中。普通写法以 `multi_match`
`best_fields + operator: and` 保证分析后的 token 在同一字段全部命中；数字写法
使用 phrase 保持完整顺序。同时移除模糊匹配，避免产生 PostgreSQL 无法复现的
fuzzy 语义。查询固定
`from: 0, size: 100`，仍可用 `_score` 帮助选择有限候选，但 `_score` 不参与
最终排序。默认 analyzer 的实际拆词只影响有限候选召回；最终层级和相关度始终
使用共享 token 规则计算。

PostgreSQL 对每个关键词组生成“每种等价写法的全部 token 在同一字段 AND、
不同等价写法 OR”，并保持关键词组间 AND；固定读取最多 100 个候选。保留现有
粗排作为超过上限时的候选选择依据，不把它当作最终顺序。超过 100 时允许两个
后端产生不同候选集，测试只要求同一候选集经过共享排序后顺序一致。

## 共享排序

Go 排序器只接收数据库最新投影，因此两个候选来源使用完全相同的最终规则。

匹配层级严格为：

1. 完全匹配：标题或原名等于完整查询或数字等价写法。
2. 完整包含：同一个标题或原名按查询顺序连续包含每个关键词组的一种完整写法，
   但不完全相等；数字原词和等价词均可作为该组的完整写法。
3. 其它匹配：每个关键词组均有一种写法的全部 token 在某个允许字段命中，但不
   满足前两层；不同关键词组可以分布在不同字段。

层级不能被任何后续键反转。完全匹配层按年份降序、Metadata ID 升序。完整包含
和其它匹配依次比较：

1. 去重后的查询 token 在标题中的命中数降序；
2. 在原名中的命中数降序；
3. 在 `genres` 中的命中数降序；
4. 在简介中的命中数降序；
5. 首选字段中最早 token 的 rune 下标升序；
6. 首选字段中已命中 token 从最早开始到最晚结束的 rune 跨度升序；
7. 标题编号降序；
8. 年份降序；
9. Metadata ID 升序。

“首选字段”取第一个有 token 命中的标题，否则取原名；两者均未命中时位置和
跨度使用最大值。Emby 的允许字段只有标题和原名，因此 `genres`、简介的命中数
固定为 0；Web 才使用全部四个字段。token 重复时只计一次。标题总长度不参与
相关度，避免数字位数在编号排序之前改变 `死神10/9/2` 的顺序。

标题编号按从左到右扫描的完整连续数字段识别，取最后一个有效段：阿拉伯数字段
必须是整个十进制段且值在 `0–100`；中文数字段必须是由 `零一二三四五六七八九
十百` 组成的整个连续段且符合上述唯一标准写法。超范围或非标准的整个段忽略，
不能从 `1000` 截取 `100`，也不能从 `一百零一` 截取 `一百`。两种写法映射为
同一个整数，未识别时为 0。相关度键完整比较完毕后才比较编号，所以 `死神2`
可以因更早、更紧凑的命中排在 `新死神10` 前；相关度相同时才是
`死神10/死神十 > 死神9 > 死神2`。

## 分页与返回总数

```text
非空查询
  -> 关键词组与数字等价词
  -> OpenSearch 或 PostgreSQL 召回至多 100 个 Metadata ID
  -> PostgreSQL 读取最新排序字段
  -> Go 统一排序
  -> total = 候选数（最大 100）
  -> 按 offset/limit 内存切页
  -> 按切页后的 Metadata ID 顺序组装 Web/Emby 响应
```

Emby 的 `StartIndex/Limit`、Web 的分页参数和响应结构保持兼容，只改变非空搜索的
内部执行方式。负 offset 归零，非正 limit 使用现有默认值 50；offset 不小于候选
数时返回空页。服务层不再进行第二次排序，只按 repository 返回的 ID 顺序组装。

## 最小改动与迁移

- 保留现有搜索后端接口，repository 对非空查询固定以 `0/100` 调用后端并忽略
  后端原始 total，减少调用方改动。
- 不新增依赖，不增加 OpenSearch 排序脚本、raw keyword、年份或编号索引字段，
  因此无需升级 mapping schema 或重建索引。
- 只新增 repository 内的数字转换、候选投影、比较和安全切页 helper；Web 与 Emby
  共用现有 Metadata 搜索入口。

## 风险与回滚

- 超过 100 个命中时，两个后端的有限候选集合可能不同，这是已确认接受的上限
  语义；最终排序只保证各自召回的候选集内部正确。
- 共享相关度是确定性业务规则，不等同于 BM25；后续调整只需修改一个 Go 比较器。
- 回滚只需恢复原有后端分页和排序，不涉及索引迁移或数据变更。
