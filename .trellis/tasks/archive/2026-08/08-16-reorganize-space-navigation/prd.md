# 调整空间导航并合并系统监控

## Goal

重新组织管理员侧栏的信息架构，让文件相关操作集中在独立的“文件空间”，让剩余管理功能直接可见，并将存储与运行状态集中到“系统监控”页面。

## Background

- 当前一级导航只有“观看空间”和“管理空间”。
- 当前“管理空间”下还有“媒体入库”“存储与清理”“任务与运行”“用户与集成”“系统设置”五个嵌套分组。
- “存储概览”和“运行监控”目前是两个独立页面。
- 路由清单 `web/src/appRoutes.tsx` 是访问权限、路由和导航元数据的唯一来源。

## Requirements

1. 一级导航按“观看空间”“文件空间”“管理空间”的顺序展示；“文件空间”和“管理空间”仅管理员可见。
2. 原“媒体入库”升级为一级“文件空间”，包含以下直接导航项：
   - 媒体库管理
   - 文件与入库
   - STRM 工具
   - 重复文件
   - 回收站
   - 任务中心
   - 外部 API
3. “管理空间”不再展示任何嵌套分组，剩余页面全部作为直接导航项展示：
   - 系统监控
   - 用户管理
   - 通知渠道
   - AI 会话
   - 常规
   - 播放与探测
   - 识别词
   - 内容访问
4. “存储概览”和“运行监控”的现有内容合并到一个名为“系统监控”的页面；存储数据加载与实时运行指标加载互不阻塞。
5. 现有管理页面的管理员权限保持不变。
6. 被移动页面保留现有 URL；原运行监控 URL `/admin/tasks/stats` 使用 replace 重定向到合并后的系统监控页面，避免旧书签失效或出现重复入口。
7. 观看空间及其现有页面不在本次调整范围内。

## Acceptance Criteria

- [x] 管理员侧栏依次显示“观看空间”“文件空间”“管理空间”，普通用户只看到有权访问的“观看空间”。
- [x] “文件空间”直接显示七个指定页面，且不存在“媒体入库”二级分组。
- [x] “管理空间”直接显示八个剩余页面，且不存在“存储与清理”“任务与运行”“用户与集成”“系统设置”等二级分组。
- [x] “系统监控”同时展示原存储概览内容和原运行监控内容，实时指标仍每 2 秒刷新。
- [x] 存储接口失败时运行监控仍可使用；监控接口失败时存储概览仍可使用，并分别显示对应错误状态。
- [x] `/admin/tasks/stats` 自动替换跳转至 `/admin/storage`；其他现有管理 URL 仍可直接访问。
- [x] 当前路由权限过滤、活动导航高亮、展开状态和移动端侧栏关闭行为保持有效。
- [x] 390x844、768x1024、1440x900 视口下导航和系统监控页无横向溢出或控件遮挡，浏览器控制台无新增错误。
- [x] Web lint、TypeScript/Vite build 和 `git diff --check` 通过。

## Out of Scope

- 修改后端存储或监控 API。
- 修改观看空间的页面、顺序或权限。
- 重命名或迁移除原运行监控页以外的 URL。
- 重做侧栏交互或视觉样式。
