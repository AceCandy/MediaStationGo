# 修复电影库剧集误判

## Goal

防止电影库条目因错误的季集字段被当作电视剧刮削，同时将电视剧库的文件名季集识别收紧为 `SxxExx` 标记。

## Background

- `mediaIsEpisodic` 当前优先相信 `season_num` / `episode_num`，电影库中的脏字段会覆盖媒体库类型（`scraper_query.go:108-130`）。
- TMDB 外部 ID 查询在判定为剧集后强制使用 `tv` 类型，最终请求 `/tv/{id}`（`scraper_lookup.go:18-36,101-109`）。
- 扫描当前对所有媒体库无条件调用 `ParseEpisode`，并把结果写入媒体行（`scanner_local_ingest.go:41-53,188-200`）。
- 当前 `ParseEpisode` 还接受 `1x02`、`EP02`、`第2集`、`- 36`、季目录加纯数字文件名等格式（`episode_parser.go:24-36,43-89`）。
- 成功匹配为电影时，现有逻辑已经会清空季、集及剧集关联提示（`scraper.go:328-339`）。

## Requirements

- 媒体库类型是刮削媒体类型的最高优先级：
  - `movie` / `nfo_movie` 始终按电影处理，不得因已有季集字段或路径命名改走电视剧刮削。
  - 电视剧类媒体库仍按电视剧处理。
- 扫描 `movie` / `nfo_movie` 媒体库时不得从文件名写入季集号。
- 扫描 `tv` / `nfo_tv` 媒体库时，只从大小写不敏感的 `S` + 1～2 位季号 + `E` + 1～3 位集号标记读取季集号，例如 `S01E02`、`s1e2`。
- 不改变 `anime` / `variety` 当前支持的命名兼容规则，避免扩大本次修复影响范围。
- 已有电影库脏季集字段在对应媒体库重扫时定向清理：
  - 仅处理 `movie` / `nfo_movie` 库中季号或集号非零的媒体行；
  - 清空季号、集号和剧集关联提示；
  - 已绑定电影元数据的记录保留正确绑定；
  - 已绑定剧集类元数据的记录解除错误绑定并重新进入刮削队列；
  - 原本处于刮削失败或未匹配状态的脏记录清除旧错误并重新进入刮削队列；
  - 清理数量计入扫描结果，供用户核对。
- 刮削判断立即忽略电影库中的历史季集字段，待处理列表不再把它们显示为 `SxxExx`。
- 不增加启动迁移或跨库批量清理；历史纠正只随用户主动重扫对应电影库发生。

## Out of Scope

- 不修改动漫、综艺媒体库的季集命名兼容规则。
- 不在服务启动时自动重写历史媒体行，不删除文件、元数据实体或 provider ID。
- 不改变手动匹配流程和 TMDB API 契约。

## Acceptance Criteria

- [ ] 电影库条目即使已有 `season_num=20`、`episode_num=24` 和 TMDB ID，也请求 `/movie/{id}`，不请求 `/tv/{id}`。
- [ ] 电影库扫描文件名 `Movie (2024).strm`、`36总局 (2025).strm`、`Title - 36.strm` 时均写入季号 0、集号 0。
- [ ] 电视剧库扫描 `Show.S01E36.strm` 时写入季号 1、集号 36。
- [ ] 电视剧库扫描 `Show.E36.strm`、`Show.1x36.strm`、`Show - 36.strm`、`第36集.strm` 时不从文件名写入季集号。
- [ ] 动漫和综艺媒体库原有解析行为保持不变。
- [ ] 刮削待处理页面不会为电影库的历史脏字段显示 `SxxExx`。
- [ ] 重扫电影库后，该库所有季号或集号非零的媒体行均被纠正，扫描结果报告清理数量。
- [ ] 已正确绑定电影元数据的脏记录在清理季集字段后仍保留原绑定。
- [ ] 错绑剧集元数据、刮削失败或未匹配的脏记录清除错误状态并重新进入电影刮削队列。
- [ ] 清理过程不影响其他媒体库，不删除媒体文件、元数据实体或 provider ID。
- [ ] 相关后端单元测试和前端针对性测试通过。

## Constraints

- 采用最小、可回滚改动；不引入新依赖或新配置。
- 仅运行针对性测试，不启动服务、不执行全量测试。
