# 将豆瓣 Cookie 收口到外部 API 配置

## Goal

让管理员只在“外部 API → Douban”中安全配置豆瓣 Cookie，并让所有豆瓣 HTTP 请求动态携带当前配置；彻底删除 `secrets.douban_cookie` 配置文件和环境变量入口。同时让管理员可从单媒体详情页立即补齐该电影的豆瓣信息，并让批量补齐在豆瓣接口暂时不可用时停止当前批次而不是继续请求或保存无用的降级结果。

## Background

- 外部 API 已有 `douban` 配置行，凭据通过 `api_configs.api_key` 加密保存，并通过公共视图遮蔽。
- 当前 `DoubanProvider` 不读取数据库配置，只读取启动配置 `SecretsConfig.DoubanCookie`，因此管理页保存的 Douban 凭据不生效。
- 豆瓣搜索、详情和发现请求统一经过 `DoubanProvider.setHeaders`，适合在一个共享入口附加 Cookie。
- 用户已明确选择数据库配置为唯一来源，不保留旧配置回退。

## Requirements

1. “外部 API → Douban”必须把凭据明确展示为 `Cookie`，使用密码输入框，并沿用现有遮蔽、加密保存和清除能力。
2. Douban Cookie 继续复用现有 `api_key` HTTP 字段和数据库列；`api_configs.api_key` 必须使用 `text` 容纳加密后的长 Cookie，不新增表、列或专用 Cookie API。
3. `DoubanProvider` 必须在每次对豆瓣发起 HTTP 请求前读取 `APIConfigService.Resolve(ctx, "douban")`，以便保存、替换、清除后无需重启即可生效。
4. 当 Douban 配置已启用且 Cookie 非空时，请求必须包含完整 `Cookie` 头；配置禁用、清除或不存在时必须匿名请求。
5. 数据库配置读取失败时记录不含凭据的警告并继续匿名请求，保持豆瓣 Cookie 可选的现有行为。
6. 删除 `SecretsConfig.DoubanCookie`、`.env.example` 中对应环境变量示例，以及运行时对旧配置的全部读取。
7. 不得在日志、测试失败信息、响应、注释或任务文档中输出真实 Cookie。
8. 单媒体详情页必须提供管理员可见的“补齐豆瓣信息”操作，只处理当前共享电影元数据，不遍历全局游标；非电影或没有唯一豆瓣电影 ID 时必须返回明确结果且不发起豆瓣请求。
9. 单媒体与批量豆瓣电影补齐必须只依赖移动详情接口的完整响应，不得调用或保存摘要降级响应。普通刮削和剧集数获取继续保留现有 `subject_abstract` 降级兼容。
10. 移动详情接口返回需要稍后重试的上游错误时，批量任务必须立即结束当前执行，不处理后续候选，也不得推进当前错误条目的游标；已完成条目的游标进度保留，下次定时或手动执行必须先重新请求同一条目。任务计划本身保持启用。可恢复错误包括网络/超时、HTTP 403/429/5xx、空响应、非法 JSON 和 HTTP 200 错误对象；明确 404/条目不存在以及本地永久性歧义记录后继续，避免坏 ID 永久阻塞游标。
11. 单媒体补齐遇到可恢复上游错误时必须给页面返回可识别的暂时不可用结果，页面显示“豆瓣请求受限或暂时不可用，请稍后重试”，不得显示笼统成功。
12. 批量任务日志和指标必须区分：字段更新、海报新增、仅刷新完整快照、上游未提供当前缺失数据、永久失败、接口异常暂停。不得再把“成功保存快照但没有字段/海报变化”概括为没有执行任何工作的“本次无变更”。
13. 批量候选仍只包含本地豆瓣数据不完整且超过刷新冷却的电影；一次执行最多发起 20 次移动详情请求，并保持串行及两秒间隔。

## Acceptance Criteria

- [ ] Douban 编辑行显示 `Cookie` 和匹配的占位文案，保存后仍只显示遮蔽状态。
- [ ] Douban 清除操作使用“Cookie”语义，并清空数据库加密凭据。
- [ ] 搜索、详情及发现请求在配置启用且 Cookie 存在时都携带 `Cookie` 请求头。
- [ ] 同一 `DoubanProvider` 实例在 Cookie 更新后，下一次请求携带新值，无需重启。
- [ ] Cookie 被清除、配置被禁用或数据库没有配置时，请求不包含 `Cookie` 头。
- [ ] 数据库读取失败时请求继续执行，日志不包含 Cookie。
- [ ] 旧库的 `api_configs.api_key varchar(512)` 在启动迁移时无损扩宽为 `text`，长 Cookie 加密后可以保存。
- [ ] `DoubanCookie`、`douban_cookie`、`MEDIASTATION_SECRETS_DOUBAN_COOKIE` 在产品代码及示例配置中不再存在。
- [ ] 聚焦后端测试覆盖携带、动态更新、清除/禁用和匿名回退；前端通过 lint/build 验证。
- [ ] `git diff --check` 通过，且不影响当前工作树中的无关任务文件。
- [ ] 管理员可在单媒体详情页立即补齐当前电影；成功后页面刷新并反映最新豆瓣完整性状态。
- [ ] 单媒体操作不会推进或重置全局 `internal.douban_movie_enrichment_cursor`。
- [ ] 批量与单媒体补齐不把摘要降级响应保存为成功快照。
- [ ] 普通刮削和剧集数获取仍可使用既有摘要降级，不受补齐专用移动接口约束。
- [ ] 批量任务遇到需要稍后重试的上游错误后立即停止，本条游标不推进、后续候选不请求，下次执行首先重试同一条。
- [ ] 单媒体操作遇到可恢复上游错误时显示明确的暂时不可用提示，不报告成功。
- [ ] 一批最多请求 20 个不完整候选；日志明确报告扫描数、字段/海报变化、完整快照刷新、无可补数据、永久失败和接口异常暂停。
- [ ] 聚焦测试覆盖单媒体成功/无标识/可恢复上游错误、批量停批与同条重试、明确 404 后继续、无变化日志分类。

## Out of Scope

- 自动迁移旧 YAML/环境变量中的 Cookie 到数据库。
- 自动绕过、破解或无限重试豆瓣限流。
- 改变每批 20 条、串行请求和两秒间隔的速率保护。
- 全局删除普通刮削和剧集数获取使用的 `subject_abstract` 降级。
- 校验 Cookie 是否有效、自动登录豆瓣或刷新 Cookie。
- 重命名通用 `api_key` API/数据库字段，或引入通用凭据类型系统。
- 为其他外部 API 提供者统一改造“启用”语义。

## Constraints and Risks

- 这是明确的破坏性配置变更：升级后旧 `secrets.douban_cookie` 不再生效，管理员必须在外部 API 页面重新录入。
- 每次豆瓣请求增加一次数据库查询和解密；本任务优先保证配置即时生效，不引入缓存及失效机制。
- 启动迁移会将旧库的 `api_configs.api_key` 从 `varchar(512)` 扩宽为 `text`，不改列名且保留已有密文。
- Cookie 可能缓解限流，但不保证豆瓣上游一定接受请求。
- 单媒体立即补齐绕过全局队列顺序，但仍受豆瓣上游限流约束；限流时只允许稍后重试，不做自动紧密重试。
- `getDetailRawJSON` 同时服务普通豆瓣详情和剧集数获取；补齐流程必须使用独立的移动详情入口，避免改变这些既有调用的兼容行为。
