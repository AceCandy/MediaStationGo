# 优化媒体详情选轨交互

## Goal

将 Web 媒体详情页改造成更紧凑的 Emby 风格首屏：基础信息优先显示，收藏操作靠近标题，媒体版本与视频、音频、字幕轨道通过下拉框展示，不再纵向铺开全部轨道。

## Background

- 当前详情页纵向展开所有视频、音频和字幕轨道，占用大量首屏空间。
- 用户提供 Emby 详情页作为交互参考，但要求沿用项目现有视觉风格，而不是复制其主题。
- 本会话已将媒体探测从详情首屏阻塞链路拆出；探测期间应只在媒体选择区域显示局部状态。
- 当前 Web 播放器只直放原始文件或 STRM 目标，无法可靠切换容器内嵌音频或字幕轨道。
- 当前详情接口只返回单个媒体版本；同一作品的可靠版本关联来自共享 `MetadataID`。

## Requirements

- 标题旁显示收藏按钮，并保留清晰的已收藏和未收藏状态。
- 在标题信息下方提供“版本、视频、音频、字幕”四个紧凑下拉框。
- 版本切换只刷新视频、音频和字幕下拉框展示的数据，不改变标题、收藏、播放、投屏或管理操作所绑定的当前 URL 媒体。
- 视频、音频和字幕下拉框允许切换当前展示项，但本次选择不传递给播放器。
- 版本列表只返回当前用户可见、通过共享 `MetadataID` 确认属于同一作品的媒体。
- 媒体探测未完成时，选择区域显示“媒体信息探测中”，不得遮挡标题、海报、简介和基础元数据。
- 桌面端优先横向紧凑排列；移动端使用两列或纵向布局，不产生横向溢出。
- 移除当前完整轨道纵向列表，避免同一信息重复展示。
- 保留管理员现有的强制重新探测功能。
- 复用项目现有原生 `<select className="input-base">`，不新增组件依赖。

## Out of Scope

- 不让任何下拉选择影响 Web 播放器、外部播放器、投屏或流接口。
- 不新增转码、HLS/DASH、MSE 或容器内嵌轨道切换能力；播放器选轨后续单独重做。
- 不使用标题、文件名或外部 ID 的启发式规则扩展详情版本列表。
- 不扩大现有 `MediaView` 详情范围；尚未关联共享元数据的扫描中媒体继续沿用现有不可见行为。
- 不复制 Emby 的暗色主题、背景布局或其他无关操作按钮。

## Acceptance Criteria

- [x] 打开详情页时，标题、海报和简介不等待媒体探测即可显示。
- [x] 收藏按钮位于标题旁，可切换并立即反映状态。
- [x] 详情首屏显示版本、视频、音频、字幕四个原生选择器；无可选项时显示明确的不可用状态。
- [x] 选择另一个版本后，视频、音频和字幕选择器只展示该版本的轨道；标题、收藏和操作区仍属于 URL 中的媒体。
- [x] 切换视频、音频或字幕选择只改变控件当前显示项；播放、外部播放器和投屏目标不随之改变。
- [x] 不可见版本不会出现在响应中；尚未进入 `MediaView` 的媒体继续沿用现有详情行为。
- [x] 探测中和探测失败只影响媒体选择区域，快速切换版本不会被旧请求结果覆盖。
- [x] 390px、768px 和桌面宽度下无水平溢出，键盘可操作各选择器和收藏按钮。
- [x] 相关后端定向测试、前端 lint、生产构建和 `git diff --check` 通过。

- `internal/repository/media_view_repository.go:131-143` 已提供按 `MetadataID` 和可见性过滤查询版本的 `FindByMetadataID`。
- `internal/service/media_listing.go:91-105` 的详情查询只返回一个媒体及其已探测轨道。
- `web/src/pages/useMediaDetailPageState.ts:35-75` 已将首次探测拆成局部异步状态，可继续复用。
- `web/src/pages/PlayerPage.tsx:50-67`、`internal/handler/media.go:310-329` 和 `internal/service/stream_file.go:22-43` 表明当前播放链路没有选轨能力。
- `web/src/pages/SettingsRow.tsx:64-70` 与 `web/src/index.css:326-334` 提供现成的原生选择器和统一样式。
