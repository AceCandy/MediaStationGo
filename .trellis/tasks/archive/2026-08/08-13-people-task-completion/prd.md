# 补齐人物翻译与人员补齐任务入口

## Goal

让管理员能在统一任务中心观察全局人物补齐与翻译的实际执行，并能从任务中心触发全局缺失数据补齐。

## Background

- 人物信息回填目前按媒体库执行，查询条件和入口都不是全局语义。
- 人物翻译是服务生命周期 worker；启动、人物数据写入和十分钟轮询会唤醒它，但实际翻译批次没有创建任务执行记录。
- 统一任务执行记录是展示摘要，不作为业务断点；详细过程继续写每个任务每天一个日志文件。
- 后台批次审计确认扫描、整理、探测、刮削、目录补水和回收站清理已经接入。自动 STRM 生成和本地探测队列是扫描内部阶段，沿用外层扫描任务，不重复生成执行记录。

## Requirements

1. 人物信息补齐按全局 TMDB metadata 对象扫描，只处理没有人物关系的对象；不接收媒体库范围，也不保存业务完成断点。
2. 人物翻译仅在配置与 AI 可用、且确实存在待处理人物或角色时创建一条事件触发的任务执行。
2. 同一次 worker pass 的缓存应用、AI 翻译和写回归入同一条执行记录；成功、失败和服务关闭中断使用现有任务状态语义。
3. 空轮询、功能关闭或 AI 不可用时不得创建任务执行记录。
4. 任务摘要和日志应包含足够的处理指标与阶段信息，不在数据库中存储逐项详情。
5. 任务中心提供全局人物补齐触发操作，不要求选择媒体库；触发后按缺失状态持续处理。
6. 单个 TMDB 对象手动重新刮削时，metadata 与人物信息在同一请求内同步完成，不依赖全局补齐队列。
7. 操作成功后任务列表按现有轮询机制出现新记录；启动失败应向管理员显示错误。
8. 本次不为扫描内部子阶段创建重复任务，不改动翻译业务筛选、缓存或重试策略。

## Acceptance Criteria

- [x] 有待翻译项时，任务中心出现“人物翻译”事件任务，并最终进入完成、失败或中断状态。
- [x] 无待翻译项、翻译关闭或 AI 不可用时，不产生空任务记录。
- [x] 翻译任务日志可通过现有任务日志入口读取，指标反映待处理和已应用结果。
- [x] 管理员能在任务中心触发全局人物信息补齐，不出现媒体库选择控件。
- [x] 触发按钮提交期间禁用；API 错误有可见反馈；重复点击不会由同一次前端提交产生多个请求。
- [x] 单个 TMDB 对象重刮削的 metadata 与人物信息同步完成。
- [x] 媒体库详情页原有回填入口保持可用。
- [x] 后端相关测试、`go vet ./...`、前端 lint/build 和 `git diff --check` 通过。

## Out of Scope

- 手动触发人物翻译；翻译仍由现有 worker 的启动、事件和定时唤醒驱动。
- 将常驻 watcher、scheduler loop 或扫描内部阶段单独任务化。

## Technical Note

- 现有媒体库详情页回填入口可保留为兼容入口，但后端语义统一为全局缺失补齐。
