# 修正媒体增量扫描与硬删除

## Goal

让本地媒体库扫描只处理真实发生变化的文件，并将媒体删除统一为不可恢复的硬删除，避免 `.strm` 重扫反复改写媒体字段、更新时间及探测数据。

## Requirements

- 持久化本地媒体文件的文件大小和纳秒级修改时间（mtime）。
- 扫描时以“文件大小 + 纳秒级 mtime”共同判断文件是否变化；两者一致时跳过，不执行媒体 Upsert，也不重新探测 `.strm` 目标。
- 新路径新增媒体；已存在且文件指纹变化时更新媒体；扫描确认路径消失时硬删除媒体。
- 移除媒体回收站能力，不再提供软删除、恢复或回收站清理流程。
- 数据库迁移时永久删除当前所有已软删除的媒体记录，不恢复到媒体库。
- 媒体删除统一为硬删除，包括扫描清理、后台手动删除、重复项清理、整理流程清理及按库/根目录删除。
- 媒体硬删除保留共享元数据、播放历史、播放事件、收藏、播放列表项和现有 STRM 记录；`media_probe_metadata` 继续按现有外键级联删除。
- 兼容已有媒体数据：升级后尚无持久化 mtime 的记录允许执行一次更新以建立文件指纹，后续未变化扫描必须跳过。
- 本次保留 `media.deleted_at` 兼容列；业务不再产生非空删除时间，物理删列延期处理。

## Acceptance Criteria

- [ ] 已有 `.strm` 的大小和 mtime 未变化时，重复扫描计入跳过，`media.updated_at` 不变，且不触发目标探测。
- [ ] 扫描结束后的自动 STRM 生成跳过源文件本身就是 `.strm` 的媒体，不生成嵌套 STRM，也不改写源文件 mtime。
- [ ] `.strm` 内容变化并导致大小或 mtime 变化时，扫描更新其目标及必要媒体字段，并刷新持久化文件指纹。
- [ ] 普通本地视频遵循相同的大小 + mtime 增量判断。
- [ ] 新文件只新增一次；文件消失后对应媒体行被物理删除，不进入回收站。
- [ ] 媒体硬删除时，`media_probe_metadata` 按外键级联删除；共享元数据、播放历史、播放事件、收藏、播放列表项和现有 STRM 记录保持不变。
- [ ] 回收站相关后端接口、服务入口和前端入口被移除，不再暴露恢复或清空操作。
- [ ] 升级前已有媒体完成一次指纹补录后，再次无变化扫描不写媒体行。
- [ ] 迁移永久删除已有 `deleted_at IS NOT NULL` 的媒体；重复执行迁移安全无副作用。

## Confirmed Facts

- 当前 `.strm` 被排除在 unchanged 快速路径之外，每次扫描都会 Upsert。
- 当前媒体扫描删除采用 GORM 软删除；永久删除才会级联清理 `media_probe_metadata`。
- 播放历史、播放事件、收藏、播放列表项和 STRM 记录中的 `media_id` 没有指向媒体表的外键。
- `Media` 当前与约 30 类模型共享含 `DeletedAt` 的 `Base`，项目存在 300 多处 `Base` 结构体初始化。物理删除 `media.deleted_at` 需要拆分基础模型并产生大面积兼容修改；保留永远为 NULL 的兼容列则不影响统一硬删除语义。
- 当前回收站包含后端服务与路由、前端页面与 API、删除入口文案以及定时清理任务，均属于移除范围。
- 现有扫描可直接从 `os.FileInfo` 取得纳秒级 mtime；媒体快照和模型尚未持久化该字段。
- `media.size_bytes` 对本地 `.strm` 表示可播放目标大小，不能作为 `.strm` 边车文件指纹；扫描指纹需要独立保存边车文件大小和 mtime。

## Out of Scope

- 物理删除 `media.deleted_at` 兼容列及拆分共享 `Base`。
- 根据 `.strm` 目标内容、目标文件时间或远程响应判断变化；本次只使用本地 `.strm` 文件自身的大小与 mtime。
- 删除磁盘上的媒体文件、NFO、图片或 `.strm` 文件。
