# 精简事件触发任务日志

## Goal

减少高频事件触发任务的定义日志噪声：不再为每次执行记录没有信息增量的“开始”和“结束”生命周期行，同时保留可用于判断实际处理结果的业务明细与失败原因。

## Background

- `TaskTrackerService.startTriggered` 当前无条件追加 `🔻 <开始消息>`（`internal/service/task_tracker.go:160-184`）。
- `TaskTrackerService.finish` 当前无条件追加 `🔺 <结束消息>`，失败时另有 `❌ <错误>`，完成明细在此之前追加（`internal/service/task_tracker.go:313-350`）。
- 当前事件触发任务包括发现目录刮削、媒体入库刮削、人物信息补齐、人物翻译和媒体库变更监听；它们仍需保留任务执行记录、状态、指标、业务明细和错误信息。

## Requirements

- 当任务的 `Trigger` 为 `TaskTriggerEvent` 时，不向任务定义日志追加开始生命周期行和结束生命周期行。
- 事件触发任务的 `Update` 进度日志、`Details` 业务明细以及失败错误日志保持现有行为。
- 事件触发任务仍正常创建、更新和完成任务执行记录，任务中心中的状态、消息、指标和实时推送保持现有行为。
- 手动触发和定时触发任务的全部日志行为保持不变。
- 在统一任务日志层实现，不逐个修改事件任务调用方。

## Acceptance Criteria

- [x] 事件触发任务日志不包含 `🔻` 开始行和 `🔺` 结束行。
- [x] 同一事件触发任务的进度、成功、跳过、警告、失败明细和失败原因仍会写入日志。
- [x] 手动及定时触发任务仍写入原有开始和结束生命周期行。
- [x] 任务执行的持久化状态、最终消息、指标和发布行为不受影响。
- [x] 使用聚焦的 Go 单元测试覆盖上述日志差异；不执行全量编译或全量测试。

## Out of Scope

- 不删除或隐藏任务中心中的事件触发任务执行记录。
- 不改变事件触发任务的调度、重试、并发或业务处理逻辑。
- 不清理既有日志文件中的历史生命周期行。

## Technical Notes

- 任务为轻量级、单层行为调整，保持 PRD-only。
- 实现应只控制日志追加，不清空 `TaskUpdate.Message`，避免影响任务状态展示与持久化。
