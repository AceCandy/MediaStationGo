# 优化发现页加载性能

## Goal

降低「发现」页面首次进入、再次进入、手动刷新和单栏翻页时的等待与无效网络开销，使已有内容尽快可浏览，并保持现有栏目、分页和错误回退行为。

## Background

- 当前默认选择 6 个栏目，共渲染 132 张海报；冷启动 `/discover/feed` 约 2091ms、LCP 约 2504ms。
- 页面每次挂载都会生成新的图片版本号，热启动仍产生 126 个图片请求和约 5.68MB 传输；132 张海报全部使用 eager 加载。
- 手动刷新会强制刷新全部图片代理缓存；本次测量最慢图片约 8363ms，等待图片完成约 8504ms，而 React 渲染总耗时约 106ms。
- 单栏翻页会同时重新请求其余 5 个未变化栏目：目标页约 413ms，无效原页批次约 1058ms。
- 默认 feed 的 TMDb 三栏按约 667ms、505ms、499ms 串行执行，构成约 1.67s 的冷请求主链。
- 服务端已保存 6 小时 section 缓存，但正常请求不读取该缓存，仅在上游失败时回退。

## Requirements

- R1：普通进入和再次进入发现页时，海报 URL 不得仅因组件挂载而变化；首屏外海报使用浏览器原生懒加载。
- R2：手动“刷新”只强制获取最新推荐数据，不强制重下 URL 未变化的海报；单张坏图现有自动重试与代理刷新机制保留。
- R3：首次加载与手动刷新仍可按相同页码合并栏目；单栏翻页只请求发生变化的栏目和目标页；新操作应实际取消仍在执行的旧 feed 请求，而非只忽略旧响应。
- R4：普通 feed 请求优先返回现有有效的非空 section 缓存；手动刷新显式绕过正常缓存读取。刷新失败时，仍按现有顺序执行 section 缓存、Provider fallback、错误响应。
- R5：保留同 Provider 串行、不同 Provider 最多两路并行、目录 hydration、artwork warm、栏目顺序、权限、响应结构和逐栏 loading/error 语义。
- R6：采用最小、可回滚的改动，不新增依赖、配置、数据库迁移或通用缓存框架。

## Acceptance Criteria

- [ ] AC1（R1）：再次进入发现页时，相同海报生成相同 URL；初始视口之外的海报不再全部 eager 请求。
- [ ] AC2（R2）：手动刷新会重新请求推荐数据，但 URL 未变化的海报不增加全量 cache-busting 参数；坏图仍最多按现有规则自动重试。
- [ ] AC3（R3）：首次加载仍按页码合并；单栏翻页只产生一个包含目标栏目和目标页的 feed 请求；快速翻页或刷新会 abort 旧请求且不会写入错误状态。
- [ ] AC4（R4）：有效非空 section 缓存命中时不调用 Provider；混合命中/未命中时，未命中栏目仍保持 Provider 顺序与并发限制。
- [ ] AC5（R4-R5）：`refresh=1` 会调用 Provider；调用失败且缓存存在时返回缓存、`stale=true`、正确 `has_next`，且不继续执行 fallback。现有 disabled、错误和响应结构回归测试通过。
- [ ] AC6（R1-R4）：在同一登录态、本地环境与缓存状态下至少采样三次，比较 feed、图片请求数/字节、LCP 与翻页请求数的中位数；结果不劣于基线。
- [ ] AC7（R6）：后端定向测试、Web lint/build、`git diff --check` 和独立复核通过，无临时浏览器产物或敏感信息进入工作树。

## Key Decisions

- 复用现有 6 小时 section 缓存，不引入新的缓存层或可配置 TTL。
- 手动刷新绕过推荐数据缓存，但不绕过全部海报缓存；同 URL 海报内容更新依赖现有缓存生命周期，坏图仍可主动重试。
- 保留现有 Provider 并发限制，不用提高外部 API 并发换取速度。

## Out of Scope

- Provider 客户端、超时、并发上限和响应协议重构。
- catalog hydration 入队、localStorage 格式或全局图片代理架构调整。
- 与「发现」页无关的页面优化。

## Risks and Deferred Items

- 将海报恢复为 lazy 后，必须通过真实滚动确认进入视口的海报能正常加载；历史曾为“加载真实海报”改为 eager。
- 第一次服务启动且 section 缓存为空时仍需等待 Provider；本次优化重点是避免重复等待和无效下载，不承诺消除外部网络冷启动。
- 现有 section cache 不保存空结果；空栏目仍会在下次请求重新查询 Provider，本任务不改变该语义。
- 上游在相同 URL 原地替换海报时，手动刷新不会立即强制下载新文件；这是用户已接受的速度与即时图片更新取舍。
