# 补充后台任务详细日志

## Goal

让管理员从任务中心的单次执行日志中直接看懂任务处理了什么对象、得到什么结果，以及为什么跳过或失败，不再只有开始和结束两行。

## Background

- 任务中心已经通过 `GET /api/tasks/:id/log` 展示独立任务日志，前端没有过滤明细。
- `TaskTrackerService` 已支持把 `TaskUpdate.Details` 逐行写为 `[DETAIL]` 日志，因此无需修改日志协议或页面。
- 现有 8 个稳定任务定义中，整理、轨道回填已有业务明细；人物翻译、媒体刮削、发现目录刮削、全库扫描和回收站清理的明细不足。人物补齐已有失败明细，但成功和跳过结果不够明确。

## Requirements

- 所有稳定后台任务都必须在已有起止日志之外，记录适合其业务粒度的处理明细。
- 人物翻译记录对象类型、原文和最终译文，并区分缓存命中、AI 翻译、无有效译文和失败。
- 人物补齐记录 TMDB 对象、补齐成功、跳过及失败结果。
- 已入库媒体刮削记录媒体对象、TMDB 匹配结果或未匹配/失败原因。
- 发现目录刮削记录 provider、媒体类型、外部 ID、标题和成功/重试失败结果。
- 媒体库扫描按媒体库记录新增、更新、移除、跳过及错误汇总。
- 回收站清理记录清理条件和删除数量。
- 整理和轨道回填保留现有明细机制，不重复建立另一套日志抽象。
- 继续使用 `TaskUpdate.Details` 和现有任务日志文件，不改变 API、数据库模型或前端展示。
- 不记录 API 密钥、认证信息、AI 请求正文、原始 provider 响应或其他凭据；错误沿用现有安全化处理。
- 单次批量任务的明细必须有合理上限或按批次输出，避免任务日志无界增长。

## Acceptance Criteria

- [x] 人物翻译执行日志包含可辨认的“原文 -> 译文”结果；缓存命中和 AI 结果均可区分，缺失/无效结果可见。
- [x] 人物补齐日志能看到处理的 TMDB ID 及成功、跳过或失败结果。
- [x] 已入库媒体刮削日志能看到媒体标题/ID、匹配的 TMDB ID（存在时）以及 matched、no_match 或 error 结果。
- [x] 发现目录刮削日志能看到 provider、类型、外部 ID、标题（成功时）和失败重试原因。
- [x] 全库扫描日志按库输出扫描计数或错误，回收站清理日志输出删除数量和清理截止条件。
- [x] 整理与轨道回填现有明细仍正常写入，任务定义与日志读取 API 保持兼容。
- [x] 对新增明细的格式、关键分支和日志写入行为有聚焦测试，相关 Go 测试通过。
- [x] 代码与日志中不新增密钥、请求正文或 provider 原始响应泄露。

## Out of Scope

- 不修改任务中心 UI、轮询频率、日志文件格式、保留策略或下载功能。
- 不回填历史任务的明细。
- 不新增通用日志 DSL、事件类型或数据库字段。
