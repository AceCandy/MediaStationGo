# 优化媒体库扫描重复读取与红果索引刷新

## Goal

减少大库新增/更新扫描的重复读取和索引请求，同时保留现有媒体内容、绑定、安全校验和失败恢复行为。用户已在诊断及两项方案说明后明确批准实施。

## Requirements

- 普通/红果全库/根扫描每批最多 100 个需处理文件复用识别词配置与解析结果，未变文件不触发配置读取。
- 红果扫描按批次合并作品及合集搜索刷新，保留每文件事务、事务内旧身份捕获和来源隔离。
- 直接单文件入库保持即时刷新；部分失败和取消不能遗漏已提交写入的刷新或索引失效。
- 不改变扫描并发、数据库配置、媒体绑定策略，不部署、不重启或复扫生产库。

## Acceptance Criteria

- [x] 测试证明批内识别词读取次数有界，批次切换可见新配置，未变重扫零识别词读取。
- [x] 测试证明多集同作品按批合并搜索写入，新增/更新及根末尾不足一批均刷新。
- [x] 覆盖回滚、部分提交、取消、旧新作品/合集、直接写入；既有并发路径回归通过。
- [x] 隔离 PostgreSQL 定向回归、竞争检查与静态检查通过；独立复核完成。

## Background

现场扫描访问 895858 个文件，新增/更新 52663 个，耗时 3168 秒。当前每次媒体构造会读取识别词设置，每次红果入库会同步刷新作品索引。上述计数为现场任务记录；各阶段占比和部署后的提速幅度尚未实测。

## NFO 扩展：已批准

用户调研后批准先实施低风险的规则复用和冗余查询削减。共享 NFO/图片缓存、持久化侧车快照和并发改造留待后续评估。

- NFO 全库/单根扫描每 100 次媒体构造复用现有识别规则；单文件事件仍读取当前规则。
- NFO 扫描不加载该分支未使用的普通媒体全库快照。
- 新增/更新统计来自入库事务结果，不再执行事务外的路径查询；旧仓储调用接口保持兼容。
- 保留每文件事务、路径锁、来源/库校验、NFO/图片读取、未变判断及资料保留行为。
- [x] 操作计数测试覆盖跨批次首扫、未变重扫、单根扫描及单文件事件。
- [x] 新增/更新/跳过统计、失败回滚、并发首次入库及已有 NFO 回归通过。

## NFO 增量扫描与共享读取：已批准

- 同次扫描有界复用已解析的共享 NFO、图片尺寸与准备好的受控图片；复用前检查当前文件版本和图片路径许可，资产返回独立副本。
- 成功入库时保存版本化依赖快照；完全未变重扫提前跳过 XML、图片字节处理和写事务。
- 检查视频身份、ctime、mtime、size、候选目录、已访问的存在文件和 XML 图片引用；NFO/图片更新、新候选、删除恢复、替换及受控图片丢失不能被跳过。
- 旧记录、错误读取、读取期间变化以及无法可靠识别文件版本的平台回退完整读取；保持旧资料与手工编辑的保留行为。
- [x] 共享读取与资产副本、旧记录升级及完全未变重扫通过。
- [x] NFO/图片/候选/文件身份变化、失败恢复、取消、来源隔离通过。
- [x] 隔离 PostgreSQL race 回归、vet、格式与独立复核通过。
