# Design

- `localMediaWriteBatch` 懒加载识别词配置与解析规则，按最多 100 次媒体构造重新读取；builder 显式接受现有 batch。watcher 等非批次 builder 保留原路径。
- `MediaRepository.WithBatchedHongGuoSearch(limit)` 返回独立仓库副本与收尾函数，仅副本的红果 Upsert 合并刷新。共享原 HongGuo owner 和索引锁，不设置全局开关。
- 原 PrepareMediaSearchRefresh 拆分捕获与刷新实现：事务内行锁后照常捕获旧绑定和来源作品；只有事务成功才加入 batch；每 100 次成功提交或显式收尾合并作品、旧合集和当前合集。
- 索引刷新继续在原锁内读取当前数据库投影，保持并发顺序。捕获/刷新失败和取消沿用失效回退；回滚不产生候选。批次不负责重试业务写入。
- scanner 的新增缓冲及即时更新均使用副本；root 的现有 Flush 即使无新增缓存也刷新已提交更新。保留错误计数、探测失效和已有元数据日志。
- 无 schema/API/依赖变化。回滚代码恢复原逐文件行为。允许批内短暂搜索可见性延迟，保留原权限数据库复核和恢复重建规则。

## NFO 扩展

- `ingestFile` 将现有 batch 传给 NFO builder；NFO 仍立即入库，不进入普通新增缓冲。规则按构造次数刷新，根末尾沿用 Flush 重置。
- 全库及单根入口仅为普通/HongGuo 类型读取原媒体快照；NFO 不使用普通未变判断，因此不读取该快照。
- `NFORepository.IngestWithResult` 保留现有事务实现，并返回 changed/added 两项成功提交结果；added 在路径锁后的已有行查询中确定。`Ingest` 包装调用它，保留旧签名。
- scanner 使用事务返回的 added 做计数，删除仅为计数进行的事务外 FindByPath。事务内行锁、来源/库检查及共享 upsert 冲突重验保持原流程。
- 文件和侧车仍逐次读取；不会引入仅依赖视频 size/mtime 的跳过规则。无需 schema 迁移。

## NFO 增量扫描与共享读取

- 现有本地 NFO 与图片选择函数使用具体读取器；普通库以 nil 读取器保持原行为。读取器记录实际访问依赖，不改变选择顺序。缺失候选由读取前的最近存在父目录版本覆盖；无法安全覆盖的断链符号链接回退完整读取。
- Linux 文件版本包含 device/inode、ctime、mtime、size 和 mode。其他平台暂不保存可用于跳过的快照。依赖从首次检查到完成必须稳定。
- 扫描 batch 内缓存成功解析的 NFO、图片尺寸与已准备图片；每 100 个文件和根末尾重置。每次命中检查当前版本，资产用值副本避免事务填充 ID/时间污染内容 fingerprint。
- NFOMediaBinding 增加 nullable text ScanInputs，json 隐藏，不参与原 fingerprint。快照包括构造上下文、依赖文件/目录和本地图片源许可检查；受控资产文件也属于依赖。
- 构造媒体后做一次轻量的路径/来源/库/文件事实/状态/根检查 SELECT，匹配快照才直接统计跳过。新文件/旧快照/变更仍走原逐文件事务及所有归属复核。
- 原内容 fingerprint 未变但依赖快照更新时，只更新 scan_inputs 列，不更改资料或 Updated 计数。成功读取的视频身份变化触发原文件变更处理与探测失效。失败不保存新快照。
- 不预读整库、不批量缓冲 NFO 写入、不做父条目数据库去重、不添加依赖。

- 提前跳过的来源/库归属以轻量 SELECT 时观察到的状态为准；这是无写入的读取结果。并发删除或迁移发生在读取后时，不尝试复活媒体或改写新归属；变更处理路径仍完整锁定并复核。不能为了再次确认只读跳过而恢复每文件写事务。
- 构造上下文仅持久化 SHA-256 摘要，避免快照重复保存 STRM URL 参数。JSON 解析失败清空整个快照，防止部分解析数据被误用。
