# 代理池保存去重

## Goal

管理员反复追加并保存代理数据时，相同代理不会被重复存储或重复使用。

## Background

- 当前 Web 编辑器会为未改动的显示行保留已有 ID，但不会去除重复 URL。
- 当前服务端仅拒绝重复的已有 ID，不会去除规范化后的重复代理地址。
- 代理 URL 加密后入库，因此不依赖数据库唯一索引完成去重。

## Requirements

- PUT 完整替换代理池时，服务端必须使用现有 URL 规范化结果对完整代理 URL 去重。
- 保留输入中第一个出现的代理，静默忽略后续重复项，并保持其他条目的原始顺序。
- 仅当规范化后的完整 URL（包括协议和认证信息）相同时视为重复；同一节点使用不同账号或密码时保留为独立代理。
- 去重必须覆盖保留的已有 ID、新增 URL 和强制替换 URL，不得仅依赖 Web 页面。
- 不得在错误、响应、日志或测试输出中暴露代理认证信息。

## Acceptance Criteria

- [ ] 一次保存两个规范化后相同的代理 URL，响应和数据库中只保留第一个。
- [ ] 已存在的重复条目被再次保存时，仅保留排在最前的条目，后续重复记录被物理删除。
- [ ] 等价输入（例如省略 `http://` 与显式 `http://`）只保留一项。
- [ ] 相同主机端口但认证信息不同的代理仍保留为两项。
- [ ] 原有加密存储、认证信息脱敏、事务替换和顺序保持行为不变。

## Out of Scope

- 不增加数据库字段、唯一索引或迁移。
- 不增加前端去重按钮、重复数量提示或额外配置。
- 不按主机和端口模糊合并不同认证账户。

## Technical Notes

- 去重放在 `ProxyPoolService.replaceLocked` 的共享解析循环，仅由 PUT 保存入口开启；健康清理保持关闭，确保令牌只删除绑定 ID。
- 使用规范化或解密后的 `url.URL.String()` 作为去重键，不引入新依赖或新抽象。
