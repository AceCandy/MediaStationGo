# 豆瓣原图与临时失败重试

## Goal

豆瓣图片始终保存稳定的官方原图 URL；下载时临时使用当前配置的 CDN，并在 CDN 失败时回退官方原域名。临时网络故障恢复后，后续任务能够自动重试，而不是被 6 小时失败缓存持续阻断。

## Background

- 豆瓣部分大图 URL 带有 `imageView2/2/q/80/w/600/h/3000/format/*` 查询串，存在把更宽原图限制到 600 像素的风险。
- 当前样本带参数和不带参数均返回 `1080×1480`、`image/webp`，但这不能保证其他原图不受 `w/600` 约束。
- 2026-09-01 17:41:30 首次失败是 `Could not resolve host: db-pic.acecandy.cn`；随后相同 URL 命中 6 小时 `.fail.direct` 标记，没有再次发起网络请求。
- 当前实现会为除请求构造失败外的所有图片抓取错误写入负缓存，包括 DNS、TLS、超时和 5xx。
- 当前 `DoubanProvider.ResolveArtworkURL` 会在返回图片 URL 前直接替换为配置 CDN，导致新候选的 `source_url` 持久化 CDN 域名；CDN 变更后无法从该字段恢复准确的官方原域名。

## Requirements

- 对已知 `imageView2/...` 豆瓣图片处理查询串删除整个查询串；稳定 URL 保留 `/view/photo/l/public/` 官方大图路径和原始扩展名，只有临时 CDN 下载 URL 投影为 WebP。
- 未知查询参数必须保留，避免破坏非标准或带签名的图片 URL。
- 豆瓣搜索、发现、详情和历史修复在缓存、响应及数据库 `source_url` 中保留规范化后的官方原图 URL，不持久化配置 CDN URL。
- `ImageProxy` 下载官方豆瓣图片时，根据当前 Douban 配置临时生成 CDN WebP URL；先请求 CDN，失败后立即请求原始官方 URL。CDN 配置变化不得要求修改数据库 URL。
- CDN 下载成功后按官方原图 URL 作为稳定缓存键；CDN 和官方源都失败时才向调用方返回失败。
- 图片负缓存只记录明确的 HTTP 404；DNS、TLS、超时、429、5xx、空响应及非图片响应不写负缓存，允许下一次任务重新请求。
- 保留现有正向图片缓存、单次抓取的 default/direct/curl 顺序、超时和任务调度频率。
- 实施后只清理本次已确认 URL 对应的精确 `.fail.direct` 标记，不批量删除其他图片缓存。

## Acceptance Criteria

- [x] 已知 `imageView2/...` 输入经豆瓣图片解析后成为无查询串的官方大图 URL；临时 CDN 下载 URL 使用同一路径的 WebP。
- [x] 未知查询参数保持不变。
- [x] 新增或修复的豆瓣候选保存官方原图 `source_url`，不保存配置 CDN 域名。
- [x] CDN 成功时不请求官方源；CDN 失败时同一次下载回退官方原图并成功写入稳定缓存。
- [x] 修改 CDN 配置后，无需迁移数据库即可让下一次未命中缓存的下载使用新 CDN。
- [x] 连续两次 DNS/网络失败都会访问上游，不产生负缓存短路。
- [x] 连续两次 HTTP 404 只访问一次上游，第二次命中负缓存。
- [x] 现有豆瓣图片 URL、直连和图片代理相关测试通过。
- [x] 当前 `p454132922` URL 的精确失败标记被清理，可在下一次任务立即重试。

## Out of Scope

- 删除全部历史失败标记或修改正向图片缓存。
- 在一次图片抓取内新增应用层重试、并发或新的网络客户端。
- 调整豆瓣补齐任务的批次、限速或调度周期。
- 批量迁移已经保存为 CDN `source_url`、但本地图片文件仍正常的历史候选；如需迁移，另行提供先预览后更新的手动 SQL。
