# 技术设计

## 边界

- `DoubanProvider` 只负责把豆瓣图片规范为稳定的官方大图 URL，不再把配置 CDN 写入返回值。
- `ImageProxy` 负责下载时的临时 CDN 投影、官方源回退、正向缓存和负缓存判断。
- 数据库候选 `source_url`、发现缓存和接口结果都保留官方 URL；不修改 API、数据库结构或前端协议。

## URL 与下载流程

```text
豆瓣原始 URL
  → 规范为 /view/photo/l/public/
  → 删除已知 imageView2 图片处理查询串
  → 作为稳定 URL 返回、缓存和持久化
  → ImageProxy 未命中正向缓存
      → 按当前 Douban 配置临时生成 CDN WebP URL
      → CDN 成功：以稳定官方 URL 为缓存键保存
      → CDN 失败：请求稳定官方 URL
```

未知查询参数不参与清理。未启用 CDN、配置不可用或投影结果与官方 URL 相同时，只请求官方 URL。

## 失败与缓存

- CDN 404 只表示镜像缺图，仍回退官方 URL。
- 官方 URL 404 是确定性缺图，写入现有负缓存。
- HTTP 客户端收到 404 后不再继续同 URL 的 direct/curl 尝试，保留可识别的 404 错误类型。
- DNS、TLS、超时、429、5xx、空响应和非图片响应不写负缓存；同一次 URL 候选链结束后返回错误，下次任务可重试。
- 当前已确认 URL 的精确 `.fail.direct` 标记在实施后单独删除，不清理其他缓存。

## 兼容性与回滚

- 不迁移历史健康候选；缺文件或小图进入现有修复流程后自然写回官方 URL。
- 现有本地图片资产及正向缓存无需变化。
- 回滚代码不会破坏已下载资产；删除精确失败标记只会允许重新请求。

## 取舍

- 不在各下载调用方保存主 URL 和备用 URL：共享代理已经是所有远程图片下载入口，集中处理能覆盖展示、预热和本地化。
- 不新增重试器或 CDN 抽象：只有一个当前 Douban CDN 和一个官方回退，使用现有配置与标准库 URL 处理即可。
