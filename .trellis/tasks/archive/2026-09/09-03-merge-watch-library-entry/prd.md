# 合并观看空间媒体库入口

## Goal

将媒体库浏览与管理集中到“观看空间 > 媒体库”，减少重复入口，同时保留管理员现有的完整媒体库管理能力。

## Background

- 当前“观看空间 > 媒体库”使用内容货架展示，并通过“管理媒体库”按钮跳转到 `/admin/media`。
- 当前“文件空间 > 媒体库管理”使用媒体库卡片和管理弹窗。
- `/library/:id` 已是单个媒体库的全部媒体页面。
- 现有管理 Hook、创建弹窗、设置弹窗及 API 已覆盖新建媒体库、封面、路径来源、路径名称、启用/禁用和删除操作，无需新增后端接口。

## Requirements

- R1：默认媒体库视图改为类似现有“媒体库管理”的卡片网格，不再展示每个媒体库的最新内容货架。
- R2：媒体库卡片分为两个明确的交互区域：
  - 上半部分点击后进入 `/library/{媒体库 ID}`，展示该媒体库全部媒体。
  - 下半部分的设置箭头仅对管理员显示；点击后留在当前页面并打开该媒体库的设置弹窗。
- R3：设置弹窗复用现有媒体库管理弹窗，保留其中全部操作项，包括路径编辑、路径名称、路径启用/禁用、路径删除、添加来源、编辑封面和删除媒体库。
- R4：管理员仍可在合并后的媒体库页面新建媒体库，并复用现有完整新建表单。
- R5：普通用户仍可浏览媒体库和进入全部媒体页面，但不能看到或触发新建、设置等管理员操作。
- R6：从“文件空间”导航中移除“媒体库管理”Tab。
- R7：保留 `/admin/media` 路由和旧 `/admin?tab=library` 兼容跳转，避免已有书签或外部链接失效。
- R8：保留“海报视图”及其 `/libraries?view=poster` URL 行为，不改变后端、API 或媒体展示详情页。

## Acceptance Criteria

- [x] AC1：进入 `/libraries` 时，每个可见媒体库以管理风格卡片展示，不再发起仅用于首页内容货架的逐库媒体预览加载。
- [x] AC2：点击卡片上半部分可导航到对应 `/library/{id}`。
- [x] AC3：管理员点击卡片下半部分设置箭头时不跳转，并打开该媒体库的完整现有设置弹窗。
- [x] AC4：管理员可在 `/libraries` 打开现有新建媒体库表单；设置或新建完成后列表正确刷新。
- [x] AC5：普通用户看不到新建按钮和设置箭头，且原有浏览行为可用。
- [x] AC6：“文件空间”导航不再显示“媒体库管理”，但直接访问 `/admin/media` 及旧兼容跳转仍有效。
- [x] AC7：`/libraries?view=poster`、非法 `view` 参数归一化及现有权限控制保持不变。
- [x] AC8：键盘可分别聚焦并触发卡片浏览区和设置按钮，交互区域具有明确的可访问名称。

## Out of Scope

- 不删除 `/admin/media` 页面、路由或相关管理组件。
- 不修改媒体库数据结构、后端接口、扫描/入库逻辑和单库详情页。
- 不新增第三方依赖或前端测试框架。

## Technical Notes

- 路由与导航元数据继续由 `web/src/appRoutes.tsx` 单点维护。
- 优先扩展并复用现有 `AdminLibraryGrid`、`LibraryDetailDialog`、`AdminLibraryCreateDialog` 和 `useAdminLibraryPanel`，不复制管理逻辑。
- 当前 Web 包未配置自动化测试框架；实现后使用 lint、构建、diff 检查及浏览器人工验证。
