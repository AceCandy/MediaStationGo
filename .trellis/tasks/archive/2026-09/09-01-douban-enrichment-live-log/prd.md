# 豆瓣补齐实时输出明细

## Goal

豆瓣电影信息补齐每处理完一条即写入任务日志，让用户无需等待整个批次结束即可看到进度。

## Background

当前任务会先查询最多 20 条候选并串行处理，但逐项结果先暂存在内存，直到 `Finish` 时才一次性写入日志。因此批次运行期间只有启动日志，所有明细在结束时显示为同一时间。

## Requirements

- 保持候选查询、串行处理、游标推进、请求规则和条目间 2 秒等待不变。
- 每个候选处理完成并生成用户可见结果后，立即通过现有任务更新机制写入该候选的明细。
- 批次结束时只写最终汇总和完成状态，不重复写入已经实时输出的逐项明细。
- 暂停、失败、永久失败、跳过、更新、新增海报、降级和仅刷新快照等现有日志语义及指标保持不变。
- 不新增日志抽象，不修改前端。

## Acceptance Criteria

- [x] 批次尚未结束时，已完成候选的明细已经出现在任务日志中。
- [x] 批次完成后，每条候选明细只出现一次。
- [x] 最终汇总、完成/失败状态和现有指标保持正确。
- [x] 现有豆瓣补齐测试通过，并有最小测试覆盖实时写入且不重复的行为。

## Out of Scope

- 调整批次大小、请求并发、2 秒限速或网络超时。
- 修改任务日志页面或任务日志存储格式。
