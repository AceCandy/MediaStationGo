# 统一精简前置查询与缓存

## 记录状态

- 慢请求优化讨论的第 1 项：前置查询精简与缓存复用。
- 用户已确认按第 1 → 2 → 3 项实施；本项先实施和验证，随后进入第 2、3 项。
- 后续候选分页、分集统计分别属于第 2、3 项，不并入本项。

## 目标

减少重复读取用户、库基础信息与可见范围的数据库往返。梳理整个项目中的同类调用，按实际数据需求统一复用读取方式，保持权限、认证与目录功能正确。

## 实施前已确认事实

- `internal/handler/active_user.go:50`：Emby 认证通过 `User.FindByID` 实时检查账户状态、有效期和令牌版本。
- `internal/repository/library_repository.go:64`：`Library.FindByID` 查询库之前检查目录表，存在时预加载 Roots；`List`（同文件第 51 行）也采用这个方式。`hasLibraryRootsTable`（第 165 行）每次调用数据库表存在性检查。
- `internal/service/emby_hongguo.go:278`：红果列表入口借助完整库读取确定 ID 和类型，随后进入作品查询。
- `internal/service/emby_visibility.go:52` 与 `internal/service/emby_compat.go:106`：Emby 可见范围已有按用户 ID 的 30 秒内存缓存；目前该缓存依靠过期更新，尚未发现配置修改时主动失效的入口。
- `internal/service/visibility.go:44`：可见范围计算读取全局开关、用户和播放配置；其中用户可能与同一请求中认证已经读取的用户重复。隐藏库计算还会按条件增加查询。
- 对正常的库存在、目录表存在、权限缓存命中路径，代码基线为 4 条前置查询：用户、目录表存在性、库、库目录。权限缓存未命中且无需隐藏库计算时另有 3 条；这不是从历史慢日志还原出的实际逐请求计数。
- 既有 `FindCoverURL`（`internal/repository/library_repository.go:83`）已经展示按需读取单个字段、避免预加载目录的做法。

## 需求与边界

1. 全项目审查同类入口。Emby、Web 和后台任务中使用库读取及可见范围计算的位置都进入调用方清单；逐项记录实际消费字段、是否依赖 Roots、是否要求事务内或写后立即读到最新数据，再决定迁移方式。
2. 仅需要库基础信息的入口不进行无关的目录表检查和 Roots 预加载。需要目录的扫描、目录管理等调用保留完整数据契约；不得全局改变原有方法语义后机械替换所有调用。
3. 同一请求内复用已经校验过的用户数据，减少重复读取。必须区分认证用户与目标用户，保留管理员代查其他用户的行为；不能把认证用户的权限套用到目标用户。
4. 库基础信息可以共享缓存；权限结果按用户及其实际权限上下文隔离，复用已有缓存能力。库缓存命中不能代替调用方的权限校验。
5. 缓存须覆盖相关修改与删除的失效路径。权限收紧、全局可见性设置及默认播放配置变化不能因新增缓存扩大旧结果的生效窗口；设计时核实实际部署和更新入口，明确失效传播边界。
6. 用户禁用、过期和令牌版本继续实时校验，不新增跨请求的认证结果缓存。缓存读取失败或未命中仍须保留原有错误、缺失记录和访问控制行为。
7. 不以所有入口只有一条 SQL 为统一要求。优先去掉无关查询和请求内重复读取，再按证据评估合并；不新增通用查询框架、依赖或独立缓存基础设施。

## 目标验收

- [x] 所有同类调用均有去向说明：迁移到基础读取、保留完整读取或保留强实时读取；覆盖依据是数据需求，不是某个客户端名称。
- [x] 红果列表前置路径在权限缓存命中、库基础缓存未命中时为 2 条查询：实时用户校验和库基础读取；两类缓存均命中时只保留 1 条用户校验。只统计前置部分，不包含作品查询和请求日志写入。
- [x] 原来不需要额外查询的调用不因统一方式增加数据库往返；其他入口按各自基线验证，不套用红果路径的绝对条数。
- [x] 轻量路径不查询目录表存在性或预加载 Roots；需要目录的入口仍获得完整正确的目录数据。
- [x] 同一请求的重复用户读取被消除；不同目标用户及不同用户之间的权限结果没有混用。
- [x] 验证库修改、删除、权限变化、缓存未命中与过期；并发的旧读取不会在失效后重新回填过期结果。
- [x] 禁用用户、过期账户、撤销令牌及越权请求仍按原契约被拒绝。
- [ ] 保持各接口字段、状态码、可见性与错误处理契约；以代表调用的 SQL 次数、实际耗时及权限回归共同验收，不能仅以条数减少宣称提速。

本地权限与响应回归、SQL 次数和并发检查已通过；最后一项的生产请求耗时尚未复测，多实例即时失效传播也未验证。不将 SQL 条数减少等同端到端提速。
