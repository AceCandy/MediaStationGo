# 优化人物翻译与豆瓣补全候选查询

## Goal

减少后台任务的无效全量读取和重复快照计算，保持现有业务语义

## Requirements

- 人物翻译过滤无效候选并分页，保留 U+4E00–U+9FFF 中文判断、软删除、缓存语言/版本/上下文隔离、人物优先、1000 组上限及全部同组角色目标。
- 豆瓣减少快照重复访问，保留首次获取、24 小时过期、不完整判断、降级排除、唯一标识和有效海报资产规则。
- 不更改调度、AI 请求、日志阈值、Emby、搜索预热或其它未提交改动；不新增缓存、状态字段和依赖，不直接修改实际库结构，不提交或重启用户服务。

## Acceptance Criteria

- [x] 经用户追加批准，角色部分索引接入启动迁移；重复迁移幂等，通用参数化执行计划能够命中索引。仅测试库执行，实际库等待用户重启。

- [ ] PostgreSQL 回归覆盖中文边界、负缓存、跨页候选/角色组、1000 组上限和取消/错误传播。
- [ ] 豆瓣回归覆盖快照缺失/近期/过期/完整/降级、多标识、海报缺失和分页，结果保持一致。
- [ ] dbx 只读对比结果及执行计划的耗时、扫描行数与循环次数。
- [ ] 独立复核任务 diff，说明已验证与未验证项，清理本次临时服务及产物。
