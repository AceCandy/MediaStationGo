# 代理池不可用代理检测与清理：实施计划

1. 后端检测分类
   - 在 `ProxyPoolService` 内增加已保存代理快照和受控并发检测。
   - 复用现有 transport、URL 解密和敏感信息边界。
   - 验证：服务测试覆盖成功、超时、连接错误、407、400、unexpected EOF、限流/上游不确定和直连基准失败。

2. 后端原子清理与 API
   - 增加检测和按 ID 清理的管理员路由、handler 与响应类型。
   - 清理只删除检测返回且当前仍存在的 ID，重排剩余位置并刷新运行时客户端。
   - 验证：handler/service 测试覆盖取消前无写入、未知/重复 ID、安全响应、并发保存后的精确删除和凭据不泄漏。

3. Web 管理交互
   - 扩展 `api_configs.ts` 类型和方法。
   - 在现有 `ProxyPoolPanel` 增加检测按钮、忙碌态、汇总提示和 `confirmAction` 危险确认。
   - 清理成功后使用服务端返回项刷新 textarea；未保存编辑不参与检测且不得被静默覆盖。
   - 验证：聚焦前端测试或最小组件检查覆盖无节点、检测失败、无不可用节点、取消、确认成功和重复点击保护。

4. 独立复核与质量门
   - 复核 API/前端字段一致、敏感信息边界、锁范围、请求取消和运行时 generation 刷新。
   - 建议运行聚焦 Go 测试、`go vet`、Web lint/build 与 `git diff --check`；按项目约束，执行编译或测试前先取得用户批准。

## Risk and Rollback Points

- 分类过宽会误删：只有有效 `cleanup_token` 绑定的不可用代理可清理，`inconclusive` 永不删除。
- 长请求可能被反向代理中断：请求 context 取消必须停止检测且不写数据库。
- 检测和保存并发：清理按 ID 精确删除，禁止用旧快照完整覆盖新列表。
- 回滚无需数据库迁移，只撤销新增代码；已删除代理无法自动恢复。
