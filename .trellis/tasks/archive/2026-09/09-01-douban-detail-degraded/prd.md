# 豆瓣详情权限降级

## Goal

豆瓣 movie/tv 完整详情因权限限制不可用时，使用 subject 响应保留可用信息，明确展示降级状态，避免定时任务重复撞击上游，并允许用户在详情页手动恢复完整信息。

## Background

- 当前豆瓣移动详情请求在 `internal/service/douban.go:190` 硬编码使用 `/rexxar/api/v2/movie/{id}`，尚未按电影/电视剧选择路径。
- 同一 Cookie 请求豆瓣电影 `35763827` 时，`/movie/{id}` 返回 HTTP 403、JSON `code=1000`，而 `/subject/{id}` 返回 HTTP 200。
- `/subject` 仅提供标题、图片等精简字段，不能等同于 `/movie` 或 `/tv` 的完整详情。
- 当前数据库已有完整豆瓣快照与旧 `subject_abstract` 快照；降级状态不能仅靠字段缺失推断。
- 当前详情 API 已返回 `douban_snapshot` 与 `douban_status`，前端已有 `missing/partial/complete` 状态展示，但 `partial` 只表示“本地数据不完整”，没有明确的权限降级语义。
- 当前详情页已有管理员专用“补齐豆瓣信息”操作，成功后会重新加载详情；后端入口仅支持电影。用户已确认手动重试继续保持管理员权限。
- `metadata_provider_snapshots` 以 `(metadata_id, provider)` 唯一，适合作为 provider 快照质量状态的持久化位置；项目 AutoMigrate 会同步模型新增列。
- 当前定时豆瓣补齐任务仅处理电影；电视剧对应 canonical `series`，不为 season/episode 建立豆瓣详情快照。

## Requirements

- 已知电影使用 `/movie/{id}`，已知电视剧使用 `/tv/{id}`。
- `/movie` 或 `/tv` 返回 HTTP 403，或有效 JSON 明确返回 `code=1000` 时，请求 `/subject/{id}` 作为降级数据源。
- `/subject` 成功后保存其原始响应，并显式持久化“已降级”状态，不把精简响应标记为完整详情。
- 详情页展示豆瓣数据的完整/降级状态；降级状态应有清晰提示和手动重新获取完整信息的操作。
- 定时豆瓣补齐任务跳过已降级条目，避免每轮重复请求已知无权限的完整接口。
- 手动重新处理继续仅允许管理员操作，并必须绕过定时跳过规则：完整接口成功后清除降级状态；再次无权限时保持降级状态。
- 404 保持“条目不存在”语义；429、5xx、网络错误保持可重试异常语义，不因这些错误进入降级状态。
- subject 请求本身失败时不写入降级快照，继续使用其实际的不存在或临时异常语义。
- subject 的空缺字段不得清空已有元数据；降级数据不得覆盖已有非空人工或更高质量元数据。
- Cookie、响应正文中的敏感内容不得进入日志或前端状态说明。

## Acceptance Criteria

- [ ] 电影完整接口发生 403 或 JSON `code=1000` 时，系统请求 `/subject/{id}` 并保存降级快照。
- [ ] 电视剧完整接口发生相同权限错误时，系统以同样规则回退 `/subject/{id}`。
- [ ] 非权限错误不会触发 subject 降级，现有 404 与临时异常行为保持不变。
- [ ] 详情 API 能返回豆瓣快照是否降级，详情页能展示降级提示。
- [ ] 降级条目不再被定时补齐任务选中。
- [ ] 详情页手动重试能请求正确的 movie/tv 完整接口；成功后状态变为完整，仍无权限时保持降级。
- [ ] 手动重试仍受现有管理员权限保护；普通用户不能触发上游豆瓣请求。
- [ ] subject 缺失字段不会清空或覆盖现有非空字段。
- [ ] 定时任务首次降级成功后继续处理本批并推进游标，不再将该条目作为临时异常暂停整批。
- [ ] 聚焦测试覆盖 movie 权限降级、tv 权限降级、非权限错误不降级、subject 失败不落库、定时跳过和手动恢复。

## Out of Scope

- 不通过 subject 补造其未返回的简介、原名、语言、国家、类型或上映日期。
- 不新增第三方豆瓣服务、API Key 或 HTML 抓取方案。
- 不自动周期性重试已降级条目；恢复完整信息由详情页手动操作触发。
- 不为 season/episode 单独请求豆瓣详情；电视剧只处理 canonical series。
- 不回填或迁移历史快照的降级标记。
