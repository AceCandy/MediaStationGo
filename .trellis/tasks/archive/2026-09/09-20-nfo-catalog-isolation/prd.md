# 独立 NFO 媒体库体系

## Goal

非常规电影/剧集仅凭本地文件和 NFO 完成入库、展示、播放，不与普通 TMDB/豆瓣资料或红果资料合并，不触发远程资料请求。

## Requirements

- 用户已在多轮讨论后批准实施，并要求独立后台任务在任务中心分开。
- 公共 media/探测/播放能力复用；NFO 资料及用户状态独立保存。
- 内部身份不依赖外部 ID。不同路径的重复作品允许存在，同一路径重复扫描幂等。
- 电影多版本只按明确的同目录、目录名前缀及版本后缀规则分组；不按标题或 provider ID 自动合并。
- 剧集保留剧/季/集层级，文件有明确季集号才归组。
- 扫描同步读取本地 NFO/图片，文件、资料、关系事务入库；远程图片不下载，外部 ID 仅附带保存。
- 首次缺失/损坏 NFO 保留待处理文件；后续失败保留有效资料并报错。
- NFO 更新（包括整剧/季）需被扫描发现，不能仅依赖视频指纹。
- 用户确认没有历史非常规库数据，不实现历史文件、收藏、进度迁移；不得修改/删除普通库仍使用的共享资料。
- Web 和 Emby 维持列表、详情、版本选择、播放及权限过滤能力。

## Acceptance Criteria

- [ ] 有效 NFO 无网络 ID 亦可正常展示播放；普通、红果、NFO 数据隔离。
- [ ] 相同外部 ID 不合并到普通资料，也不产生任何元数据 HTTP 请求。
- [ ] 重复扫描不增殖记录；不同路径重复文件可保留；正确版本一张卡片，非版本文件不误合并。
- [ ] NFO/图片更新、缺失、损坏、权限失败及取消保留正确状态。
- [ ] 启动自动建表且重复启动幂等，不触碰本地媒体/NFO 文件。
- [ ] 专项 PostgreSQL 测试、Web 检查及跨体系回归通过；独立复核后交付。

## Notes

- 不包括在线刮削、新增依赖、自动改名整理、写回 NFO、部署生产迁移、重构普通库或红果。

## Approved follow-up: playback statistics

- 用户追加批准：非常规库接入管理员播放统计，普通/红果/非常规支持合并或分体系查看。
- 只合并读投影，不合并底层资料或事件。统一筛选、排序、分页、时间趋势和 Top 10。
- API 保留默认 catalog；Web 默认 all，并可选 catalog/hongguo/nfo，明细和排行榜标注体系。
- 复用普通电影/季度及红果来源作品口径；NFO 电影/季度使用本地身份，不按同名合并。
- 不涉及历史迁移、播放列表、生产部署。
