# 设计

## 作品候选统一追加（用户已确认）

- 最小行为差距：已有最新入库时间/库归属及作品范围资格方法没有覆盖所有同语义的作品列表；继续从全库文件生成候选，并非 Items 精确总数所必需。统一职责边界，不建立跨来源通用框架，不按客户端分流。
- 三来源各保留身份与可见性实现，优先扩展已有候选方法供库内及全局复用：红果 `hongGuoWorkScope` 的作品/合集范围与有效状态；NFO `NFOWorkCandidates`；普通 `latestMetadataViews/latestSeriesGroups` 的作品成员预筛与原资格范围。将轻量身份、请求所需排序/筛选列交给现有全局合并及计数分页；不要把库内 MIN DateCreated 与全局 MAX DateCreated 混为一谈。
- 对 Movie/Series 作品级需求启用共享候选；包含 Season/Episode、默认 Movie/Episode、IsResumable 或文件依赖排序时，保留必要语义分支。仅在状态用于过滤/排序时计算候选状态；海报角标等展示统计始终留在页内。PersonIds 从作品/credits 及可见文件存在性确认，避免为资格验证调用完整节点。
- 无总数 Latest 不再为了复用调用计数版全局列表；有/无 NFO 的路由均需回归。跨来源合并保持原层级、全局排序与稳定 tie，不用任意预截断替代资格检查。既有 global count/page 单次物化可保留。
- 普通 Emby 计数页及混合电影库从作品候选复用资格；Web 普通库允许按作品计算旧代表版本/分集排序值，但不得在分页前顺带计算展示统计。现有文件依赖规则、Part 选择与数量口径全部通过旧结果对照。若实际计划表明已有文件边界在某个分布更可靠，保留经验证的必要分支并记录原因，不通过强制规划器或新增缓存掩盖问题。
- 预期代码范围：service 的 emby_hongguo_browse/emby_hongguo_library/emby_hongguo/emby_nfo/emby_metadata_scope/emby_movie_items，以及必要调用方；repository 的 nfo_library_candidates、work_libraries、library_metadata_repository 及相关资格方法。只修改被排查和计划证据确认的部分；Web 红果/NFO 和最近添加已优化路径只回归。规范新建一个共享契约入口，既有来源契约只同步真正被替代的条款。
- 不涉及新存储、历史补算、权限/播放写入、API 参数、前端 UI、索引搜索、下载/维护任务。API catalog 做行为一致性核对；若响应契约不变，不为内部性能改动添加文案/UI 修改。最终不提交/归档或重启生产。

## Hills 全局列表补充（用户已确认）

全局候选按原筛选查询一次物化，仅保留身份与排序列，计数和分页共用。红果候选使用轻量层级投影，合集标题/全局时间先在作品层计算一次，避免每文件关联海报和重复读取合集；页内仍复用原完整 payload。普通/NFO 保留原候选语义，按计划证据约束重复文件/层级展开，不资格前截断。

红果单项范围扩展为可复用批量身份范围，按 group/work/season/episode 原生绑定选择文件再聚合，保留外层身份检查；NFO 的 nfoItemNodes 接收同类批量身份，混合页直接复用 NFOWorkNodes 的父子去重。仅修改 emby_hongguo_browse.go、emby_hongguo.go、emby_nfo.go、emby_system.go、必要回归及 API catalog/契约。不改数据库结构、播放写入、客户端设置、库内 Latest、OpenSearch 或连接池。CollectionFolder 删除未计算的未看数占位值，不新增全库计数。

## 时间所有权

- metadata_items、nfo_items 增加可空 latest_media_added_at。电影/分集来自自身文件；季/剧包含自身及后代文件，祖先字段随变更维护。
- hongguo_works 保存源作品（季）的最新时间。合集只在作品表层取成员 MAX，不扫描 Media，不把共同时间写回易变的第一季，不新增合集实体。合集取值范围独立于当前库有文件的成员范围。
- 无文件为 NULL，最近添加排序 NULLS LAST + 稳定 ID；不回退到资料更新时间，不覆盖 CreatedAt。

## 写入边界

生产写入不仅经过 MediaRepository.Upsert，还有删除库/根、手工重绑、整理器和 metadata merge 的直接 SQL。采用项目已有 internal/database/tmdb_recheck.go 的 PostgreSQL 事务触发器安装模式，覆盖 Media、两类绑定及普通/NFO parent 变化，避免多个入口重复维护。

新增更新最大值；删除/旧归属退出只重算受影响作品和祖先。按稳定顺序锁定受影响实体，锁后读取当前数据；不得用异步 best-effort 刷新维持正确性。批量、级联、并发与重复 AutoMigrate 要真实验证。只更新派生字段不能触发资料重查，Save/UpdateAll 不得写回陈旧派生值。

## 查询边界

最近添加候选读取作品字段，EXISTS 保留库成员资格，页内才补展示。已看过滤仍在分页前；不假设时间字段能省掉状态查询。统一指定库和全局近期查询，保留既有作品/分集响应层级，不全局替换所有 MAX(created_at)。标题、上映时间、DateCreated 和文件版本代表选择不变。

## 上线慢查询补充（用户已确认）

- 红果库 Items/Latest 共用路径先用非空作品时间排除无文件作品，再保留当前库与用户文件资格检查。
- 候选查询以作品层 CTE 一次汇总合集代表标题与全局成员时间；不在文件行重复计算合集时间。
- 页内文件仅按源作品汇总最早入库时间、去重分集数与有效播放状态，之后才关联作品资料、封面及收藏并合并合集。
- 非 DateCreated 的已看筛选将“全部可见文件已看”改写为“不存在未看可见文件”，复用有效播放状态、命中未看文件即停止；单独保留可见文件非空检查，再按合集过滤与分页。有效已看集号先按源作品在查询内汇总，再与作品关联一次，不按每个作品重扫用户全部状态。DateCreated 保留原日期聚合。
- 不改季集/搜索路径，不增加字段、表、缓存或历史补算。保留合集无文件首季的代表规则、跨库全局时间、状态过滤先于分页、DateCreated 与现有 payload。
- 用旧层级输出对照验证语义；真实计划覆盖多季合集、真实分集与多版本，不再仅用没有分集绑定的单季样本。

## 普通与 NFO 同类路径检查（用户追加）

- NFO 非 DateCreated 候选保留作品级时间与当前库可见文件检查；状态条件改为不存在未看可见文件，避免分页前聚合全库文件。继续复用 PlaybackStates，不改变原文件删除后的有效状态和代表版本选择。
- 普通库保持分集状态筛选后再聚合剧的语义；仅针对执行计划证实的 Latest 候选全文件展开做约束。已有 Web/Emby 页内统计、普通剧库空目录保护不重写。
- 回归加入 NFO 10 万文件/2.5 万状态、普通多季/多版本及大量状态执行计划；同时保留 DateCreated、权限、隐藏祖先和旧层级输出对照。

## 首页封面与剩余慢点补充（用户已确认）

- 红果公共图片入口按 group/work/season 身份限定作品与本地 artwork，再短路探测原规则下的可见文件；不展开层级或状态。保留无可见文件首季不参与封面、合集成员顺序、旧 work 身份失效和分集不提供海报的规则。
- 所有 Emby 缺图占位改为 no-store，正常图片长缓存不变；同步 API catalog。测试检查真实非 1×1 图片、GET/HEAD、缩放、缺图缓存以及大样本查询计划。
- 首页 Latest/Resume 用实际生产参数只读采样再决定优化；不凭日志毫秒数盲改权限、状态或分页，不新增缓存或重启服务。
- 实际计划证实：电影库强制相关 EXISTS 在全局时间索引跳过约 14.9 万无关项；仅该非整剧路径取消 OFFSET 0，允许规划器从库成员开始。整剧候选保留原边界；回归新增目标电影库较旧的分布。
- 红果无任何有效已看集的作品直接视为未看，省去重复文件/分集探测，仍检查可见文件存在。Resume/NextUp 精确总数与分页共用物化候选，Web 不计数路径不变。

## 红果详情点击链路（用户已确认修复）

- 详情、作品下季列表、季/作品下集列表先按 group/work/season/episode 身份限定可见文件，再复用原层级、状态与输出投影；保留外层身份过滤、排序、分页、精确总数和无文件首季代表规则。
- 检查当前页分集版本加载是否仍全库扫描，若实际计划证实则在相同身份边界限定绑定。只修改这条点击链路需要的 service/repository 与回归；不重写全局浏览、NFO/普通库、权限或播放规则，不新增缓存、表或后台任务。
- 对照原节点输出，大样本执行计划覆盖 group/work/season/episode 与子页；实际最近失败请求在生产只读事务验证，匿名化输出，不启动完整业务服务、不重启或提交归档。

## Web 与 NFO 点击链路补充（用户已确认）

- Web 红果 `hongGuoSeriesScope` 先以 group/work 原生 ID 限定绑定，保留原 CASE 身份校验。NFO 复用现有条目展开，增加季输入和父子去重，详情、子列表及两端版本查询共用范围；保留祖先 NSFW、库权限和状态投影，不更改普通库 SQL。
- Web 无 season 链接等待定向卡片的可见季，沿用优先正季、其次特别篇的默认选择，再加载该季。显式季仍独立请求；空卡片或失败不回退全剧。后端省略 season 的整剧 API 保留给管理员整剧操作。
- 回归对照原结果，真实执行计划检查文件/绑定读取范围，覆盖电影、剧、季、集、多版本、父子混合 ID、可见性和用户状态。Web 检查显式/默认季、特别篇、错误、刷新、切换和失效请求；不新增缓存、表、后台任务，不重启或提交归档。

## 各库 Latest 候选排序补充（用户已确认）

- 普通库先读取库内文件的作品身份超集，以全局作品时间排序；外层复用原可见性与分集已看资格。无 ParentID 的全局 Latest 保持原路径。
- 实际全库复测发现大剧库枚举库内身份反而更慢：剧库先检查全局有序的 512 个近期 Series，筛够一页即可返回；不足（含空和部分命中）则丢弃首批并查询完整库成员，绝不将首批作为最终截断。库成员子查询从限定文件范围 OFFSET 0 进入季/剧，避免倒置连接反复探测文件。
- NFO Latest 先排序当前库非空顶层条目，取消该分支候选物化；沿用原季集可见性和有效播放状态。红果先排序全局逻辑作品，再用 LATERAL 对候选成员复用原 scoped 查询，聚合可见成员已看状态后分页。
- 最终完整候选查询均无提前 LIMIT，权限和状态过滤后才截断；剧库有界尝试只有凑满才可提前结束，否则必须完整回退。保留 NFO 季/集号次序、红果全局合集时间、无文件首季代表、仅返回当前库可见成员、日期并列与普通计数列表语义。
- 只改 Latest 候选 service/repository 和对应回归。真实 PostgreSQL 比较旧结果与执行计划，并只读抽样实际新版业务方法；不增加缓存、索引、表，不写生产数据、不重启、不提交归档。

## 一次性补算执行边界

隔离验证通过后确认目标数据库身份（不输出凭据），先启用新字段和增量维护，再执行一次性补算并核对实际 MAX。补算须与持续写入协调，不能用旧快照覆盖新值；必要停写/重启另请授权。仅记录脱敏结果，删除临时材料。没有启动回填、永久补算命令或调度任务。

新字段/索引/触发器是长期维护结构，不是历史补算逻辑。回滚需考虑触发器写成本，不能直接破坏性删除数据。

## 持久库归属追加设计（用户已确认）

### 存储与维护

- metadata_items 与 hongguo_works 新增内部只读 library_ids，保存去重、稳定排序的实际非空库 ID 集合。采用 PostgreSQL JSONB 数组及 GIN 包含索引，复用项目已有 JSONB/GORM 模式；保留现有最新时间 B-tree 索引，不新增依赖。NFO 使用自身 LibraryID，不合并身份。
- 相比关系表，本轮只需要集合成员资格，没有每库独立时间或其他关联属性；关系表会增加实体、写入和孤立关系约束，暂无必要。JSONB 与原生 text[] 均可索引，JSONB 可沿用 internal/model/nfo.go:40、player_request_log.go:22 的既有存储/序列化方式，避免单独引入数组扫描类型。GIN 不提供时间顺序，必须实测成员过滤加时间排序，而非把建索引等同于查询变快。
- 实际计划证明仅 GIN 时 nullable OR 会使小电影库扫 22,000 个作品行；增加 `WHERE library_ids IS NULL` 的时间/ID 部分索引，允许规划器将未知分支与 GIN 组合，样本作品访问降为 10 行。保留按库大小选择其它索引的自由，不强制全局规划器设置。
- 库集合与 latest_media_added_at 在 latest_media_refresh 的同次受影响实体重算内维护，复用现有稳定行锁、锁后快照和祖先重展开；不再添加第二套触发器或异步队列。Media UPDATE 检测增加 library_id；普通自身/后代、红果绑定分别按现存文件计算。NFO 保留原入库时间维护。
- 新增/移入会加入库；删旧版本但仍有文件不退出库，删该库最后文件才移除。重绑与移季同时重算旧、新归属；库/根删除沿实际文件删除入口生效。派生字段 gorm 只读、不对外暴露，资料 Save/UpdateAll 不得写回陈旧值，触发器不得递归或误触发资料重查。
- 红果只存源作品集合；逻辑合集通过当前相关季投影，不持久化首季的合集并集。SaveAlbum 改关系即可改变逻辑归属，无须维护额外合集实体；标题代表和全局 MAX 时间仍来自全部有效成员。

### 读取边界

- 普通 latestMetadataViews/latestSeriesGroups 从作品库集合过滤候选，按全局作品时间排序，再复用原文件权限/有效状态资格。替换原 Media 成员枚举与为它服务的 512 前缀尝试/完整回退；保留剧集先按分集已看筛选后聚剧的契约。不做任何资格前截断。
- 红果 hongGuoLibraryItems 的 Latest 分支先限定有当前库成员的源作品，再聚合逻辑身份。albums 的标题和时间仍读全部成员，不能跟随库筛选缩小；matched 及页内投影只处理当前用户可见的源成员。
- Web ListRecentLogicalWorks 在已有允许/隐藏库边界内增加同一成员候选约束；没有库限制时不人为创建过滤条件。其共享统计消费者随入口复用，输出字段、排序与页内版本加载不改。NFO 已有单库条件，重点回归，不为形式统一改 SQL。
- 集合不是 NSFW、状态或权限缓存。保留原资格查询；仅删除纯成员身份枚举。未带状态条件的查询也不能在未证明可见性等价前直接删掉资格 EXISTS。

### 海报未看集数追加设计

普通容器已看聚合同时返回去重未看分集数，经批量 relations 和单项 payload 返回；红果层级、红果页内 file_stats 及 NFO 节点聚合各增加同一有效状态条件的 DISTINCT 计数。红果合集按源作品计数求和，保留不同源作品的同季号/集号身份。只在 Series/Season UserData 中输出，不改叶子、已看规则或总集数字段。

### 兼容、补算及回滚

- 字段允许 SQL NULL，明确表示尚未初始化；已维护无文件作品用空数组。新增列不能用空数组默认值把历史记录伪装成已计算。
- 读取端的候选成员筛选对 NULL 放行到既有精确资格检查，已知集合则按成员筛选。这样用户提前升级也不会隐藏历史作品；补算前可能仍有旧成本，但不把 NULL 当作可见性授权，也不在读取或启动时触发回填。
- 生产结构、增量触发器、一次性历史补算须分清状态：本次只做代码与隔离验证；生产操作前另请确认。补算经现有行锁维护函数分批进行或在明确协调写入后执行，不能用旧快照覆盖并发变更。集合核对零差异后 ANALYZE，重新验证计划与空集合/未知集合的处理。
- 无历史回填任务、永久补算 API 或自动全量迁移。回滚代码可以继续忽略新增列，保留字段及触发器以免破坏数据；任何结构删除另行评估。
- 主要风险是写入聚合/GIN 成本、NULL 兼容条件影响规划器、大小库分布差异；隔离计划及写入回归决定是否达到预期，不以“字段存在”作为提速验收。
