# 第 3 项设计评审稿

## 2026-09-29 红果查询收敛

身份直接来自作品的 kind/related_album_id；有效剧集候选要求非空合集和正季号。将 Emby 作品资格与合集展示聚合拆开，状态资格及页后成员查询不再重建 albums；页后按原生作品/合集 ID 限定作品。Web 库页一次聚合代表标题，不逐源作品执行 LATERAL；最近添加及页后版本身份定位复用直接关系。保留全局成员时间/标题范围、电影身份及现有文件资格，不改资料写入或追加缓存。原始源码查询与已补齐夹具作结果/计划对照，代码回退即可撤销。

## 2026-09-29 继续观看与 Part 优化边界

- `HistoryRepository.continuationSource` 以现有 `PlaybackStates` 的当前用户有效历史驱动，只关联对应身份的可见文件/层级，然后沿既有归组/下一集选择继续。共享状态算法及调用方响应不变；查询边界是否减少读取以 PostgreSQL 实际计划确认。
- `IngestPathResult` 在写入前识别名称或旧 Part 关系，`RemovePath` 复用删除前记录判断。局部 `reconcileMediaParts` 仅同级目录，扫描收尾显式保留递归范围；复用解析和关系修正逻辑，不依赖文件指纹变化触发校准。
- 为局部目录添加 `(library_id, lower(regexp_replace(path, '[^/]*$', '')))` 表达式索引，不新增父目录列或文件系统枚举。保留目录大小写兼容与组身份大小写区分；索引由现有启动迁移创建，生产建索引/重启不在本轮执行。
- 预期只修改 continuation 查询/测试、Part 查询及两个事件调用方/测试、现有性能索引迁移/测试和任务/契约记录。源码可独立回退；新增索引无业务数据变更，回退查询后可保留。第一次启动建索引可能增加耗时并阻塞写入，交付时注明。

## 2026-09-29 红果详情入口实施

`Client.Album` 直接切换到已实测的固定 `multi_video_detail/v1/` 与详情上下文，`parseAlbum` 按请求源 ID 取键，再校验内层源 ID。只改变这两个位置与相应夹具，不加旧入口回退、不改共享 `appRequest`、下载取流或补充任务调度。空体、空目标或错身份仍失败并保留旧关系；成功无合集使用前轮已批准的自身第一季。

验证先更新契约测试并观察旧代码失败，再修改实现；运行红果相关回归、真实只读样本和独立复核。代码回退即可撤销本轮接口调整，本轮不启动生产补充任务。

## 2026-09-29 退役路径清理边界

只删除 `cloud://` 的 guard/skip、三处媒体查询排除条件、专用错误映射、URI 相对路径分支以及云存储历史清理。目录仍复用 `resolveAccessibleLibraryPath` 校验；正常挂载映射、STRM、Part 名称与目录校准、防覆盖不变。原迁移中的转码设置删除独立保留，不改变其匹配范围。同步相关测试，移除旧云协议夹具，保留被其他迁移测试共用的断言方法。

用户确认观看记录按当前用户和逻辑媒体身份共享，不按库拆分。Emby Latest 的候选库筛选与卡片级全集统计是不同职责；本轮只核实当前范围差异，不改变返回字段含义。红果只读对照验证替代详情入口，不顺带修改共享下载请求或写生产合集。

## 2026-09-29 红果字段补齐边界

最小缺口在 `parseAlbum` 的成功空关系分支及 `PendingAlbums` 的候选条件。前者返回自身源 ID/第一季，后者纳入已检查但字段缺失的作品；`SaveAlbum` 拒绝空关系，防止成功检查点再次保存空值。保留未完成/失败作品的未知状态，不在建作品时编造已核验关系。

修改上述解析/仓库文件、现有契约测试、API 说明与相关规范，不改其他库或 Part 逻辑。存量只能在接口成功核验后通过已有保存链写入，不能批量 SQL 直接填自身。现有源身份不变，卡片从独立入口转成自身合集入口属于本次授权的展示变化。

## 已批准的验收阻塞修复

- 根因：未持有文件句柄时 inode 可复用；路径身份检查与直接删除之间也可替换。
- MediaProbeService 统一管理本地文件句柄生命周期；Linux 的 FFprobeService 使用继承句柄 `/proc/self/fd/3`，复用原并发限制与超时。成功写入也复核对象身份。非 Linux 保留普通探测，不执行无法安全保证的自动删除。
- 清理复用 `renameNoReplace`，不得降级为复制删除。临时隔离目录权限 0700，移后核对设备/inode、大小、修改时间；恢复不覆盖，空目录才清除。失败提示保留受控相对恢复位置。
- 现有 ScannerService 与 MediaProbeService 共用进程内读写锁，覆盖 RemovePath 及两类 prune 从存在性判断至删除。隐藏目录沿用现有 walk 排除规则。
- 不承诺跨进程事务、崩溃自动恢复或任意外部进程原地写入的内容快照；不新增配置或清理框架。
