# HongGuoDB 独立资料体系接入

## Goal

建立独立红果资料体系，为后续本地下载、文件整理、STRM 入库提供稳定资料匹配，兼容 Web 与 Emby；不污染现有资料体系。

## Requirements

- R1：本次来源只包含红果。作品、人物与演职员关系、图片、原始资料快照、同步状态和人工聚合数据按体系隔离，支持独立停用；不将红果作品复制入现有 metadata_items。
- R2：优先使用上游作品 ID，始终按字符串处理。文件匹配依据来源、作品 ID 和 SxxExxx；分集源 ID 可内部保留，不要求写入文件名。
- R3：确认完结且全一集的作品按电影处理；仅更新到一集的作品不能据此归电影。总集数、已更新集数、网页可访问集数分别处理，不以可访问集数替代总量。
- R4：无人工聚合时，多集作品独立呈现，默认第一季。支持人工将多个源作品映射为一个聚合剧的不同季，不自动根据标题或推荐列表合并；聚合不改变源作品或单集身份，不丢失进度。
- R5：保存来源真实提供的介绍、标签、评分、演员、图片与首次上线时间。首次上线不冒充权威首播时间；缺失字段不编造。分页抓取未覆盖的作品不能据此删除。
- R6：媒体文件及探测能力可复用，来源资料绑定隔离。已有媒体、收藏、播放记录、权限及 Emby ID 必须保持兼容；新来源的用户数据不随资料体系停用而丢失。
- R7：任务中心保留一个 Web 入口，按公共任务、现有资料体系、HongGuoDB 切换，URL 保存选择。配置、执行范围、业务检查点、互斥与取消边界按体系隔离；可复用调度、日志与组件，并保留公共资源总量限制。
- R8：红果任务视图不加载旧体系专属待办。现有体系包含豆瓣等能力，不能简单全部重命名为 TMDb。
- R9：图片本地存储按体系隔离，不泄露签名 URL、请求上下文或敏感凭据；快照不保存无关用户评论。

## Acceptance Criteria

- [ ] 红果资料入库不新增、覆盖现有作品、人物或图片记录；相同外部 ID 在不同来源不会互相匹配。
- [ ] 超过 JavaScript 安全整数范围的作品 ID 往返不失真；来源 ID 与集号能够定位唯一资料。
- [ ] 完结单集与更新一集的多集作品分类不同；免费可访问集数不影响作品总集数。
- [ ] 未聚合剧正常展示；人工聚合后 Web/Emby 按指定季号展示，原播放进度仍可读取。
- [ ] 本地文件或 STRM 可绑定红果资料，并沿用权限受控的现有播放链路；旧媒体行为回归通过。
- [ ] 任务体系选择可通过 URL 恢复，旧任务配置兼容；红果操作不运行旧体系专属任务或读取其待办。
- [ ] 收藏、继续观看与播放记录按用户隔离，来源停用不误删用户数据。
- [ ] 来源解析、入库幂等性、隔离边界与相关接口有可运行检查；涉及 Web 的修改通过 lint/build。

## Out of Scope

- 黄果、黄豆接入；资源站在线播放、解密代理；下载器；自动跨季合并；移动或重命名现有媒体文件；强制生成 NFO。
- 未来下载与整理功能保留 ID 契约，本次不实现下载或 NFO 导出。

## Delivery

- 用户已确认完整推进，不限任务中心。开发期间执行自动化检查并持续记录人工验证项，全部完成后提供逐项人工验收清单，不要求用户逐阶段介入验证。

## Planning Status

- 完整接入已获实施授权；按独立资料、任务、媒体与用户状态、Web/Emby 顺序实施，各阶段保留可重复验证记录。
