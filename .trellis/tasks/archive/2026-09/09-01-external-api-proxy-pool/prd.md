# 外部 API 代理池

## Goal

在现有“外部 API”页面提供管理员手工维护的静态代理池，并允许豆瓣显式启用该代理池，以在豆瓣 JSON 元数据请求命中出口限制的 `HTTP 400` 时按固定顺序切换线路，同时不改变其他外部请求的网络行为。

## Background

- 当前豆瓣 JSON 详情请求在上游返回 `HTTP 400` 时只记录 `douban detail: 400`，响应体会被丢弃，因此现有日志本身不能进一步证明具体服务端原因。
- 已观察到的同类响应可包含 `code=1309`、`subject_ip_rate_limit`，指向出口 IP 限制；本任务按精确 HTTP 状态处理，不依赖响应体字段。
- 当前 `NewExternalHTTPClient` 会读取环境变量和系统代理，应用内没有可由管理员维护的代理池。
- 代理 URL 可能包含用户名和密码，必须按敏感凭据处理。

## Requirements

### 管理与配置

- 在“外部 API”页面现有 Provider 配置下方提供独立的代理池区域。
- 管理员能够新增、替换、删除和调整静态代理节点顺序；不接入动态代理供应商。
- 公共或管理响应均不得返回代理用户名、密码或完整带凭据 URL；页面仅显示不含认证信息的地址和“已配置认证”状态。
- 所有代理 URL 均加密落库；Cookie、代理认证信息和完整带凭据代理地址不得写入日志、任务详情或错误消息。
- 豆瓣 Provider 配置增加“使用代理池”开关，默认关闭；新安装和已有安装升级后均保持关闭。
- 代理池列表或豆瓣开关保存后立即对后续请求生效，并将豆瓣粘性线路重置为真正直连。

### 网络边界

- 开关关闭时，豆瓣保持现有 `NewExternalHTTPClient` 网络路径，包括已有的环境变量和系统代理行为。
- 开关开启时，状态机中的“直连”必须将 Transport 的 `Proxy` 设为 `nil`，完全绕过 `HTTP_PROXY`、`HTTPS_PROXY` 和系统代理。
- 首期仅接入豆瓣 Search、Discover、Detail 等 JSON 元数据 GET 请求。
- 豆瓣图片下载、AI 请求和其他 Provider 均不使用本代理池，保持现有行为。

### 选路状态机

- 启用后初始线路为真正直连；真正直连返回非 400 时保持该线路。
- 当前真正直连返回精确 `HTTP 400` 时，按管理员配置顺序尝试代理节点。
- 首个返回非 400 的代理节点成为当前线路，后续请求持续使用该节点。
- 当前代理节点返回精确 `HTTP 400` 时，从真正直连重新开始选路，而不是直接从下一个代理开始。
- 一轮中真正直连返回 400 且全部代理也返回 400 时，最后再真正直连一次；最后一次直连返回非 400 时恢复并保持直连，否则返回现有 400 错误。
- 代理池为空时仍执行“首次真正直连、最终真正直连”的同一规则。
- 仅精确 `HTTP 400` 触发线路切换。网络错误、超时、DNS/TLS 错误、403、404、429、5xx 或其他非 400 结果立即沿用现有返回语义，不继续尝试其他线路，也不改变当前粘性线路。

## Acceptance Criteria

- [ ] 管理员能够在“外部 API”页面 Provider 配置下方维护有序静态代理列表。
- [ ] 代理 URL 全量加密落库，管理 API 和页面仅返回/显示去除认证信息的地址及认证状态。
- [ ] 豆瓣配置能够保存并立即生效“使用代理池”开关；默认值为关闭。
- [ ] 开关关闭时，豆瓣 JSON 请求继续使用原有环境/系统代理感知路径。
- [ ] 开关开启时，真正直连完全绕过环境和系统代理；首次直连非 400 时不会使用代理节点。
- [ ] 首次直连 400 后按静态列表顺序尝试；首个非 400 节点被粘性复用，直到该节点返回 400。
- [ ] 当前代理返回 400 后从真正直连重选；全部线路返回 400 时完成最终真正直连后才返回错误。
- [ ] 网络错误和所有非 400 HTTP 状态不触发后续线路尝试，也不改变当前粘性线路。
- [ ] 修改代理列表、关闭代理池或重新开启代理池后，下一次启用态请求从真正直连开始。
- [ ] Search、Discover、普通 Detail 和补齐 Detail 使用同一选路规则，且保留各自现有响应解析、错误分类和详情降级语义。
- [ ] 豆瓣图片、AI 和其他 Provider 的客户端与网络路径不变。
- [ ] 日志、API 错误和任务输出均不包含 Cookie、代理认证信息或完整带凭据代理 URL。

## Out of Scope

- 自动让所有外部 API 使用代理池。
- 对 AI 等可能产生费用或副作用的 POST 请求自动重试。
- 按网络错误、超时、403、404、429、5xx 或响应体业务码切换线路。
- 动态代理供应商、自动健康检查、定时探测、随机/权重调度和失败节点摘除。
- 改变豆瓣图片 CDN、图片直连、图片缓存或负缓存语义。
- 将代理配置复用为 Provider 的 `base_url` 或明文放入 `Extra`/通用 Settings。
- 为 `douban detail: 400` 新增响应体日志或诊断采集。

## Notes

- 本任务跨数据库、管理 API、Web 设置页和豆瓣请求层，按复杂任务规划。
- 首期共享的是安全的静态代理配置；每个未来接入的 Provider 应拥有独立线路状态，不能共享豆瓣的当前线路。
