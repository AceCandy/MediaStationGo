# 红果卡片分集状态批量统计

## Goal

按已确认方案将红果卡片详情的逐集状态探测改为本页作品有效状态批量关联，保持现有权限、去重和播放语义并验证执行计划。

## Requirements

- 红果库卡片详情按当前页作品一次读取当前用户的有效观看状态，再与页内文件/分集批量关联，避免每个文件重复探测历史。
- 保持合集身份、顺序、标题封面、文件最早时间、逻辑分集去重、未看集数和收藏不变。
- 保留用户/库权限、空状态、缺分集绑定按第 1 集、显式完成及删除版本后的有效完成推导；电影/混合页仍返回原播放位置和时间。
- 不修改候选排序、50 条补取、总数、其它来源/层级入口、后台任务、数据库结构或缓存；不部署或重启服务。实现阶段不提交，后续按用户明确授权提交归档。

## Acceptance Criteria

- [x] 与原层级查询的完整 payload 对照通过，覆盖两位用户、多版本、跨库、缺绑定、电影与 Series、有效状态。
- [x] 真实隔离 PostgreSQL 大样本计划证明状态访问限制在页内作品，状态探测循环按源作品而非分集数量增长；不扫描无关历史。
- [x] 记录改前失败的性能断言和改后执行计划；功能回归、race、vet、格式及独立只读复核通过。
- [x] 临时测试服务关闭、调试产物清理；明确 SQL 测试与未验证生产 HTTP 的边界。

## Approval / Evidence

- 用户在解释“本页分集统一统计＋当前用户本页状态批量关联”后明确回复“可以 那你改吧”。本任务落实已批准方案，不增加产品行为。
- 最新请求红果详情约 352 ms；只读计划观察 16 张卡片含 53 个成员作品、约 6,566 条文件关联，每条都探测完成状态。
- 此前规范防止 UNION 扫描全用户历史的边界仍须保留；本轮改变关联粒度，不简化有效状态规则。
- 用户复核当前流程后明确要求“提交归档吧”，授权本任务提交、归档及验证记录；不含推送远端或部署。
