# 优化季集复查吞吐及单轮进度

## Goal

按季复用复查请求，固定单轮到期边界，展示剩余量并区分失败阶段

## Requirements

- 同季已到期待办集中执行，减少整季数据重复请求。
- 固定单轮到期边界；本轮产生的重试在后续执行处理。
- 任务进度显示本轮剩余量；错误区分详情、图片和保存阶段及耗时。
- 三路并发按季领取，季内分批核对；保留逐集结果、身份校验、72 小时冷却及退避规则。
- 入库复用季清单，未收录的集保留占位关联并标记待核对；网络失败不冒充编号不匹配。

## Acceptance Criteria

- [x] PostgreSQL 测试覆盖同季优先、全局回退、锁竞争、截止时间和重试排除。
- [x] 模拟上游验证跨季乱序条目集中执行后请求被复用。
- [x] 失败日志可区分阶段，错误分类及敏感信息脱敏保持有效。
- [x] 剩余量低频刷新；验证相关 Go 测试及页面检查。

## Notes

用户进一步批准季级调度及入库问题标记，下列验收在此轮重新验证：
- [x] 同季租约互斥、分批处理、续租及旧执行者拒绝写入。
- [x] 一季的网络失败共享给该季各集，不逐集重新请求。
- [x] 未收录集保留关联并显示问题，后续恢复可清除问题。
