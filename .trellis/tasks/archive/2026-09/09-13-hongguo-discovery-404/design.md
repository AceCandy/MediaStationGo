# 红果发现摘要展示与 404 暂缓设计

## 边界

- `hongguo_discoveries` 继续只保存来源摘要，不成为可绑定、可收藏或可播放的正式作品。
- Web 作品列表增加“是否已补齐”投影；仅发现条目只用于浏览卡片，详情、分集、聚合和媒体接口仍要求 `hongguo_works`。
- 上游海报地址继续只留在服务端，浏览器只接收现有图片 ID 并访问本地图片接口。

## 数据流

1. 分类或榜单发现保存摘要时，以 `source_id` upsert 对应作品海报图片待办；空海报不建待办，同一来源跨分类/榜单仍只有一条。
2. 红果图片下载任务沿用现有下载、退避、落盘和图片服务逻辑。
3. 列表在数据库分页前以来源 ID 合并正式作品与发现摘要：正式作品字段优先，摘要只补充尚未补齐的卡片。
4. 详情成功后在同一事务内将同一来源 ID 的海报关联到正式作品；详情海报地址优先，详情未给海报时保留发现海报，不复制图片文件或公开上游地址。
5. 前端根据 `hydrated` 区分卡片。仅发现卡片点击时提示资料不存在；直接访问一个不存在的详情 ID 时也展示明确 404 空态。

## 数据库兼容

- 给 `hongguo_artworks` 增加可空且唯一的 `source_id`，作品海报以来源 ID 为稳定身份；人物头像仍以 `person_id` 为身份。
- 幂等启动迁移按“加列 → 从 `hongguo_works` 回填 → 检查重复/缺失 → 建唯一索引 → 替换 owner 约束”的顺序执行。已有 `work_id`、本地文件键和下载状态保持不变，失败时事务回滚。
- 新 owner 约束要求人物图片只有 `person_id`；作品/发现海报至少具有 `source_id` 或旧版 `work_id`。保留旧版 `work_id` 形式是为了代码回滚后仍可 upsert，新增代码始终写 `source_id`。
- 发现海报允许只有 `source_id`、没有 `work_id`；详情补齐后更新其 `work_id`。人物图片不设置 `source_id`。
- 海报 upsert 统一按 `source_id` 冲突：发现写入不得覆盖已经关联正式作品的详情海报；详情写入可更新来源地址并补 `work_id`。现有 `source_url` 条件写回继续阻止并发旧下载覆盖新地址。
- 不新增第二张图片表或第二套下载器。

## 列表契约

- `GET /api/catalogs/hongguo/works` 保持原分页结构，列表项新增 `hydrated: boolean`；合并、去重、过滤和计数都在 LIMIT/OFFSET 前完成。
- 同一来源 ID 最多返回一项；有正式作品时返回原字段及本地图片 ID。
- 仅发现项返回标题、简介、来源分类、摘要集数/更新文案、本地图片 ID、`hydrated=false`；无法从摘要证明的字段使用零值。前端显示“待补齐”，不显示评分、详情标签或电影判断。
- 具体题材筛选继续只查正式作品；来源分类、榜单、无筛选和搜索允许返回摘要。
- 默认列表按各记录首次入库时间倒序、稳定 ID 倒序；已有正式作品之间维持当前顺序。榜单按官方 position、来源 ID 排序。总数按去重后的来源 ID 计算。

## 404 与任务语义

- 继续使用 `errors.Is(err, hongguo.ErrNotFound)` 分类，不匹配错误文本。
- 同步失败记录方法接收明确的 `retry_at`：详情 404 使用当前尝试完成时间加 72 小时，其他错误保持加 1 小时；重复失败递增 attempts 并从最近尝试重算。
- `PendingDiscoveries` 继续排除所有失败行；72 小时到期后由 `DueSyncFailures` 选中，成功刷新清除失败行，摘要在整个期间保持可见。
- 任务报告单独累计 `deferred`。批量刷新遇到 404 时写 `⚠️` 暂缓明细并继续，不增加 `failed`；404-only 批次返回 nil，只有非 404 错误使批次最终失败。
- 管理员单 ID 刷新的 HTTP 失败行为保持现状，但同样写入 72 小时冷却。

## 回滚与风险

- 回滚代码后新增可空列和已回填值可安全保留；兼容 owner 约束允许旧代码继续按 `work_id/person_id` 工作，发现专属图片行会被旧代码忽略。
- 没有 `hongguo_discoveries` 摘要的历史失败 ID 无法展示标题或海报，需未来再次被分类/榜单发现或详情恢复。
- 摘要集数只是来源列表文案，界面必须标识待补齐，不能用于媒体绑定或生成分集。
