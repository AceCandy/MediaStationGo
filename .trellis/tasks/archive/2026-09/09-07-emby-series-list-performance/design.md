# 设计

计数/分页的四表连接误估为约一行，先遍历目录中的全部分集，再逐条匹配媒体文件；真实执行约 15.3 万次文件索引查询。只读 EXPLAIN 已复现计数约 907ms、分页约 875ms。

在 `seriesMetadataPage` 内使用相关 LATERAL 季查询和 `OFFSET 0` 作为查询展开边界，使分页先限定可见文件/分集再查询父级。`OFFSET 0` 不截断结果。保留原有父级 kind 检查和完整过滤条件。当前页摘要继续使用原始 `seriesScopeQuery`，保持具体整剧 ID 的选择性；详情、搜索、计数等其他调用不改。

不增加索引、持久缓存、配置或数据库迁移。回滚只需恢复列表查询代码。

收藏条件使用相关 EXISTS：父级连接移至分页函数后，旧 JOIN 的 ON 会提前引用尚未出现的整剧别名。EXISTS 保留用户与软删除筛选，且同时适用于分页和摘要。

Web 扩展：只在 `ListLibraryMetadataPage` 的 Series 分页聚合中，将媒体输入包成按当前库筛选且带 `OFFSET 0` 的派生表。禁止优化器先展开全目录再对媒体表做逐条参数化索引查询。外层原有过滤全部保留；计数、单剧详情和电影分页不变。此边界与 Emby 不同，不抽取混合两端排序和选版规则的通用分页器。
