# 季集复查持久化待办

## Goal

用事务登记、到期领取和有界核对替代季集复查全库候选扫描

## Requirements

2026-09-09 用户批准慢 SQL 优化：季集待办搜索复用匹配结果；媒体库整剧分页复用文件范围和总数，仅对当页统计代表文件与版本。保持精确总数、空页、筛选、排序、直接整剧/季文件及多版本语义；不新增索引、不写实际数据库。

- 季/集专用持久化待办，每目标唯一；空闲领取不联查整个元数据库。
- 文件新增/删除/重绑、相关元数据/标识/快照/图片变化、合并操作与登记同事务；重复事件合并，整剧后代展开有界。
- 保留季/集缺失判断、有效资产与标识唯一性、72 小时成功检查冷却；标题不独立触发检查。
- 保留任务中心开关、调度周期、手动入口、日志和最多 3 并发；事件只登记，不直接请求 TMDb。
- 租约、领取 token、变更版本保护并发，旧 worker 不得迟到覆盖新事件或用户修改；取消/重启可恢复。
- 完整/无文件退出活动待办，成功仍缺资料按 72 小时安排；请求失败退避，标识阻塞等待变更或低频核对。
- 首次上线与低频补偿使用持久游标分批核对，空批仍推进，不在启动迁移内全量补建，不覆盖已有冷却/租约。
- 用户追加批准 Web 只读待办：在现有任务中心展示季集标题、状态、下次检查时间、重试次数、脱敏原因；提供状态数量、状态筛选和服务端分页。仅管理员访问，不提供逐条重试/删除。

## Acceptance Criteria

- [ ] 真实 PostgreSQL 验证业务写入与登记同事务回滚、批量/合并入口、处理中变更、自身写入、租约过期/旧 token、多实例领取及重启恢复。
- [ ] 保持原缺失/冷却/季零/多版本/无文件规则；验证初始化空批、续扫和取消。
- [ ] 大量未来/完成待办下，到期领取命中索引且不扫描 media/metadata_items；按批检查及后代展开规模有界。
- [ ] 原定向回归、go vet、独立复核通过；清理临时服务，不直接修改实际库、不重启用户服务、不提交。
- [ ] 管理员只读 API 的鉴权、参数验证和分页测试；Web 加载/空/失败状态、筛选分页及 lint/build 验证。
