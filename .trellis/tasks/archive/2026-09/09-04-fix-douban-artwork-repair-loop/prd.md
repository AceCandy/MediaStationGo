# 修复豆瓣海报重复本地化

## Goal

让豆瓣海报本地化任务可靠区分“已经检查过的最佳可用图片”和临时下载失败，避免同一候选每次运行都重复下载或重复报告确定性 404，同时保留真正可恢复故障的重试能力。

## Background

- `artwork_backfill.go:61-91` 当前把 `source_url` 含 `s_ratio_poster` 或资产宽度不超过 300 的候选视为小图；即使 `/view/photo/l/` 下载成功后实际宽度仍不超过 300，下次任务仍会再次处理。
- `artwork_repository.go:278-297` 每次扫描所有豆瓣海报候选，任务历史不参与业务重试判断。
- `image_proxy_remote.go:164-190` 仅当配置 CDN 失败后最终官方源也返回精确 HTTP 404 时，才把结果保留为 404；网络错误、5xx 和非图片响应仍是临时失败。
- `artwork_repository.go:397-421` 成功修复会原子切换候选，并仅同步仍指向同一旧豆瓣资产的当前选择。

## Requirements

- R1：候选必须持久化最近已经完成检查的官方大图 URL；任务日志和执行历史不得充当业务检查点。
- R2：本地候选文件可用且当前派生的官方大图 URL 等于已检查 URL 时，本轮必须静默跳过，不再依据实际宽度重复下载。
- R3：配置 CDN 与最终豆瓣官方源均返回精确 HTTP 404，且现有本地小图可用时，必须保留小图、持久化已检查 URL，并以非失败详情说明“大图不存在，保留现有小图”。
- R4：精确 404 发生时若本地文件缺失，仍必须作为失败保留，不能用检查点掩盖缺图。
- R5：网络错误、超时、HTTP 5xx、429、空响应或非图片响应不得写入已检查 URL，后续任务仍可重试。
- R6：修复下载成功后，必须在同一候选 CAS 更新中保存新资产、官方来源 URL 和已检查 URL；并发变化仍按现有逻辑跳过。
- R7：豆瓣元数据产生不同的大图 URL 时，新 URL 与旧检查点不匹配，必须重新尝试；不得伪造小图的来源 URL。
- R8：保留现有 CDN 临时投影、官方 URL 持久化、旧资产/文件保留和手工选择不被替换的约束。

## Acceptance Criteria

- [x] 已成功下载官方大图但实际宽度不超过 300 的候选，第二次运行不再发起下载，也不再输出重复成功详情。
- [x] 最终官方源精确返回 404 且旧小图文件可用时，任务保留旧资产，写入已检查 URL，输出跳过详情，并且整项任务不因该候选失败。
- [x] 上述 404 候选在派生 URL 未变化的后续运行中不再发起下载；派生 URL 变化后会再次尝试。
- [x] 最终官方源精确返回 404 且本地文件缺失时，候选仍被报告为失败且不写入检查点。
- [x] 临时下载错误不写入检查点，下一次运行仍会调用下载。
- [x] 候选在下载或检查点写入期间发生变化时，CAS 不覆盖新状态。
- [x] PostgreSQL 自动迁移可重复执行并创建新字段；相关 service/repository 聚焦测试通过，`git diff --check` 通过。

## Out of Scope

- 不为豆瓣图片增加新的重试队列、定时器或可配置阈值。
- 不回写任务历史，不清理旧资产或旧文件，不修改前端任务中心结构。
- 不把 403、429、5xx 或网络错误永久降级为“只有小图”。
