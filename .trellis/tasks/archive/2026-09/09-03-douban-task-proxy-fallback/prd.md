# 修正豆瓣任务代理回退顺序

## Goal

让每次豆瓣电影信息补齐任务从直连开始，并将单次请求的故障切换限制为“直连 → 一次代理 → 一次直连”，避免 Resin 或普通代理池故障后持续卡在代理线路。

## Background

- 当前 `DoubanProvider` 会跨定时任务保留成功代理路由，导致上次已切到 Resin 后，新任务可能直接请求 Resin。
- 当前仅 HTTP 400 或 `unexpected EOF` 会触发线路切换，因此 Resin 返回 HTTP 503 时不会回退直连。
- 定时和手动执行最终都进入 `ScraperService.runDoubanMovieEnrichment`，该方法是本需求的任务开始边界。

## Requirements

- 每次进入豆瓣电影信息补齐任务时，将豆瓣请求路由重置为直连；分页和逐条处理期间不得重复执行任务级重置。
- 首次直连成功时继续直连。首次直连只有遇到精确 HTTP 400 或可由 `errors.Is` 识别的 `unexpected EOF`，才尝试代理池。
- 进入普通代理池或 Resin 后，一次请求只尝试一条代理线路。代理返回 HTTP 400 以上状态，或发生请求/响应体读取错误，均视为代理失败。
- 代理失败后立即尝试一次直连，不再尝试代理池中的其他条目，也不再次尝试 Resin。
- 最终直连的结果直接返回给现有调用层；若仍失败，由现有豆瓣补齐任务错误处理停止或暂停本次任务，不在路由层继续重试。
- 代理成功后可在本次任务后续请求中继续复用；下一次任务开始时必须再次重置为直连。
- 普通代理池和 Resin 使用同一切换规则；不得回退到另一种代理池类型。
- 不新增配置项，不修改管理 API、数据库或前端。

## Acceptance Criteria

- [x] 连续执行两次补齐任务时，两次任务的第一次豆瓣请求都走直连，即使前一次任务已成功切到代理。
- [x] 直连成功时不调用代理；直连返回非 400 的 4xx/5xx 或非 EOF 网络错误时不调用代理。
- [x] 直连返回 HTTP 400 或 `unexpected EOF` 时调用一条代理；代理成功后返回代理结果并复用该线路。
- [x] 当前线路为代理时，HTTP 503、其他 HTTP `>=400`、网络错误或读取错误均只触发一次直连；该直连无论成功或失败都不再调用代理。
- [x] 初始直连触发代理后，如果代理失败，调用顺序严格为 `direct, proxy, direct`。
- [x] 普通代理池存在多个条目时，首条代理失败后不会尝试下一条。
- [x] 现有任务异常日志与暂停机制继续接收最终直连错误，不泄露 Resin Token、代理凭据或完整反向代理 URL。
- [x] 聚焦 Go 测试、Vet 和 `git diff --check` 通过。

## Out of Scope

- 不调整豆瓣搜索、发现页或海报下载任务的任务级起始路由。
- 不增加自动健康检查、熔断、退避重试或代理排序。
- 不改变 HTTP 2xx/3xx 的现有成功判定及豆瓣详情权限降级规则。
