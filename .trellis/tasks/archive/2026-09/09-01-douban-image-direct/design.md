# 豆瓣图片直连开关设计

## Boundary

改动只贯通一个豆瓣专用布尔配置，并在共享图片代理中切换豆瓣图片的请求顺序。豆瓣元数据请求、非豆瓣图片和现有 curl 参数保持不变。

## Data and UI

- 在现有 `APIConfig` 模型、管理 API 的公开视图/更新补丁/运行时解析结果中增加 `image_direct`。
- 数据库迁移为旧表补齐布尔列，零值 `false` 保持旧行为。
- React 外部 API 面板仅在豆瓣编辑项中显示“图片直连”复选框，保存时显式提交布尔值。

## Runtime Flow

1. 服务装配时把现有 `APIConfigService` 注入 `ImageProxy`，不改变广泛使用的构造函数签名。
2. `ImageProxy` 在实际远程请求前读取豆瓣配置：开关开启，且 URL 属于豆瓣官方域名或当前自定义图片域名时，选择直连模式。
3. 直连模式只创建直连 HTTP 客户端候选；失败后允许现有 curl 兜底，不再限制 host。
4. 普通模式继续按“默认客户端 → 直连客户端 → 官方豆瓣域名 curl”执行。
5. 直连模式使用独立失败标记，因而不会被旧模式失败标记拦截；成功缓存仍按原 URL 共用。清理缓存时同时删除两种失败标记。

## Compatibility and Failure Handling

- 未迁移记录、旧前端和缺少 API 配置服务的测试实例均得到 `false`，行为不变。
- 配置读取失败时回退普通模式，不扩大故障影响。
- curl 缺失、超时、返回非图片或错误状态时继续使用现有错误与日志路径。
- 回滚时关闭开关即可恢复旧请求顺序；删除代码不会影响已有成功图片缓存。

## Verification

- 数据库迁移测试确认旧表补列。
- API 配置测试确认 `image_direct` 保存、公开返回和运行时解析。
- 图片代理测试确认直连候选顺序、豆瓣自定义域名 curl 资格、非豆瓣域名隔离及独立失败标记。
- 前端执行现有类型检查或构建，确认字段和表单提交类型一致。
