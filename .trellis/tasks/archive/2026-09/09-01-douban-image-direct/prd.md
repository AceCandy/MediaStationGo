# 豆瓣图片直连开关

## Goal

让豆瓣图片在代理不稳定时可以显式绕过系统代理获取；直连仍失败时，由现有 curl 机制兜底。

## Background

- 豆瓣图片会先应用官方大图和自定义图片域名，再统一经过 `ImageProxy` 展示或下载。
- `ImageProxy` 当前依次尝试默认客户端、直连客户端；curl 仅允许豆瓣官方域名，自定义域名失败后无法进入 curl。
- 图片失败会缓存 6 小时；豆瓣本地化修复会主动清理失败缓存，普通页面不会。

## Requirements

- R1：在“外部 API”的豆瓣配置中增加图片直连布尔开关，并持久化保存；默认关闭。
- R2：开启时，豆瓣官方图片域名和当前配置的自定义图片域名按“直连 → curl”请求，不先尝试默认代理客户端。
- R3：开关覆盖豆瓣图片的页面展示、预加载和本地下载共享链路，但不影响非豆瓣图片或豆瓣元数据 API。
- R4：首次开启时立即绕过旧策略留下的失败缓存；直连模式自己的失败仍缓存 6 小时，避免重复请求。
- R5：关闭时保持现有请求顺序；curl 不可用或仍失败时沿用现有失败与日志行为。
- R6：不增加依赖或通用网络策略抽象。

## Acceptance Criteria

- [x] 外部 API 的豆瓣配置中可以启用或关闭图片直连。
- [x] 开启后，豆瓣图片不会先走默认代理客户端，而是先走直连客户端。
- [x] 直连失败后，自定义图片域名也会进入 curl 兜底。
- [x] 非豆瓣图片不受该开关影响。
- [x] 关闭后，现有默认请求顺序不变。
- [x] 开启直连后不受旧失败缓存阻塞，直连模式失败仍受 6 小时失败缓存保护。
- [x] 旧数据库自动补齐配置列；配置保存、读取和图片请求顺序均有聚焦验证。

## Out of Scope

- 不改变非豆瓣图片的请求策略。
- 不改变豆瓣元数据、搜索和发现接口的网络请求策略。
- 不增加 curl 路径、超时或代理等额外配置。

## Technical Notes

- 豆瓣 API 配置由数据库模型、管理 API 和 React 表单共同维护；新增字段默认 `false` 保持兼容。
- `ImageProxy` 根据豆瓣官方域名或当前配置的自定义图片域名识别豆瓣图片，避免把直连策略应用到其他图片源。
- 默认策略和直连策略使用独立的失败缓存标记；共用成功图片缓存。
