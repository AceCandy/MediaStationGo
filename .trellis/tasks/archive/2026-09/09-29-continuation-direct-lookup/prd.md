# 续播按逻辑身份直接定位

## Goal

收窄 NextUp 目标观看历史，并按已知逻辑身份直接定位续播分集，减少重复读取和编译开销，保留原返回结果。

## Background

- 用户已确认按此前说明实施：先限定目标剧历史，按作品和集号定位单集，再查可见文件版本。
- 实际红果样本含当前用户 1,714 条历史，原查询访问分集约 417,272 次；NextUp 和 Resume 重放约 15 秒，约 12 秒用于 JIT。指定无历史合集的只读范围对照约 49 毫秒且结果一致。
- 状态身份已有普通 metadata_id、红果 source_id + episode_number、NFO item_id；media_id 仅保留具体播放版本。

## Requirements

- R1：指定剧集的续播／下一集先限定该剧所属来源和历史身份，保留 group/work、NFO 和普通剧身份语义。
- R2：红果历史按源作品和集号直接定位分集及文件绑定，避免逐条历史遍历作品的全部文件。
- R3：保持用户和库权限、电影／分集、多版本、旧文件删除后的替代、有效完成与重播断点、跨季顺序、准确总数和分页不变；共享 Web 续播一并验证。
- R4：使用既有字段与索引，不新增缓存、持久配置、表结构或播放状态写入。

## Acceptance Criteria

- [x] 长剧、大量当前用户历史的回归在原实现中揭示重复读取，修改后分集／绑定访问量受逻辑身份限制。
- [x] 指定有历史／无历史剧集、全局 Resume／NextUp／Web、三来源和分页结果正确，已有权限与替代版本测试通过。
- [x] 实际参数化 SQL 计划验证默认及通用预编译计划；记录访问量、JIT 与耗时，不以合成测试时间代替 HTTP 验收。
- [x] 针对性数据库回归、race、vet、格式检查及独立复核通过；诊断临时服务和文件清理。

## Out of Scope

- 不调整收藏／已看错误码、客户端重复请求、全局 JIT、生产索引、服务部署或重启。
