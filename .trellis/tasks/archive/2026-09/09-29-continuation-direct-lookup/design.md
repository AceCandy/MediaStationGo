# 查询范围与兼容性

改动位于 `HistoryRepository.Continuations/continuationSource`，所有 Web/Emby 续播消费者复用该入口。指定公共剧 ID 时选择所属来源，并通过该来源现有资料关系限定历史身份；保留最终公共 series_id 条件作为结果约束。

红果历史文件资格先按 source_id、episode_number 查既有作品／分集／绑定索引，再沿现有投影验证作品、文件可见性和有效版本。电影保留可空 episode_id 及原身份判断。下一集必须保留对没有历史的分集的独立 LEFT JOIN 状态路径。

保持 PlaybackStates 的完成推导、替代版本和重播语义；不因优化改为仅相信原 media_id，不先截断历史，也不写入读取结果。全局 Resume 不缩成单剧。

计划实测补充：仅减少历史分集访问仍会因替代版本检查及下一集反复展开有效状态而保留高成本 JIT。因此同时优化 PlaybackStates 红果文件资格的连接顺序（先 source_id + episode_number，再绑定），并将该来源／用户／剧范围的有效状态在请求内物化一次，供历史和 LEFT JOIN 下一集复用。它不是持久缓存，不改变完成阈值或写入路径。正常绑定由 hongguo_media.go 按同作品分集构建；人工跨作品错绑不属于有效分集身份，需在只读生产检查中核对现有数据。

预期修改共享查询、仓储性能／范围回归及播放规范。测试需覆盖同用户多部长剧的大量历史、指定空合集、独立作品、电影、多版本和权限；用原结果及既有服务测试核验等价，用实际绑定 SQL 核验查询计划。

不修改 schema、全局数据库设置或外部响应；源码回退即可撤销。上线实际 HTTP 耗时与客户端行为仍需用户加载新代码后验证。
