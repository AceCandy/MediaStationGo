# 第 2 项设计评审稿

## 状态与前置

### 2026-09-28 已批准的播放器兼容修正

- HTTP Items 不再删除 TotalRecordCount。Items 在参数归一化后，为跳过准确计数的分页请求多取一项，再裁回原页大小并返回分页下界；有数据时为 StartIndex + 实际取得数量（包含额外一项），空页为 0。IDs 与根 Views 不裁切。500 条外部上限不变，内部允许 501 条前瞻，Persons 同步允许该内部边界。内部查询和缓存存取的是原始前瞻页，不污染准确计数页。
- Random 用每次 Items 请求生成的内部整数种子及候选身份生成稳定 hash 顺序；全部补取沿用该种子，刷新/独立请求可重新随机。不引入随机种子 API、跨请求快照或额外缓存；随机普通页绕过整页缓存，避免高基数随机键。普通 Movie/Series、NFO、红果、全局与混合电影库共用随机排序表达式，随机路径不读取文件日期；原资格和合集身份保持不变。
- 下界是兼容性测试方案，不是准确总量；可能随翻页增长。随机轻量排序仍可能扫描作品候选，不能把 LIMIT 50 等同于扫描 50 行。用实际执行计划验证文件关联已移出候选阶段；稀疏资格需补取，客户端行为单独验收。

用户已确认按序实施，并明确不存在需要兼容的历史媒体级 NSFW 数据；第 1 项完成验证后开始。保留已有候选/计数/页内详情架构，不另建分页框架。

## NSFW 库级化

- 复用已有 `adult.library_ids`、全局成人开关和用户/播放配置的库权限，不能因 Library 模型没有 NSFW 列就新建重复配置。
- 移除媒体编辑成人开关、后端媒体级设置与其对可见性的影响；导入/刮削不再将单项标记作为独立授权依据。普通、NFO、Web、Emby、搜索、详情、图片和播放入口使用相同库级边界。
- 删除基于库内媒体 NSFW 反推隐藏整库的逻辑；现有基于库名称/路径的兼容判断单独核对，不能以媒体标记替代库配置。
- 删除媒体级 NSFW 模型/API 字段、数据库列及相关索引、编辑/导入/导出和过滤逻辑，不保留旧数据或兼容分支；库级配置继续保留。用户明确无历史 NSFW 标记数据，不进行相关存量兼容调查。
- 不把任何普通库自动改成成人库，不批量改写用户已有 sidecar 文件；此后读写不再处理媒体级 NSFW 标记。数据库结构清理通过项目迁移机制实现，不直接操作运行中的业务数据库。

## 候选资格

### 后续特殊入口补齐（用户已批准）

- 普通搜索共享 `metadataSearchQuery` 使用作品可见归属，已知 Movie 省文件存在判断；Series 仍验证正确季集链，受限搜索不重复执行全局存在判断。NFO 搜索使用自身库和有效最新时间，缺资料/未初始化时精确回退；红果按源作品归属筛选后维持官方合集身份。
- 续播与季集在当前身份范围内复用库归属预筛，保留具体文件权限、有效状态、原父子/集序，不用作品最新时间替代观看时间或集序。
- Web 普通电影排序改用作品最新入库时间；Part 资格在最终分页前处理，分辨率/首选版本和展示统计只读取最终页。其他 Web 剧集及 Emby 上映日期排序不在本次语义调整内。
- 改动落在 repository 搜索/电影分页/续播与 service 季集/续播共享查询，复用现有权限函数，不新增持久字段、缓存或通用框架。真实 PostgreSQL 验证权限、已知/未知归属、跨库、多版本/Part、分页和执行计划。

- 固定已授权库的普通 Movie/Series、NFO、红果请求，优先用持久库归属、来源/类型和非空最新时间产生候选；仅在与原文件资格等价时省略 EXISTS。
- 普通/红果 `library_ids IS NULL` 保留原精确回退；空数组不是未知。普通祖先汇总包含直接绑定和后代，而某些 Emby 列表仅接受特定分集结构，必须保留不能由汇总字段证明的层级资格。
- NFO 普通候选直接使用自身 LibraryID 和有效文件汇总，不再重复检查归属或绑定存在性；缺失资料等真正文件筛选仍需原谓词。
- 必要文件资格、有效播放状态在每批 50 个逻辑候选内筛选，未满页继续下一批；只水合最终页。Items 的准确总数单独计算，取页与计数在只读可重复读事务中共享快照；Latest 不计数、够数即停。复用同一资格 SQL，避免总数与取页判定漂移。
- 红果保持全局合集代表/时间、当前库成员资格、先合并展示身份再 LIMIT；准确总数仍基于同一合格集合，Latest 不新增 COUNT。
- 用户再次确认统一 Web、Emby 同类列表：包括全局混合来源、电影/剧集混合库、Web 库页与最近新增。不改搜索排序、续播身份或普通 Items 既有播放筛选语义；无后置资格的列表直接分页，不机械增加 50 条循环。
- 将既有批次分页放到 repository 层复用；资格按候选 ordinal 关联，保留同 ID 不同 origin 的既有分组/总数。候选、排序值和精确计数不加载无关展示关联。
- 混合候选共处同一 PostgreSQL，沿用 SQL UNION ALL 统一排序与只读快照，不引入多连接快照协议。并发限定最终页不同来源的详情加载：复用项目已有 WaitGroup/WithCancelCause 模式，任一失败取消同批工作，按原 ID 顺序合并。验证重叠执行、错误传播、取消及单连接池不死锁。
- Web 普通电影按后续授权使用作品最新入库时间，代表版本与 Part 规则不变；普通剧集分集日期及混合电影库上映日期降级排序保留必要文件计算。Web 无播放筛选，优先删除由有效归属已证明的重复存在性检查；真正文件筛选才分批资格。

## 风险与回滚

### 无总数测试边界（2026-09-28 历史方案，字段省略已由顶部兼容修正取代）

- 仅 `embyItemsHandler` 解析 `EnableTotalRecordCount` 并选择默认不计数；内部 `ItemsParams.SkipTotalRecordCount` 零值仍保留计数，避免改变专用入口和 Web 契约。不计数时由 HTTP 边界统一省略字段，不返回假总数。
- 将开关传给既有 WorkBatchPage、metadataPageWithCount、NFO/红果候选分页及混合/续播/人物列表的计数点。计数仍复用原资格；无总数不能拿内部零值作空页判断。Items 缓存键必须区分模式。
- 不引入配置、缓存系统、估算器或分页框架。必要页内 COUNT、搜索相关性召回和排序仍保留；少一条 SQL 不等于全流程不扫描全库。
- 回滚本轮入口默认值即可先恢复省略参数时的旧行为；完整源码回退须只撤销本轮差异，保留已有工作树修改，无数据迁移。HillS/Yamby 若因缺字段停止翻页，再依据实测决定保留哪些入口计数，不能先假定兼容。

主要风险为候选层级不等价、库归属历史 NULL 被漏掉和日期排序变化。NSFW 不留兼容；库归属 NULL 的必要回退与 NSFW 无关，仍保留。未获等价证据的特殊分支保留必要文件检查。删除列后不能仅靠代码回退恢复数据库结构；部署需配套结构恢复或备份，不在本次直接执行生产迁移。

## 2026-09-28 查询计划修复

- 红果共享作品 scope 投影原生 kind，库内与全局消费者直接按存储值筛选；详情仍转换为 Emby 类型，不改变全局合集范围。原 LOWER/CASE 使估算严重偏小，导致重复扫描 albums。
- 普通有库限制的排序候选先预筛；已知正向归属与 NULL 归属用互斥 UNION ALL 保留同一权限规则，再用 OFFSET 0 隔离排序与库选择。只加排序边界仍可能因 OR 选择全表扫描；回归要求真正候选访问量而非固定别名。无限制全局不强制该边界，必要文件排序仍按原定义。
- 普通 Series 准确计数按非空/空入库时间拆成两个互斥执行分支：非空复用原批次文件 EXISTS；空值保留原受限文件→季→作品 DISTINCT ordinal，且无空值候选时不执行文件扫描。时间不是有效分集或权限证明；所有原文件谓词保留。
- 不改 schema/索引/配置，无生产迁移。回滚仅撤销本轮查询和对应断言，不覆盖已有工作树修改。
