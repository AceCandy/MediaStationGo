# Design

将可见文件范围提取为同文件内共享查询，原详情调用保留原有语义。库分页从 `hongguo_works` 出发，通过相关 `EXISTS` 判断当前库/权限下绑定文件是否存在，复用官方合集身份、季号和最早已收录主体。

采用现有普通剧集分页的物化 CTE 模式：作品范围只计算一次，总数和当前页共用。存在性查询保留 `OFFSET 0` 索引查找边界；当前页返回明确作品 ID 后，通过绑定表 `work_id` 查询文件并聚合，避免将文件聚合与分页 CTE 放在同一语句引起基数高估和昂贵 JIT 优化。最终仍批量加载代表文件，服务/API/前端结构不变。

无有效关系继续使用 `hg-work-<内部UUID>` 和第 1 季，源红果 ID 保留在来源字段。既有 `hg-group-<合集ID>` 不变；不回填业务数据、不更改 Emby 身份。仅改 repository 查询、对应测试与规范；回滚代码即可恢复旧查询。
