# 优化媒体库扫描与轨道回填

## Goal

让媒体库扫描只负责发现文件和同步入库，并在任务中心持续展示可理解的扫描进度；轨道探测由统一、可见的“媒体轨道回填”执行负责，避免隐藏的 ffprobe 队列拖慢扫描或在进程退出时丢失待处理工作。

## Background

- 新建媒体库会启动 `event` 类型的整库扫描；同一媒体库的多个启用路径已由 `scanLibrary` 串行处理（`internal/service/scanner_scan.go:68-149`）。
- 当前扫描在媒体写入后通过内存队列直接调用 `ProbeMedia`，该队列没有任务执行记录，容量满时会对扫描形成回压（`internal/service/scanner_local_probe_queue.go:17-31,77-87`）。
- 任务中心已有“媒体轨道回填”，手动执行复用 `BackfillLibrary` / `BackfillAll` 并记录 `TaskKindProbe` 进度（`internal/handler/tasks.go:174-240`、`internal/service/task_definitions.go:61`）。
- `event` 任务按契约省略通用开始/结束行，但必须保留业务进度、详情和错误；当前自动扫描没有向 `TaskHandle` 传递遍历进度（`.trellis/spec/backend/background-task-execution.md`）。
- 当前 `ScanResult.Changes` 会累计全部变化，任务结束时可能一次写入大量详情（`internal/service/scanner.go:145-170`、`internal/handler/media_scan.go:162-182`）。

## Requirements

### R1. 扫描与轨道探测解耦

- 整库扫描、单路径扫描和文件监听入库不得直接把 ffprobe 工作放入隐藏的本地内存队列。
- 新增或发生文件指纹变化的媒体必须留下可查询的“缺少或过期探测文档”业务状态。
- 一次扫描或监听批次完成后，自动唤醒统一的轨道回填执行；自动与手动入口复用同一回填逻辑和同一 `TaskKindProbe` 并发保护。
- 若回填正在执行，新的唤醒不得启动并行回填，也不得永久丢失；现有执行结束后仍能处理新产生的缺失项。
- 自动回填以 `event` 任务出现在任务中心；手动回填行为保持兼容。

### R2. 可观察的扫描进度

- 扫描任务至少展示：路径总数、当前路径、已完成路径数、访问、新增、更新、跳过、删除和错误数量。
- 每个路径开始和结束时更新任务；大路径扫描期间按有界节奏更新指标，不能每个文件写一条进度日志。
- 路径读取失败时记录可操作错误，并保留该路径已有媒体，不得因不完整遍历执行删除。

### R3. 路径级提交边界

- 多路径保持串行扫描，不引入路径并行。
- 每个路径遍历结束后立即刷新待写批次，再执行该路径的失效媒体清理。
- 一个路径失败不阻止后续路径扫描；失败路径不得执行失效清理。

### R4. 有界任务详情

- 单次扫描保留的逐文件变化详情必须有固定上限。
- 新增、更新、删除等汇总指标必须保持完整，不受详情上限影响。
- 超过上限时，任务日志必须明确显示还有多少条变化未展开。

### R5. 兼容性

- 手动、定时、新建媒体库自动扫描和新增路径自动扫描继续使用现有入口与任务定义。
- 已有完整且未过期探测文档的媒体不得重复执行 ffprobe。
- `.iso` 及无法解析到受支持本地目标的 `.strm` 继续跳过轨道探测。
- 扫描结束触发的媒体刮削、缓存失效、STRM 生成和多版本合并行为保持不变。

## Acceptance Criteria

- [ ] AC1：新建含多个启用路径的媒体库时，路径按配置顺序串行扫描，任务中心能看到路径开始、周期指标和路径完成进度。
- [ ] AC2：扫描新增媒体不会调用旧 `localMediaProbeQueue`；扫描任务可以在 ffprobe 尚未执行时独立完成。
- [ ] AC3：扫描完成后出现 `event` 类型的“媒体轨道回填”执行，缺失或过期媒体通过 `ProbeMedia` 写回完整探测文档和轨道摘要。
- [ ] AC4：自动回填与手动回填不会并行；执行期间到达的新唤醒在当前执行结束后仍被处理。
- [ ] AC5：进程退出导致内存工作消失后，数据库中的缺失/过期探测状态仍可由统一回填执行重新发现。
- [ ] AC6：文件大小或 mtime 变化会使旧探测文档失效；完全未变化且探测文档有效的媒体不会重复 ffprobe。
- [ ] AC7：每个成功遍历的路径在失效清理前刷新写入批次；失败路径不清理旧媒体，其他路径继续执行。
- [ ] AC8：超出详情上限的大型扫描仍保留准确汇总，并只写有界详情及截断摘要。
- [ ] AC9：现有手动轨道回填、手动/定时扫描和新增路径自动扫描测试继续通过。

## Out of Scope

- 真正的数据库批量 upsert 与逐条 `COUNT + Upsert` 优化。
- 节目级 NFO/图片目录缓存。
- 将已有媒体快照改成按路径加载。
- 并行扫描路径或为每个文件、每个路径创建独立任务。
- 为网络文件系统的单次阻塞系统调用提供强制超时。

## Risks and Constraints

- 网络挂载的 `WalkDir`/`stat` 仍可能在系统调用层长时间阻塞；本任务改善可观察性，但不承诺中断阻塞的内核 I/O。
- 探测文档失效必须与媒体文件指纹变化绑定，不能仅依赖任务历史或内存队列。
- 自动回填需要合并重复唤醒，避免扫描与监听产生任务风暴。
