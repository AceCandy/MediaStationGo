# 播放器请求日志实时查看

## Goal

让管理员在观看空间中查看播放器兼容 API 的持久化请求日志，并在页面打开期间及时看到新请求，以便排查播放器接入问题。

## Background

- 现有实现只在 Zap `http` 日志中为播放器请求附加 `player_api=true`、脱敏后的 headers 和 query。
- 现有实现没有播放器日志表、查询接口、观看空间页面或实时更新链路。
- 生产环境默认日志级别为 `warn`，现有 `Info` 请求日志不能作为该产品功能的数据源。

## Requirements

### Persistence

- 每个播放器兼容 API 请求写入独立的 PostgreSQL 日志表，不依赖文本日志级别。
- 日志包含请求时间、HTTP 方法、路由模板、响应状态、耗时、来源 IP，以及脱敏后的 path params、headers 和 query；不持久化未经处理的原始 URL。
- 日志表按 UTC 自然月使用 PostgreSQL 原生范围分区；应用仍通过一张逻辑表查询，历史数据不自动删除。
- 跨月前必须保证对应分区可写；分区准备或日志写入失败不得改变播放器 API 的状态码、响应头或响应体。

### Privacy and Access

- Token、Authorization、Cookie、API Key、密码、签名、凭证、Referer 及设备标识等敏感值在持久化前统一替换为 `[redacted]`。
- path params、headers 和 query 的单值及整体 JSON 使用固定大小上限；超限内容以明确的截断标记代替，不允许无界写入。
- 不记录请求体。
- 播放器日志入口位于观看空间，但只对管理员显示。
- 页面路由、历史查询 API 和实时刷新链路均不得向普通用户暴露日志内容。

### Web Experience

- 页面默认查看当前月份，按时间倒序分页。
- 列表显示时间、方法、路由模板、状态码、耗时和 IP；点击记录查看脱敏后的 Path 参数、Header 和 Query 详情。
- 支持按月份、路径关键字、HTTP 方法和状态码筛选。
- 页面打开后通过现有 SSE 链路接收更新通知并刷新最新结果；断线重连后重新查询，以数据库记录补偿漏掉的实时通知。
- 首版不提供导出、批量删除或复杂全文检索。

## Acceptance Criteria

- [ ] 调用任一 `/emby/*` 或根路径播放器兼容 API 后，对应月份分区中产生一条日志记录。
- [ ] 普通 `/api/*` Web 请求不会进入播放器日志表。
- [ ] 持久化数据和 Web API 响应均不包含原始 URL、明文敏感值或请求体，超限请求元数据带有截断标记。
- [ ] 日志写入失败时，播放器 API 保持原状态码、响应头和响应体。
- [ ] 管理员能从观看空间进入播放器日志页，并按月份、路径、方法和状态码查询分页结果。
- [ ] 管理员能查看单条记录的脱敏 Path 参数、Header 和 Query 详情。
- [ ] 页面保持打开时，新日志写入成功后无需手动刷新即可出现；SSE 重连后会重新查询数据库。
- [ ] 普通用户看不到入口，直接访问页面或查询 API 也无法获取日志。
- [ ] 月末跨月后，新请求自动写入新月份分区，旧月份仍可查询。
- [ ] 页面在项目规定的移动端、平板和桌面尺寸下可用且无横向溢出。

## Out of Scope

- 记录请求体。
- 记录普通 Web API 请求。
- 替代现有 Zap 运行日志或管理审计日志。
- 导出、批量删除、任意全文检索和自动删除历史月份。

## Technical Constraints

- 复用现有 PostgreSQL/GORM、路由清单、管理员守卫、`/api/events` SSE 和 `useSSE`，不增加依赖或新的实时协议。
- 现有 `AccessLog` 语义和字段不匹配，播放器请求日志使用独立模型、仓储和 API 契约。
- SSE 广播只发送不含日志详情的变更通知；实际内容只能通过管理员查询 API 获取。
- PostgreSQL 分区表的主键/唯一约束必须包含分区键，请求日志模型不能直接复用仅以 `id` 为主键的通用 `Base`。
- 请求元数据每个值最多保留 4096 个 Unicode 字符，每个 JSON 对象编码后最多 64 KiB；达到上限时写入 `_truncated` 标记。
