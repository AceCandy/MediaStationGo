# 第2项：各类库作品级筛选与分页精简

## 记录状态

- 用户确认普通电影、电视剧、NFO、红果库都应纳入本项，不仅优化红果。
- 用户已确认按第 1 → 2 → 3 项实施，并明确无历史媒体级 NSFW 数据，不保留相关兼容。本项在第 1 项完成后启动。

## 目标

利用已有作品级库归属和最新入库时间，减少 Emby 库列表在分页前重复读取、关联和聚合文件的开销。优先在作品级完成筛选和排序分页，仅为当前页读取展示所需的文件详情与播放状态，同时保持原有结果正确。

## 实施前已确认事实

- 普通作品已有 `library_ids` 和 `latest_media_added_at`，NFO 条目已有 `library_id` 和 `latest_media_added_at`，红果作品已有 `library_ids` 和 `latest_media_added_at`；定义见 `internal/model/metadata.go`、`internal/model/nfo.go`、`internal/model/hongguo.go`。
- `internal/database/latest_media_added.go` 通过数据库触发器维护相关汇总，覆盖文件及绑定的增删改。最新时间是现存相关文件的 `MAX(created_at)`，不是最新文件 ID；普通/NFO 容器包含后代，红果源作品字段不自动包含同合集其他作品。
- 红果已进行只读数据核验：当时 21,603 个作品中，已初始化库归属与实际绑定聚合不一致为 0，最新时间不一致为 0；33 个库归属未初始化作品均无绑定文件，目标库归属与实际文件匹配数均为 7,620，相关触发器启用。该结果仅代表当时红果数据，不代表普通/NFO 已通过同类核验。
- `internal/service/emby_work_pagination.go:36`、`:72`：普通作品与剧集分页已经利用作品字段，但仍逐候选检查文件存在性；本项是继续精简已有流程，不是重新建设分页框架。
- `internal/repository/nfo_media_view.go:12`：NFO 文件可见性除了库范围，还检查绑定、条目、季与剧的 NSFW 标记；`internal/service/emby_visibility.go:14` 的普通文件可见性也涉及所绑定元数据的 NSFW 标记。库归属本身不表达这些子项限制。
- `web/src/components/MetadataEditDialog.tsx:162` 与 `internal/service/media_metadata.go:15`：目前存在媒体级成人内容编辑及后端接收字段；`internal/service/nfo_local_ingest.go:199` 导入条目级标记，`internal/service/nfo_metadata.go:32` 支持编辑并写回 NFO。这些是现状证据，不是新需求下保留该功能的理由。
- `internal/service/visibility.go:12` 已有 `adult.library_ids` 库级配置；`:94` 的库可见性在未配置成人库时还会回查库内元数据 NSFW，收敛至库级规则时须一并处理，不能只移除列表 SQL 中的条件。
- `internal/service/emby_nfo.go:12`：NFO 的 `DateCreated` 排序使用文件 `MIN(created_at)`，`DateLastContentAdded` 使用作品最新时间；已看/未看筛选在分页前应用。`internal/repository/nfo_library_candidates.go:10` 生成候选及所需日期、播放状态条件。
- `internal/repository/nfo_repository.go:105` 先 upsert Media，`:149` 再创建 NFO 条目，冲突更新字段不包含 `created_at`；`internal/service/nfo_local_ingest.go:76` 构建条目时未复制 Media 创建时间。缺失有效 NFO 时允许只保存 Media，后续补齐资料才创建条目；多版本中删除最早文件也会改变现存文件 MIN，而已有作品创建时间不随之更新。
- `internal/service/emby_hongguo_library.go`：源作品须映射并合并为展示卡片后分页；合集最新时间按现有全局成员范围计算，不能改成仅当前库成员的最大时间。

## 需求与边界

2026-09-28 播放器实测修正（用户已批准实施）：Yamby 确认因缺失 TotalRecordCount 报错；HTTP Items 默认/false 改为保留数字字段，每页多取一个合格结果，以已确认的分页下界提示下一页，不恢复全量 COUNT。true 保留准确总数；空越界页无已知数量时返回 0，不宣称为准确总量；IDs/根 Views 的非分页响应保留原计数。此约定取代下段试验版的字段省略及禁止下界规则。HillS Random+IsUnplayed 实测仍耗时 31–48 秒后取消；本轮同时修复各类作品 Random 入口，轻量候选固定请求内随机顺序、50 条不足补取、不为随机排序计算文件日期。保留权限、身份/合集与资格；非随机排序、Web、专用接口不改，不部署或重启。验收包括最大页 500、边界/缓存/跨批、随机顺序与真实执行计划；原生播放器仍须用户实测。

2026-09-28 无总数测试追加授权：用户同意准备可回滚的 Emby `/Items` 测试改动并配合 HillS/Yamby 翻页验证。该 HTTP 入口及大小写/用户别名默认不额外计数、省略 `TotalRecordCount`，`EnableTotalRecordCount=true` 保留准确计数；不伪造 0 或约数。覆盖库内、全局/混合、季集、人物和筛选分支，保留页内容器统计、权限、排序及每批 50 条不足补取。Web 当前依赖总数，及 Views/Latest/Resume/NextUp/Shows 专用入口本轮不改；不同时修复 Random 排序，不部署或重启服务。此次仅覆盖本入口旧的必计总数要求，原生客户端兼容性待用户实测，不视为已验收。

2026-09-28 后续批准：搜索、续播、季集特殊入口也复用已维护的库归属，保留关键词相关性、有效播放状态、父子关系和具体文件资格。Web 普通电影库页改按作品 `latest_media_added_at` 降序（空值最后、ID 降序），不再按首选版本日期排序；首选版本和 Part 选择规则不变。此项覆盖下文早期“搜索不在范围内”和“代表版本时间不变”的边界，不修改其他上映/播放日期排序，不新增字段或回填。

2. 固定库、按最近新增排序、无文件级或播放状态筛选的普通列表，优先直接复用现有作品字段。逐类证明与原资格条件等价后，去掉冗余文件存在性检查和日期聚合；不得因现实现曾将库归属视为预筛而一概保留全部文件查询。
3. NSFW 收敛到库级设置和授权；对已确认可见的固定库，不再为 NSFW 逐作品检查文件。删除媒体级字段、数据库列及相关索引、前端编辑、后端接收/写入、导入/导出和可见性消费，不能只隐藏开关而保留后台行为；核对 Web、Emby、详情及播放等入口的一致性。用户明确无历史 NSFW 标记数据，不保留旧字段或兼容分支；保持用户/播放配置的库访问限制，不自动调整库级设置、不批量改写现存 NFO 文件。
4. 区分播放状态的两种用途：仅展示已看标记/剩余集数时，留在当前页详情阶段读取；请求带已看/未看筛选时，先按作品字段取 50 个逻辑候选，再批量筛选，不足继续补取直到够数或耗尽。用户已明确要求此方案，不再作为可选项。StartIndex 按合格作品计算，保留原接口要求的准确总数和各来源有效状态规则；红果先归并合集再取批次。
5. NFO 作品 DateCreated 按已确认的首次创建时间定义读取、排序，直接使用现有 `nfo_items.created_at`，去掉仅服务于该日期的文件 MIN 聚合；文件增删和重扫不改写仍存在条目的创建时间。DateLastContentAdded 继续使用 `latest_media_added_at`；Media 自身入库时间和其他来源的日期规则不变。此次是用户批准的 NFO 日期含义调整，不声称 created_at 与旧 MIN 数值恒等，验收须说明相关历史排序差异；不新增字段或自动回填。其他排序继续保持原作用范围、方向、空值及并列规则。
6. 保持展示身份、合集归并和混合电影库中剧集识别等现有规则。红果按归并后的卡片分页，不能对源作品先 LIMIT 后归并；跨库时间范围也不得随优化改变。
7. 需要准确总数的接口仍保留计数，并与分页共享同一合格作品集合；不需要总数的接口不新增计数。不能把 LIMIT 描述为不再需要处理总数。
8. 库归属未初始化等历史数据保留正确回退；移库、删除最后文件、重绑和并发更新后不得残留空卡片或丢失可见作品。实施前验证不同来源的维护范围与读取资格是否等价。
9. 复用现有字段、索引、触发器和查询组件，不在本项默认引入新依赖、通用查询框架或整页响应缓存。
10. 用户后续批准统一 Web、Emby 全局混合及电影/剧集混合库等同类入口，并评估并发查询后合并。保持原全局排序、同 ID 分组、权限和精确总数；不能拼接各来源单独分页后当全局页。无后置筛选时不强加批次循环；并发不得降低原计数/分页快照保证，任一来源失败须传播错误并取消剩余工作。

## 未纳入本项

- 第 1 项的用户、库基础信息、权限缓存改造。
- 页内分集统计或播放状态计算本身的独立重写；本项仅保持其输入范围与结果正确。
- 搜索、随机排序支持、播放跳转上游解析等其他慢请求原因的独立优化；NSFW 库级规则仍须覆盖搜索等共享入口。
- 除已确认的 NSFW 库级化和 NFO DateCreated 定义调整之外，擅自更改权限、排序、总数或已看判定；未经确认新增字段、数据回填和外部基础设施。
