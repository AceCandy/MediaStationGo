# 优化红果发现与404重试

## Goal

让红果分类发现得到的作品即使详情暂时不存在，也能凭摘要在发现界面可见；同时把详情 HTTP 404 作为可延后处理的上游状态，避免影响同批其他作品。

## Background

- 当前详情刷新在请求 `/detail?series_id=<id>` 得到 HTTP 404 后停止，不会创建完整作品或分集。
- 失败 ID 会进入同步失败表；当前统一按一小时后重试，并使批量刷新任务最终显示失败。
- 实际失败样本中，只有部分 ID 仍保有分类发现摘要；摘要可包含标题、海报地址和分类页集数，但不能证明详情或分集可用。
- 当前作品列表和详情接口都只读取 `hongguo_works`，因此仅存在于 `hongguo_discoveries` 的摘要不会展示，点击其源 ID 则返回 404。
- 发现海报目前只保存上游地址；现有公开 DTO 禁止暴露上游图片地址，现有本地图片表也只允许完整作品或人物作为图片所有者。
- 发现摘要没有详情标签，因此只能可靠参与“全部”、来源分类、榜单、标题或源 ID 查询，不能冒充某个详情题材筛选结果。

## Requirements

- 分类发现摘要应能独立出现在发现界面，不要求详情导入成功。
- 分类发现摘要中的海报应进入现有红果图片下载任务，并由发现卡片使用下载后的本地图片；不得把上游图片地址暴露给浏览器。
- 仅有发现摘要的条目应明确区别于完整作品，不创建虚假的作品或分集数据。
- 用户点击详情不可用的发现条目时，应收到“红果资料不存在”之类的明确提示。
- 详情 HTTP 404 应记录为暂缓状态，下一次重试时间为三天后，并继续处理同批其他条目。
- 详情 HTTP 404 不应使整批刷新任务最终标记为失败；其他网络、解析、数据库或检查点错误保持现有失败语义。
- 已成功导入的作品、分集、绑定和用户状态不得因详情 HTTP 404 被删除或覆盖。
- 已补齐作品与发现摘要重复时只展示一个条目，并以完整作品字段为准。
- 仅发现条目可参与全部、来源分类、榜单以及标题/源 ID 查询；没有详情标签时不得出现在具体题材筛选中。

## Acceptance Criteria

- [ ] 分类发现记录具有标题/海报摘要但没有完整作品时，仍可在发现界面看到该条目。
- [ ] 运行红果图片下载任务后，具有有效发现海报地址的仅发现条目可以显示本地海报。
- [ ] 点击该条目不会进入伪造详情，并显示资料不存在提示。
- [ ] 一个详情请求返回 HTTP 404 后，同批后续条目仍继续处理。
- [ ] HTTP 404 对应 ID 的下一次尝试时间落在请求完成时间加 72 小时的前后一分钟内；重复 404 从最近一次尝试重新计算 72 小时，期间不被待补齐扫描提前请求。
- [ ] 仅有 HTTP 404 暂缓项时，批量刷新任务不显示失败；真正错误仍显示失败。
- [ ] 已有完整作品遇到 HTTP 404 后保持原作品、分集和绑定不变。
- [ ] 已有作品海报升级后继续可用，发现海报在详情补齐后复用为作品海报，不产生重复公开条目。
- [ ] 404 暂缓项在任务日志和指标中计为“暂缓”而不是“失败”；失败记录保留至到期重试成功后清除。

## Out of Scope

- 根据分类摘要推造详情字段或分集。
- 自动删除长期 404 的发现记录或完整作品。
- 改变非 404 错误的重试和任务失败策略。
- 根据仅有 ID 的失败记录推造标题或海报；没有发现摘要的历史 ID 仍只保留等待重试。
- 改变管理员按 ID 手动刷新发生 404 时的 HTTP 失败提示；本次只保证批量任务不中断且不因 404 判失败。
