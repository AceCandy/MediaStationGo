# 任务中心待办统计缓存与手动刷新

## Goal

任务中心待办数量首次查询后保留服务端内存，仅手动刷新重算；说明连接池配置及最近执行记录查询。

## Requirements

- 任务中心的两类待办数量首次访问时计算，随后保留在服务端进程内存中，日常访问不重复查询。
- 提供明确的手动刷新按钮和上次统计时间。关闭待办弹窗不自动重算数量。
- 统计加载独立于任务列表；失败时保留已成功加载的旧值并提示重试，不伪装为零。
- 继续使用管理员权限和原有统计口径；待办明细按需实时查询。
- 说明连接池配置及最近结果含义，不在本轮更改运行环境、连接池、历史查询或红果详情。

## Acceptance Criteria

- [x] 重复普通请求不查询数据库，手动刷新更新数量和时间。
- [x] 并发首次加载/刷新合并，失败不覆盖缓存，取消请求不写入失败结果（合并及后端取消经代码复核，未直接构造集成用例）。
- [x] 页面进入只读取缓存接口；关闭弹窗及任务轮询不触发统计重算。
- [x] UI 显示更新时间、刷新中及失败状态，保留待办明细入口。
- [x] 通过后端缓存/权限检查、现有任务页面脚本、前端 lint/build 和独立复核。

## Notes

- 缓存允许过时，手动刷新前显示其统计时间；服务重启后首次访问重新计算。
- 原始需求已明确缓存和手动刷新；本轮直接在这一范围内实现。
