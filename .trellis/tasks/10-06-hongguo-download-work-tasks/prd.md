# 红果与黄果 AI 下载任务改为作品摘要

## Goal

下载表维护分集业务状态，任务中心每部作品保留一条可恢复摘要，整理旧分集执行历史

## Requirements

- 按体系及作品 source ID 保留一条摘要，并发、重试、补集和重启接续。
- 分集队列拥有状态、租约、恢复；从全作品队列汇总，全部完成才表示 completed。
- 逐集安全日志保留，但不创建分集执行摘要；摘要失败不能阻止下载或业务操作。
- 已提交入队、取消、重试及 worker 边界更新摘要，字节心跳不聚合。
- 保留下载空间历史入口及权限，下载定义继续不在任务中心枚举。
- 固定截止点，只整理可明确关联的终态旧红果分集摘要，不删除业务队列和运行中记录。
- 用户另行授权清除 system 为空的终态旧执行历史，保留有归属的记录、业务数据和独立日志。

## Acceptance Criteria

- [x] 真实 PostgreSQL 覆盖同作品并发唯一、作品隔离、混合状态、重试补集、重启和摘要故障。
- [x] 相关下载、tracker、历史、日志回归与竞态检查通过。
- [x] 历史整理逐作品原子且可重复，保留未识别、运行中和截止后记录，不将阶段成功伪造成最终完成。
- [x] 黄果电影/剧集、体系隔离、并发唯一、重试取消恢复、摘要故障与安全日志回归通过。
- [x] 独立复核并报告上线及清理限制。
- [x] 用户授权后清除已结束的旧空归属执行历史，保持其他记录和业务队列。

## Notes

- 用户已批准前一轮最终方案。实库约 285 万红果分集执行、17424 作品位置、1427709 分集队列行；旧下载路径均包含明确作品 ID。
- 红果与黄果 AI 都采用作品摘要；保持两套分集下载管线、租约与发布行为。
- 用户追加授权黄果 AI 同步处理；实库当前黄果下载队列及执行历史均为零，无需历史删除。
- 运行旧版本仍会产生旧记录，明确报告部署限制，不主动启动或重启生产服务。

## Outcome

红果和黄果 AI 均已改为每作品一条执行摘要（含电影）；分集下载表继续维护业务状态。
真实 PostgreSQL 普通/race 回归、静态检查和独立复核通过，详细证据见 research/validation.md。

实库两轮共删除 2,867,218 条红果终态旧分集执行。用户确认重启后，第二轮核对
旧格式记录为零、作品摘要无重复，近期更新的摘要指标与队列全部一致。
另按用户明确授权删除 151,039 条已结束的空 system 历史，核对后剩余零条。

最近一次清理核对：有归属且早于截止点的任务记录 122,702 条保持；
下载队列 1,434,463 条和作品位置 17,524 条保持。黄果下载历史为零，无需删除。
未删除媒体文件或独立日志，未做数据库物理收缩；释放空间供数据库复用。

用户已确认重启服务；本轮未自行部署/重启，也未验证新版生产 HTTP 或浏览器。
用户已授权提交归档；只提交本任务代码、规范及工件。
