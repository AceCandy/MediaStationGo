# 发现弹窗元数据与入库标记

## Goal

保留 TMDb 作品详情弹窗，补全元数据和演职员，并为已有可见媒体的作品显示已入库标记

## 已确认增量：TMDb 搜索

- TMDb 发现增加搜索框与搜索按钮，支持全部作品、电影、电视剧和分页；搜索结果继续使用现有卡片、入库标记及详情弹窗。
- 仅处理用户已加载的搜索页，按 TMDb ID＋作品类型检查 Metadata；缺失作品登记到既有持久化目录补齐队列，由后台创建并补齐 Metadata、快照及图片，搜索请求不等待详情和图片下载。
- 已有 Metadata 不被搜索摘要覆盖；重复搜索复用同一目录任务，不重置失败重试状态。目录 worker 沿用现有电影/剧集补齐行为；不创建 Media，不自动下载媒体，也不把 Metadata 存在当成已入库。
- URL 使用 tmdb_query、tmdb_kind 保存搜索状态；切换/退出搜索取消旧请求，失败页可重试且不跳页。
- 验收：同数值电影/剧集不串项；人物和成人结果不入队；搜索分页无详情网络请求；已有 Metadata 内容不变；重复搜索只保留一个任务；前端 lint/build 与后端针对性测试。

## 已确认需求

- 保留发现页弹窗交互，展示电影或整部电视剧，不展示具体季和集，不跳转替换为媒体详情页。
- 补充评分、上映/首播日期、时长、TMDb 链接、可靠关联的豆瓣链接、类型流派、国家/地区、语言、演职员，样式与媒体详情页的元数据区域一致。
- 管理员打开已有本地 metadata 的弹窗后，先展示本地资料，再异步复用媒体详情页的 TMDb 刷新逻辑获取最新字段、快照、图片和演职员；刷新失败保留当前资料并可重试。
- 电影时长与剧集单集时长明确区分；没有来源数据时显示暂无，不推算全剧时长。
- 发现列表作品卡片显示「✅ 已入库」：当前用户可见媒体中只要存在该作品的电影文件或任意一集即可，不判断完整性；STRM 同样算入库。
- 作品匹配使用可靠来源 ID 与电影/剧集类型，不能按名称猜测；仅有元数据缓存而无媒体文件不算入库。
- 第一版围绕 TMDb 发现条目补充详情和入库判断；后续确认增加红果弹窗，不引入跨源模糊匹配。

## 后续确认：红果发现弹窗

- 搜索登记和发现每批保存成功后自动唤醒资料刷新；运行中的刷新不重复启动，期间新增待补齐项在结束后接续下一轮。复用原任务、日志、失败冷却及取消/关闭机制。

- 搜索遇到缺少完整资料的作品时，将摘要登记到既有待补齐集合，供下一轮资料刷新任务处理；重复搜索不覆盖现有分类或失败冷却，不触发媒体下载或入库。

- 视觉修正：直接复用 TMDb 标题、海报、评分日期、标签及演职员组件，统一 260px 桌面海报栏和右侧资料布局。上版仅复用外壳与简介，交互测试不能代替视觉对照；后续同风格要求必须检查共享组件和截图。

- 红果卡片统一弹窗展示资料，保留管理员下载；分类设置仅在空分类或“其它”时显示，设置成功后隐藏。移除发现弹窗收藏及其请求、手动刷新资料和下载空间跳转按钮；不改后端收藏、任务中心刷新能力，不展示本地文件、分集播放或合季管理。
- URL 的作品 ID 仍可打开弹窗，开关不重挂载列表，保留筛选及已加载数据。
- 未补齐作品可展示列表摘要，读取失败可重试，补录由管理员显式刷新触发。
- 原本跳回发现的红果媒体库卡片改为库内详情，原分集和合季组件移到库内，已有接口和数据不变。

## 现状依据

- `web/src/pages/DiscoverDetailModal.tsx:10` 只渲染传入列表摘要，没有详情请求。
- `web/src/pages/DiscoverContentRow.tsx:74` 的卡片尚未提供入库标记；`web/src/api/discover.ts:10` 是基于部分 Media 的发现类型。
- `internal/service/tmdb_match.go:13`、`:105` 已有电影/电视剧详情查询及演职员转换，可复用；`internal/service/tmdb_types.go:6` 的 Match 不公开 Credits 且没有时长字段，需要受控的详情响应。
- `internal/model/library_media.go:32` 明确区分媒体文件与权威 Metadata；查库不得将扫描提示 ID 当成权威绑定。
- `web/src/pages/MediaDetailCast.tsx:10` 目前同时负责媒体演职员请求与展示，可轻量分离展示部分复用，不能为未入库作品伪造 mediaId。

## 验收标准

- [ ] TMDb 电影/电视剧点击仍打开弹窗；上述字段与演职员可展示，不出现季集列表。
- [ ] 详情按点击加载；管理员本地命中后异步刷新，失败可重试且保留当前资料和列表摘要，关闭/切换后旧请求不会写回。
- [ ] 有可靠 ID 才显示对应条目链接；缺失字段不显示虚构值或错误的时长口径。
- [ ] 任意一集或电影/STRM 存在就有标签；只有元数据、已移除媒体、不可见媒体均不误标。
- [ ] 同 TMDb 数值的电影与电视剧不串标；入库状态不跨账户/播放配置串用、不污染共享源缓存。
- [ ] 列表入库查询成批执行，不对每张卡片单独请求；移动端/桌面端无溢出，Web lint/build 和专项测试通过。

## 不包含

后续确认：发现的自动刷新增加 3 小时冷却，以本地 TMDb 成功快照时间为准；媒体详情手动刷新仍立即执行。没有本地 metadata 的远端预览沿用原行为。

入库动作、播放入口、季集浏览、全剧完整度检查、豆瓣按名称猜测关联、下载功能调整或既有红果任务收尾。

## 本轮修订：库内资料与详情样式（待确认实施）

后续用户确认覆盖本节的媒体可见性门槛：发现详情只按 TMDb ID＋作品类型读取本地 metadata，完全不依赖 media 或库权限；仅列表「已入库」标签检查可见 media。共享目录中的已保存译文应直接复用。普通详情 GET 命中本地时不请求 TMDb；管理员随后可调用独立刷新接口获取最新资料，发现权限保持不变。

- 命中本地 metadata 的作品优先展示库内资料，包括已翻译的人名和角色名；没有本地 metadata 时才走 TMDb 只读预览。管理员本地命中后异步刷新并替换有效最新字段，按 TMDb ID 与作品类型匹配。
- 复用详情页的评分、日期、时长徽章、来源链接、剧情简介、分类标签和演职员展示；不引入分辨率、大小、容器、本地路径、媒体管理操作或具体季集。
- backdrop 作为整个弹窗的背景，向下渐变至当前主题底色；移除海报下面重复的小 backdrop。海报保留，保证正文和关闭按钮可读。
- 验收新增：库内中文人名/角色和元数据与详情一致，普通详情 GET 命中本地资料时不请求 TMDb，管理员随后刷新可替换有效最新字段；未入库仍可预览；隐藏库不泄漏；详情页原有字段和操作不回归；深浅主题多屏宽无溢出。
- 根因记录：上一版只复用了部分展示组件，却没有复用详情页的数据投影。以后要求“与详情页一致”时，同时核对数据源、翻译字段、单位与组件，而不只核对字段名称。
