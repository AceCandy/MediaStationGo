# 修复整体审查确认的可靠性与权限问题

## Goal

落实审查中的七项问题及请求取消、重复关闭优化，保留回归检查并补齐数据库 CI。

## Requirements

- R1: Web、管理和 Emby 请求使用当前账号状态、角色与等级；停用、删除、过期、降权立即生效。
- R2: 文件和目录移动不得因并发目标竞争覆盖已有内容；失败保留来源。
- R3: 账号切换或退出后，旧刷新响应、失败和重试不能污染新会话。
- R4: 整理移动后的数据库失败恢复文件位置，并报告恢复失败；同类重分类路径保持一致。
- R5: 修改/重置密码原子撤销刷新令牌，并使旧 Web/Emby 令牌失效；新登录继续正常工作。
- R6: 手动任务不受 HTTP 请求取消影响，但随服务关闭取消并等待退出；关闭幂等。
- R7: CI 实际运行 PostgreSQL 集成测试，并执行前端静态检查及新增回归脚本。
- R8: 切换媒体库、剧集、季或卸载时取消过时请求，保留分页、重试和共享请求正确性。

## Scope

用户在审查报告后以“那你优化吧”授权落实以上修复及移除重复 Scheduler.Stop。只修改对应入口、测试、CI 和必要规范；不处理已排除的续播 SQL 误报、不启用隐藏洗版能力、不做通用重构。

用户随后以“处理”授权继续修复真实 PostgreSQL 全量回归中的剩余失败。按现行契约区分夹具漂移与业务缺陷，不恢复已取消的自动名称匹配、不跳过失败测试、不放宽有效断言。

## Acceptance Criteria

- [x] 旧管理员令牌在停用、删除、过期或降权后被拒绝；普通账号与 Emby 身份一致。
- [x] 并发同目标移动仅一个成功，其他源文件保留；破损链接和目录不被覆盖。
- [x] 刷新成功/失败在切账号、退出、同账号重新登录后均不污染当前会话。
- [x] 数据库故障时文件补偿执行，冲突时不覆盖并报告恢复失败。
- [x] 改密码事务失败不部分撤销，成功后旧 access/refresh/Emby 失效，新登录正常。
- [x] 关闭取消并等待所有调度任务，原有手动任务请求取消测试继续通过。
- [x] 实际 PostgreSQL 测试、Go 检查、前端 lint/build 与定向脚本通过；临时服务关闭。
