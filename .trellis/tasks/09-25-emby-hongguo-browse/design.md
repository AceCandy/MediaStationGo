# 技术方案

## 边界与数据流

1. 在共享 libraryAsView 映射中加入 LibraryTypeHongGuo -> tvshows，使 Views 和库详情一致；不改作品种类与节点身份。
2. 为指定红果库的作品层浏览复用现有作品身份、合集归属与可见文件范围规则。从可见作品构造候选，先完成过滤及稳定排序再分页，仅对页内作品补全节点详情。不能把全库文件展开成作品、季、集之后才截页。
3. 总数从相同过滤条件的作品候选计算；Latest 只要列表，不计算总数。候选时间与播放状态仍可能需要读取可见绑定，但不展开无关层级或加载全量卡片。
4. Latest 指定红果库的路径在 NFO 分支前统一处理，按 MAX 可见文件入库时间降序、ID 稳定排序。DateLastContentAdded 使用相同时间，DateCreated 保留 MIN。标题排序保留既有契约。
5. 优化路径严格限定能保持语义的作品层请求；季集浏览、特殊搜索/人物/续播等不适用请求继续原路径。所有参与快速路径的权限、类型和播放状态条件必须在分页前应用，不允许先取页再过滤。

## 兼容与风险

- 复用 HongGuoAlbumJoin、现有身份表达式及可见文件范围；官方合集的多个源作品必须作为同一逻辑作品分页。
- 用户状态、可见文件资格及代表文件应使用一致作用域，避免总数和返回项不一致。
- 不直接使用 Web hongGuoLibraryPage 替代 Emby：其返回字段和播放状态、日期排序语义不同。
- 特殊条件回退仍可能较慢；本次不承诺所有查询恒定耗时。需分别验证默认浏览与 Latest。
- 不加依赖、缓存、索引或数据库迁移。仅代码回滚即可撤回；客户端可能需要刷新库视图才丢弃旧 CollectionType。
- 不改变普通库、NFO 库、全局 Latest 或 OpenSearch 行为。
