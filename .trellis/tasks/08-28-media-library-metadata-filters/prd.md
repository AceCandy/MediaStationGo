# 精简媒体库操作并增加缺失元数据筛选

## Goal

清理媒体库页面中已经失效的管理入口，并让管理员能在单个媒体库内筛出缺少海报或中文名的条目，便于补齐元数据。

## Background

- 单库页面的“修复+重刮本库”调用 `POST /admin/libraries/:id/repair-rescrape`，后端未注册该路由；全库页面还调用同类的 `POST /admin/media/repair-rescrape`，该路由已在后端测试中明确标记为 retired。两个入口当前都会返回 404。
- “媒体轨道回填”在任务中心已有可选单库、全库及数量上限的手动入口，单库页面入口功能重复。
- “回填人物信息”在任务中心已有定时和手动入口；单库页面入口实际忽略库 ID，转发为同一个全局任务。
- “每集图片”前端当前默认关闭，但异步刮削队列没有传递该选项，开关实际不生效；后端未显式传参时的默认语义为开启。
- 单库“刮削元数据”会将当前库所有可刮削条目（包括已匹配条目）重置后重新排队，误操作风险高；任务中心“媒体入库刮削”只重排尚未成功的条目，应作为保留入口。
- 截图对应单库详情页。电影类条目通过 `/libraries/:id/media` 服务端分页；剧集类媒体库通过另一套 `/libraries/:id/series` 聚合接口加载。
- 海报是否存在可由海报资源关联判断。当前数据模型没有独立的“中文标题”字段，展示标题会在元数据标题为空时回退扫描标题。

## Requirements

- R1：删除已经失效的单库和全库“修复+重刮”前端入口，以及由此变为无调用的前端 API 和状态代码。
- R2：在单库详情页提供“无海报”和“无中文名”两个可独立组合的筛选条件。
- R3：筛选必须在服务端分页查询前生效，返回数量、分页和实际条目保持一致。
- R4：“无海报”指条目没有可用的 poster artwork asset。
- R5：筛选状态只影响当前单库页面，不扩展到媒体库总览、搜索、收藏等其他页面。
- R6：筛选控件仅向管理员展示，与页面现有元数据管理操作权限一致。
- R7：删除单库页面“回填媒体轨道”入口及无调用的前端 API，统一从任务中心触发；保留后端兼容路由。
- R8：删除单库页面“回填人物信息”入口及无调用的前端 API，统一从任务中心定时或手动触发；保留后端兼容路由。
- R9：删除所有页面和手动刮削对话框中的“每集图片”开关；刮削流程统一按默认开启每集图片，并修正异步队列当前丢失该选项的行为。
- R10：删除单库“刮削元数据”入口及整库强制重刮 API；保留任务中心针对未成功条目的媒体刮削和单媒体手动刮削。
- R11：“无中文名”按当前展示标题不含汉字判断；纯英文、日文假名、数字或符号标题均属于无中文名。
- R12：筛选覆盖电影类和剧集类媒体库；电影类按媒体卡片判断，电视剧/动漫等剧集类按聚合后的整部剧卡片判断，不下钻到单集维度。

## Acceptance Criteria

- [x] AC1：单库页和媒体库总览中不再出现会请求 retired `repair-rescrape` 路由的入口，前端不再保留对应无调用 API。
- [x] AC2：管理员可分别筛选“无海报”“无中文名”，也可同时启用两项；关闭筛选后恢复完整列表。
- [x] AC3：筛选请求切换后从第一页重新加载，条目数、继续加载和无结果状态正确。
- [x] AC4：非管理员看不到筛选控件，现有媒体浏览行为不变。
- [x] AC5：后端筛选覆盖无海报、有海报、含中文展示标题、不含中文展示标题及组合条件。
- [x] AC6：单库页不再出现“回填媒体轨道”“回填人物信息”和“每集图片”入口；任务中心对应任务仍可用。
- [x] AC7：从单库、单媒体和整剧触发异步刮削时，每集图片默认开启且不再依赖无效的前端开关。
- [x] AC8：不存在可将整个媒体库已匹配条目批量重置并重刮的页面入口或专用 API；任务中心安全刮削和单媒体刮削仍可用。
- [x] AC9：电影库筛选结果以媒体卡片为单位；剧集/动漫库筛选结果以整部剧卡片为单位，数量与分页均与筛选结果一致。

## Out of Scope

- 恢复或重写 `repair-rescrape` 后端功能。
- 改变任务中心媒体轨道回填、人物补齐的执行逻辑或调度周期。
- 删除媒体轨道回填、人物补齐的后端兼容路由。
- 给总览、搜索、收藏等其他页面增加相同筛选。
- 新增独立的多语言标题字段或迁移历史元数据。
