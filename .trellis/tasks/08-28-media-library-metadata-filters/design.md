# 技术设计

## 边界

本次调整媒体库批量入口、每集图片默认行为，以及单库列表筛选。任务中心、搜索和收藏保持原行为；单媒体与整剧手动刮削保留，但不再提供关闭每集图片的选项。

## 管理入口清理

- 前端删除单库页全部批量管理按钮及其状态/处理函数：整库刮削、修复重刮、轨道回填、人物回填和每集图片开关。
- 媒体库总览删除同样已退役的全库修复重刮入口。
- 删除只服务于这些入口且不再有调用方的前端 API。
- 后端删除危险的整库强制重刮路由/handler；单库轨道回填和人物回填兼容路由保留，但页面不再使用。
- `repair-rescrape` 后端本就不存在，不新增替代实现。

## 筛选契约

单库媒体与剧集列表接口增加两个可选布尔查询参数：

- `missing_poster=1`：只返回最终展示卡片没有可用海报的对象。
- `missing_chinese_title=1`：只返回最终展示标题不含汉字的对象。

参数缺省时保持现有结果；两项同时存在时按 AND 组合。

## 数据流

### 电影类媒体库

`LibraryPage` 筛选状态 → `useLibraryData` → `libraryAPI.listMedia` → `listMediaHandler` → `MediaVisibility/MediaQueryFilter` → `applyMediaViewFilter`。

- 无海报按 `poster_asset.id IS NULL` 判断。
- 无中文名按最终展示标题 `COALESCE(NULLIF(mi.title, ''), m.scan_title)` 不含汉字判断。
- 条件进入 Count 和分页前的共享查询，确保 total 与 rows 一致。
- 服务端缓存键包含筛选值，避免不同筛选结果互相污染。

### 剧集类媒体库

`LibraryPage` 筛选状态 → `useLibraryData` → `libraryAPI.listSeries` → `ListLibrarySeriesCards`。

现有服务先读取库内媒体并聚合为 `SeriesCard`，再由 handler 分页。筛选放在聚合之后、分页之前，按最终 `SeriesCard.Rep` 的展示海报和标题判断，避免按单集过滤破坏剧集分组语义。

## 前端交互

- 在单库标题区域提供管理员可见的“无海报”“无中文名”两个切换项。
- 切换任一条件时清空已有列表并从第一页重新请求。
- 条件仅存于当前页面状态，不增加全局 store 或持久化配置。

## 每集图片

删除单库、媒体详情和手动刮削对话框中的每集图片开关。前端不再显式发送关闭值，异步刮削 worker 不再显式关闭每集图片，统一使用服务层默认开启语义；后端可选字段保留兼容，不新增配置或持久化选项。

## 兼容与回滚

- 新查询参数均为可选，旧调用方行为不变。
- 整库强制重刮 API 被删除；轨道和人物回填的后端兼容 API 保留，任务中心正式 API 不变。
- 回滚可按“筛选链路”“入口清理”“每集图片默认行为”三个独立 diff 撤销，不涉及数据迁移。

## 风险

- PostgreSQL 汉字正则需用仓储测试验证，不能依赖前端过滤。
- 每集图片默认开启会增加剧集刮削时的外部请求和图片存储量，这是用户确认的目标行为。
- 删除整库强制重刮 API 可能影响仓库外部调用方；该能力风险高且用户明确要求移除，不保留兼容壳。
