### Bug Analysis: 轻量候选仍携带全目录展示/成员汇总

1. Root Cause Category：D/E。一次聚合并不必然便宜；全目录标题/成员数组会选择排序聚合，且资格估算叠加后触发 JIT。旧样本候选扫描边界没有约束全目录数组和编译开销。
2. Why Fixes Failed：本轮初版保留成员 ARRAY_AGG，线上候选仍约 160 ms（目录排序约 110 ms）；改为批后成员但使用宽泛 OR-of-IN，又扫描目录并触发 JIT。最终将成员限定到 work_batch 的原生键 LATERAL，候选＋资格降至约 52–57 ms。
3. Prevention Mechanisms：断言无全局标题/成员数组聚合、无 JIT，累计作品访问上界；保留文件/状态及页内数据边界。150 成员与状态的批内比较实测 22,350 次，将原无区分的 20,000 比较阈值改为该固定样本 150×150 上界，未放宽全目录扫描限制。
4. Systematic Expansion：同库共享的 Latest 和 DateLastContentAdded 一起覆盖；全局/混合/随机不扩展。大样本原全局/随机路径仍可有明显 JIT 成本，不以本轮库内改造宣称全局性能问题已消失。
