# 豆瓣候选搜索并回填 ID

## Goal

让管理员在编辑元数据时无需离开应用即可查找并选择正确的豆瓣条目，同时继续保留已关联条目的豆瓣页面入口。

## Background

- 元数据编辑弹窗目前为豆瓣 ID 提供按当前标题打开豆瓣搜索页的按钮。
- 用户希望搜索结果改为站内候选弹窗，选择条目后直接回填豆瓣 ID。
- 详情页已关联豆瓣时，点击豆瓣徽标会打开豆瓣详情页；该行为需要保留。

## Confirmed Facts

- 现有 `GET /media/:id/scrape/search` 接口和前端 `mediaAPI.manualScrapeSearch` 已支持按来源执行手动搜索。
- 现有手动刮削候选模型已包含标题、年份、海报和 `douban_id`，候选列表组件可复用。
- 豆瓣 `subject_suggest` 返回候选数组，但当前 Provider 只取第一项；现有自动刮削依赖这个单结果行为。
- 元数据编辑表单已负责保存 `douban_id`，因此候选选择只需修改本地表单状态。

## Requirements

- 点击豆瓣 ID 字段的搜索按钮后，在应用内展示按当前标题查询的豆瓣候选条目。
- 搜索词使用当前编辑表单中的标题；标题为空时搜索按钮保持不可用。
- 用户点击候选条目后，将其豆瓣 ID 回填到当前编辑表单，不立即保存整份元数据。
- 选择候选后关闭候选弹窗，用户仍通过原编辑弹窗的“保存”按钮确认修改。
- 详情页已关联豆瓣的外链行为保持不变。
- 优先复用项目已有豆瓣搜索接口和候选展示能力。

## Acceptance Criteria

- [ ] 点击豆瓣搜索按钮后能看到与当前标题相关的豆瓣候选列表。
- [ ] 候选项至少能让用户识别标题、年份和豆瓣 ID；有海报时展示海报。
- [ ] 点击候选项后，豆瓣 ID 字段被正确回填，其他表单内容不丢失。
- [ ] 选择候选本身不写入后端，只有点击原编辑弹窗“保存”后才持久化。
- [ ] 豆瓣搜索无结果或失败时，弹窗给出明确状态且不修改表单。
- [ ] 已关联豆瓣的详情页徽标仍跳转到对应豆瓣页面。

## Out of Scope

- 不自动选择或自动保存第一条结果。
- 不改变 TMDb、Bangumi、TheTVDB 搜索按钮行为。
- 不改变自动刮削或外部搜索服务对豆瓣单结果匹配的现有行为。
