# 豆瓣资料统一落库、定期刷新与管理页面

## Goal

统一豆瓣资料存储、复用获取时间并拆分资料刷新与本地补齐；为管理员提供可查看、可手动更新的资料中心。

## Background

- 共享资料表、独立刷新任务和业务读取切换已实现且经过针对性验收，尚未提交或部署。
- 当前界面复用任务页与媒体详情页，没有集中浏览共享豆瓣资料的入口。
- 用户新增要求：增加资料中心管理页面，直接查看当前已有豆瓣信息并手动更新。

## Requirements

- 豆瓣详情、独立评分、质量与获取/重试时间统一持久化；业务通过现有豆瓣身份关联读取。
- 所有豆瓣取数复用统一入口、有效期、请求去重及限速；主要数据不依赖进程内缓存。
- 保留现有人工绑定、跨类型绑定、字段补齐、图片资产、Web/Emby 响应契约。
- 独立资料刷新任务支持已绑定电影/整剧；不修改本地字段、季集或图片。
- 新任务默认关闭，每天检查；详情默认有效期 7 天，可通过已有设置机制调整。
- 迁移旧豆瓣快照，保留旧行供回滚，新业务停止读写旧豆瓣行。
- 搜索/榜单结果独立短有效期，不作为完整详情。
- 在管理空间新增“资料中心”入口，本次展示共享豆瓣资料；只有管理员可以访问页面及接口。
- 页面支持按标题或豆瓣 ID 搜索、按类型筛选及分页；列表展示名称、ID、类型、年份、评分、资料质量、获取和重试时间。
- 查看详情时展示已保存的主要资料及折叠的原始 JSON，兼容历史 subject/data 包装和没有成功资料的失败记录；浏览不请求豆瓣。
- 电影/整剧条目支持手动刷新，即使缓存未到期也可更新；复用现有请求去重、限速、身份和质量保护。
- 更新只修改共享资料和独立评分并失效展示缓存，不补本地字段或图片；成功后更新界面，失败时保留旧资料并显示原因。
- 历史季/集记录可以查看，界面明确显示不支持单条刷新，不新增季/集网络获取能力。
- 搜索、分页和类型由 URL 保存；旧请求不能覆盖新页面或新账号状态，单条刷新禁止重复提交。

## Acceptance Criteria

- [x] 旧数据迁移幂等，完整资料优先，保留获取时间且不覆盖已存在的新资料。
- [x] 列表及 Emby 独立评分从新表批量读取；通用评分不变。
- [x] 相同详情并发/连续访问只产生一次必要的请求；失败保留旧数据并独立退避，迟到成功不能清除较新失败状态。
- [x] 刷新后的详情能被补齐复用；海报失败不丢失已获取的详情。
- [x] 改绑/强制跨类型绑定定位正确的远端资料；旧响应不能改变新关联。
- [x] 新任务可手动/定时运行，有独立历史，评分变化使 Web/Emby 缓存失效。
- [x] 资料刷新遇到临时上游错误时停止本批，返回错误并记录失败历史及暂停指标。
- [x] 季/集、NFO、HongGuo 等来源保持原有边界。
- [x] 管理空间入口和直接页面访问均只对管理员开放，接口拒绝未登录及普通用户。
- [x] 分页搜索覆盖已有共享资料；列表不返回完整 JSON，详情读取不触发网络请求。
- [x] 页面正确展示空数据、请求失败、无成功资料、完整/降级/摘要资料及历史类型。
- [x] 手动更新新鲜或到期的电影/整剧资料，成功后读回实际保存结果；失败保留旧评分及获取时间，不伪装成功。
- [x] 手动更新不改变 canonical 字段、图片、绑定或子层级，并复用共享请求协调和 Web/Emby 缓存失效。
- [x] 列表/详情能取消过期请求，更新按钮防重复提交，深浅主题及手机/平板/桌面均可用。

## Out of Scope

- 其他资料来源的中心页面、批量强制更新、新增豆瓣 ID、删除缓存、人工编辑 JSON、独立缓存策略设置和生产部署。
