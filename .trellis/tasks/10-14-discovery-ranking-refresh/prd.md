# 发现榜单刷新与资料任务衔接

## 目标

发现榜单支持可判断新鲜度的手动、定时刷新；榜单发现的新作品由来源资料任务补全，再由独立图片任务下载，避免榜单请求直接执行详情抓取和图片下载。

## 已确认的需求

- R1：发现的榜单移除搜索框；分类保留现有搜索能力。
- R2：榜单标题附近提供刷新当前榜单的按钮，显示运行状态并防止重复提交。
- R3：豆瓣、TMDB 任务分组增加排行榜刷新任务，支持定时运行与任务中心执行记录。
- R4：每榜展示最近一次成功刷新上游数据的时间；缓存读取、失败、回退不推进时间；未成功刷新显示未更新。
- R5：豆瓣、TMDB 榜单刷新发现未收录作品后，交由现有来源资料任务处理，资料写入后交由独立图片任务处理。按来源身份去重，不因重复刷新重复创建作品或待办。
- R6：手动和定时刷新使用一致的成功判定、摘要保存规则；资料或图片后续失败不伪装成榜单抓取失败，分别记录任务结果。

## 验收条件

- [x] 榜单页无搜索框，分类仍能搜索，旧 URL 搜索参数不会让榜单误进入搜索结果。
- [x] 当前榜单可手动刷新，操作状态清楚，切换榜单或账号不会写入旧响应。
- [x] 每榜成功时间跨浏览器和服务重启可读取；失败保留原数据及原成功时间。
- [x] 豆瓣、TMDB 榜单任务归属正确、周期可配置、运行结果可查看；多榜部分失败不显示全部成功。
- [x] 新作品按来源 ID（TMDB 包含作品类型）去重，资料与图片由各自任务处理；重试及中断后待办不丢失。
- [x] 已有资料不会仅因再次进入榜单被强制重抓，不创建本地媒体文件记录。
- [x] 使用针对性 Go 测试、前端 lint/build、浏览器交互验证和独立复核；数据库测试跳过须明确记录。

## 范围边界

不调整红果、黄果分类发现规则；不扩展来源；不抓取全站作品；不递归扩展所有季集和人物；不主动修改已有任务的启停设置。

## 已确认的处理规则

榜单刷新保存摘要占位，已存在的完整资料不降级；已有占位仍可被现有资料定时任务选中，不额外投递或立即执行资料任务。图片由独立任务维护。

保留每榜按页加载，手动刷新当前榜首页，定时刷新来源各榜首页。TMDB 8 榜按每页 20 条判断续页，豆瓣 3 榜每页 24 条；不增加前 100 名限制或全站翻页抓取。每榜显示首页成功时间。

用户在需求澄清后明确同意开始实施。技术设计和验证计划见 design.md、implement.md。
